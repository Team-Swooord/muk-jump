## 0. 이 문서의 역할과 읽는 순서

이 문서는 홍보용 소개서가 아니다. 먹점프의 기획, 실제 플레이 규칙, 수치, UI, 아트,
사운드, 성장, 저장, 기술 구조, 협업 규칙과 폐기된 기능을 한곳에 모은 **현재 기준서**다.
다른 GPT나 개발자가 작업을 시작할 때는 다음 순서로 판단한다.

1. 루트 `AGENTS.md`의 작업·Git·Unity 규칙을 먼저 지킨다.
2. 이 문서에서 게임 전체 맥락과 기능 간 관계를 읽는다.
3. 변경 대상의 실제 C# 코드와 테스트를 확인한다.
4. 문서와 코드가 다르면 **현재 컴파일되는 코드가 실행 사실**이고, 기획 의도가
   불분명하면 이 문서와 `docs/design/`을 함께 비교한다.
5. 게임 규칙을 바꾸면 이 문서, `README.md`, `docs/project-brief.md`, 관련 설계 문서와
   `docs/ai-usage-log.md`를 같은 작업에서 함께 갱신한다.

### 진실 공급원 우선순위

| 우선순위 | 자료 | 의미 |
|---:|---|---|
| 1 | 현재 런타임 코드와 테스트 | 지금 실제로 실행되는 규칙 |
| 2 | `AGENTS.md` | 작업 방식과 저장소 안전 규칙 |
| 3 | 이 문서 | 기능 간 관계와 확정 기획의 전체 지도 |
| 4 | `docs/design/`, `docs/architecture.md` | 세부 설계와 기술 근거 |
| 5 | `README.md`, 제출 PDF | 플레이어·심사용 요약 |
| 6 | 과거 AI 로그와 대화 | 변경 이력. 현재 기능의 근거로 단독 사용 금지 |

### 이름 규칙

- 최종 한글명: **먹점프**
- 영문 표기: **MukJump**
- 코드 식별자와 네임스페이스: `MukJump.*`
- `Ink Jump`, `먹뛰기`는 과거 문서나 기술 흔적에만 남을 수 있으며 새 화면 문구로 쓰지 않는다.

## 1. 제품 요약

### 한 줄 소개

> 선 하나가 발판이 되고, 발판 하나가 그림이 된다.

먹점프는 자동으로 뛰는 작은 먹방울을 위해 플레이어가 직접 수묵 발판을 그리는
모바일 세로형 드로잉 클라이밍 게임이다. 캐릭터를 좌우로 움직이거나 점프 버튼을
누르는 대신, 먹선의 위치·기울기·길이로 다음 점프의 궤적을 설계한다.

### 기본 정보

| 항목 | 현재 기준 |
|---|---|
| 장르 | 캐주얼 아케이드 · 드로잉 플랫포머 · 반복 도전 |
| 핵심 목표 | 살아 있는 먹방울을 지키며 최고 고도 갱신 |
| 플랫폼 | Android 제출 빌드, iPhone 세로 UI 대응 |
| 화면 | 9:16 세로, 1080×1920 논리 좌표, Safe Area 대응 |
| 엔진 | Unity 6000.3.10f1, URP 2D 17.3.0 |
| 입력 | Unity Input System 1.18.0 전용 |
| 세션 길이 | 목표 1~3분 반복 플레이 |
| 프레임 목표 | 모바일 60 FPS, 품질 단계에 따라 연출 자동 축소 |
| 점수 | 한 판에서 시작점 대비 도달한 최고 높이 |
| 장기 성장 | 누적 거리로 얻는 먹빛과 영구 성장 먹나무 |
| 네트워크 | 코어 플레이에 불필요 |
| 런타임 AI API | 사용하지 않음. API 키 없이 전 기능 동작 |

### 제품의 네 기둥

1. **조작의 역전** — 캐릭터가 아니라 환경을 그려 움직임을 유도한다.
2. **한 획의 물리성** — 선이 장식이 아니라 실제 충돌 발판이고 기울기와 길이가 결과를 바꾼다.
3. **먹떼 생존** — 분신마다 체력과 물리가 독립적이며 한 마리만 살아도 도전이 이어진다.
4. **한 장의 산수화** — UI, 캐릭터, 발판, 배경, 위험 표시와 전환을 한지·먹·낙관색으로 통일한다.

### 의도적으로 하지 않는 것

- 캐릭터 좌우 이동 버튼과 수동 점프 버튼
- 한 판 중 무작위 증강 카드, 두루마리 선택, 도감
- 온라인 랭킹과 서버 검증 점수
- 계정 연동, 클라우드 저장, 결제
- API 키나 네트워크가 없으면 멈추는 원격 생성 기능
- 화면을 화려한 파티클로 계속 덮는 연출
- 일본풍 문양, 불필요한 붉은 점, 고급 판타지 금속 장식

## 2. 플레이어 경험과 전체 상태 흐름

### 코어 루프

```text
먹방울의 궤적 관찰
    ↓
착지할 위치에 한 획 그리기
    ↓
먹선이 물리 발판으로 확정
    ↓
자동 착지·충전·점프
    ↓
아이템·장애물·바람에 대응
    ↓
더 높은 위치에 다음 획 그리기
    ↓
모든 먹방울 전멸 → 결과·기록·먹빛 정산 → 로비
```

### 상태

| 상태 | 주요 동작 |
|---|---|
| `Lobby` | 로고, 최고 기록, 시작·성장·옵션. 플레이어 물리와 드로잉 비활성 |
| `Playing` | 자동 점프, 드로잉, 스폰, 날씨, 점수, 카메라 활성 |
| 일시정지 | 별도 `GameState`가 아니라 pause reason과 `timeScale=0`으로 런 보존 |
| `GameOver` | 저장 정산, 사망 지연, 결과 두루마리, 저장 재시도 또는 로비 전환 |

현재 코드와 결과 화면 문구 기준으로 게임오버 뒤 터치는 현재 씬을 다시 불러 **로비로
돌아간다**. “로비를 건너뛰고 즉시 재도전”이라고 적힌 옛 문서는 현재 구현과 다르다.

### 최초 실행

최초 설치에서만 로비를 한 프레임 거친 뒤 자동으로 `Playing`에 들어가고, 월드 위에
5장 튜토리얼이 열린다. 튜토리얼이 닫힐 때까지 물리, 스폰, 날씨, 기록 시간, 드로잉과
아래 UI 입력을 모두 멈춘다. 옵션에서 같은 튜토리얼을 다시 열 수 있다.

## 3. 조작과 튜토리얼

### 조작

| 상황 | 조작 |
|---|---|
| 발판 생성 | 플레이 영역을 누른 채 드래그하고 손을 뗀다 |
| 로비·성장·옵션 | 버튼 또는 성장 열매를 탭한다 |
| 일시정지 | 우상단 쉼 버튼을 탭한다 |
| 성장 지도 | 드래그·스크롤로 2축 이동한다. 확대·축소 제스처는 없으며 배율은 기기 화면비에 맞춰 자동 결정된다 |
| 게임오버 | 결과 확인 뒤 화면을 탭해 로비로 돌아간다 |

입력은 모두 `MukJump.Core.PointerInput`을 통과한다. 구형 `Input.*` API를 사용하면
Device Simulator가 마우스를 가로채는 문제가 다시 생기므로 금지한다.

### 튜토리얼 5장

| 순서 | 제목 | 반드시 전달할 규칙 |
|---:|---|---|
| 1 | 한 획이 발판이 돼요 | 1초 자동 점프, 선=발판, 하단 게이지=더 그릴 수 있는 먹, 오래된 획부터 소멸 |
| 2 | 기울기와 길이를 읽어요 | 기울기=방향, 길이=거리, 캐릭터 바로 곁의 획은 무효 |
| 3 | 붉은 먹은 위험해요 | 장애물·해태·추락은 체력 1칸, 전멸 시 종료 |
| 4 | 바람을 읽어요 | 풍향표, 횡풍, 풍맥과 상승기류 |
| 5 | 산수화도 함께 변해요 | 고도별 환경 변화, 분신 생존, 최고 기록 |

튜토리얼 패널은 820×1180 논리 크기에서 Safe Area에 맞춰 축소한다. 설명은 가운데
정렬하며, 이전·다음·시작 버튼은 공용 붓획 버튼을 쓴다. 건너뛰기는 2.5초 이내 두 번
확인해야 한다.

## 4. 드로잉, 먹선과 먹 게이지

### 처리 파이프라인

```text
포인터 입력
→ 월드 좌표 표본 수집
→ 짧은 간격 필터
→ Chaikin 스무딩·재표본
→ 캐릭터 주변과 측벽 금지 영역 제거
→ 가장 긴 유효 구간 채택
→ 먹 비용 확정
→ LineRenderer 수묵 표현 + EdgeCollider2D 생성
```

### 핵심 수치

| 항목 | 값 |
|---|---:|
| 기본 최대 먹 용량 | 4.8m |
| 성장 일반 최대 | 10.2m |
| 넓은 벼루 결실 최대 | 20.4m |
| 최소 표본 거리 | 0.15m |
| 최소 유효 획 길이 | 0.6m |
| 한 번에 이어 그리는 최대 길이 | 30m |
| 캐릭터 주변 무효 거리 | 0.55m 이상, 렌더 외곽도 함께 검사 |
| 좌우 벽 먹선 금지 띠 | 각 0.95m |
| 자연 유지 시간 | 3.4초 |
| 기본 소멸 페이드 | 1.1초 |
| 사용자 먹 발판 비상 상한 | 96개 |
| 미리보기 폭 | 0.4 world unit |

### 먹 용량의 정확한 의미

- 먹 게이지는 잉크를 매초 자동 생성하는 마나바가 아니다.
- 현재 그리고 있는 획과 확정된 먹선이 같은 총량 장부를 쓴다.
- 새 획으로 총량을 넘기면 **가장 먼저 그린 먹선의 시작점부터** 사라진다.
- 시간 만료와 총량 초과는 같은 단조 소멸 경로를 사용한다.
- 시각 선과 `EdgeCollider2D`가 같은 비율로 줄어 보이지 않는 발판이 남지 않는다.
- 자연 만료 또는 총량 초과 소멸이 시작되는 순간 해당 비용은 먹 장부에서 즉시
  반환된다. 화면의 먹선과 `EdgeCollider2D`는 이후 페이드 동안 시작점부터 함께 줄고,
  HUD는 반환된 잔량을 약 0.75초에 걸쳐 보간해 표시한다.
- 회복 성장은 유지 시간을 늘리지 않고 소멸 페이드 속도만 빠르게 한다.

### 하단 먹 게이지

- 숫자 텍스트를 표시하지 않는다.
- 전체 실루엣은 최대 용량을 보여 주기 위해 낮은 알파로 고정한다.
- 실제 잔량만 오른쪽 붓 쪽을 기준으로 crop한다.
- 소모 보간은 약 0.24초, 회복 보간은 약 0.75초다.
- 최대 용량 성장 시 트랙의 논리적 최대 범위가 함께 반영돼야 한다.
- 황금 붓 중에는 붓 이미지를 바꾸지 않는다. 옅은 전체 실루엣은 먹색으로 유지하고,
  불투명 잔량 채움만 금색으로 바꾸며 효과 시간에는 가득 찬 상태로 표시한다.

### 황금 붓의 정확한 효과

황금 붓은 8초 동안 총량 초과로 발생하는 오래된 먹선 퇴출을 미룬다. 자연 시간 만료는
계속 진행한다. 따라서 “8초간 모든 발판 영구 유지”나 “진짜 무한 먹”으로 설명하면 안 된다.

## 5. 자동 점프와 물리

### 기본 점프

| 항목 | 현재 값/규칙 |
|---|---|
| 점프 준비 | 기본 1초 |
| 기본 이륙 속도 | 12 × 1.12 배율 |
| 발판 길이 입력 | 1~5m를 점프 배율 0.85~1.30으로 변환 |
| 발판 방향 | 표면 노멀 70% 반영 |
| 수평 속도 상한 | 5.5 |
| 몸 방향 | 대각선 발판에 붙으면 렌더 몸도 발판 방향에 맞춤 |

첫 점프는 접지 상태에서 충전하고, 이후 충전은 점프 정점부터 준비된다. 플레이어는
점프 시점을 누르지 않는다. 좋은 발판을 제때 그리는 것이 곧 점프 조작이다.

### 좌우 화면 벽

일반 상태에서는 벽에 닿으면 화면 안쪽으로 트램펄린처럼 강하게 튕긴다.

- 수평 반발: 7.5~9
- 수직 반발: 4.8~6.2
- 재반동 쿨다운: 0.45초
- 충돌 직후 안쪽으로 분리해 벽과 먹선 사이 무한 상승을 막는다.
- 같은 벽에 붙어 있는 동안 수직 상승분을 반복 추가하지 않는다.

`돋는 먹발 결실`을 선택하면 즉시 반발 대신 벽에 잠시 붙고 일반 발판처럼 자동 점프해
안쪽으로 나온다. 최소 부착 0.22초, 이탈 뒤 재부착 지연 0.35초를 사용한다.

### 2단 점프

`높은 먹발 결실`을 적용한 모든 본체와 분신은 일반 자동 점프마다 정점 직전에 한 번 더
도약한다. 두 번째 수직 힘은 첫 점프의 40%다. 먹물방울이나 풍맥처럼 별도 상승 기능은
해당 비행의 2단 점프를 취소하고, 다음 일반 점프부터 다시 적용한다.

## 6. 캐릭터, 체력, 피해와 사망

### 먹방울이 디자인

- 불규칙하게 번진 검은 먹방울 몸통
- 큰 흰 타원 눈과 검은 원형 동공
- 눈썹, 입, 안광 없음
- 팔 없이 다리만 사용
- 표정은 눈과 다리 자세로 표현
- 그림자는 기본 아트에 넣지 않음
- 4×2, 8프레임: idle, crouch, launch, rise, apex, fall, dive, land

### 체력

| 대상 | 기본 | 현재 성장 최대 | 코드 안전 상한 |
|---|---:|---:|---:|
| 본체 | 1 | 4 | 5 |
| 분신 | 1 | 2 (`먹피 결실`) | 2 |

각 캐릭터는 머리 위에 자기 체력만 표시하는 월드 칸형 체력바를 가진다. 96×14 공유
텍스처, PPU 100, 몸 위 여백 0.12를 사용한다. 체력이 낮을 때 남은 칸은 붉은색으로
보인다. 상단 HUD에 대표 체력 한 줄을 두지 않는다.

### 피격

- 일반 피격 후 기본 무적: 0.55초
- 생존 성장 최대 무적: 0.71초
- 방어막 소모 뒤 무적: 0.35초
- 새 분신 생성 보호: 1초
- 방어막은 개체별 1회권이고 중첩되지 않는다.
- 이미 방어막이 있으면 새 방어막 아이템은 소비하지 않는다.
- 피격 시 밝은 플래시, 붉은 먹 번짐·링, 충돌음으로 피격을 명확히 알린다.

피해 단계 1·2는 전용 손상 스프라이트를 쓴다. 더 많은 체력 단계는 마지막 손상 아트를
재사용하면서 단계당 약 6.5% 더 크게 보이게 한다. 렌더 스프라이트만 커지고 루트
Transform, Rigidbody2D와 Collider는 바뀌지 않는다.

### 화면 하단 추락

1. 개발용 무적 확인
2. 방어막이 있으면 1회 소모하고 생존
3. 방어막이 없으면 체력 1칸 감소
4. 체력이 남으면 카메라 하단 안쪽으로 옮겨 35m 회복 상승
5. 마지막 체력까지 소진하면 사망
6. 숨고르기 결실을 가진 본체라면 판당 한 번 체력 1, 0.8초 무적, 50m 상승으로 부활

### 사망

- 분신 하나가 죽어도 다른 생존자가 있으면 런은 계속된다.
- 마지막 생존자가 죽을 때만 게임오버다.
- 사망 시 약 0.65초 동안 먹 번짐이 커지고 한지에 검은 먹 자국이 남는다.
- 사망 자국은 풀링하며 최대 20개를 유지한다.
- 마지막 목숨의 사망음과 먹 번짐은 동시 사망 피드백 병합 제한을 우회한다.

## 7. 먹분신과 먹떼

### 생성

- 첫 아이템은 약 12m에서 먹분신으로 보장한다.
- 아이템을 먹은 개체 바로 옆에 생성한다.
- 카메라 중앙의 반대쪽을 우선하고 좌우를 번갈아 쓴다.
- 화면 가장자리에서는 안쪽 공간을 우선한다.
- 분신끼리는 충돌하지 않지만 장애물과 먹선에는 정상 반응한다.
- 기본 아이템 1회당 1마리, `먹떼 결실` 적용 시 2마리다.
- 전체 생존 상한은 24마리다.

### 독립 상태

각 분신은 다음을 독립적으로 가진다.

- 체력과 체력바
- 방어막
- 피격·무적 시간
- 자동 점프와 2단 점프 상태
- 벽 부착 상태
- 사망과 먹 자국

본체만 쓸 수 있는 것은 `숨고르기 결실`의 판당 1회 부활이다.

### 전체 먹떼에 적용되는 효과

- 먹물방울: 모든 생존자를 50m 상승
- 풍맥 발판: 모든 생존자를 36m 상승
- 카메라: 가장 높은 생존자 추적
- 난이도·맵 진행: 하위 중앙값 기준

## 8. 카메라와 서로 다른 세 높이 기준

먹점프는 목적이 다른 높이 값을 하나로 합치지 않는다.

| 기준 | 계산 | 사용처 |
|---|---|---|
| 최고 기록 높이 | 런에서 도달한 최고 고도 | 점수, 결과, 로컬 Best |
| 먹떼 진행 높이 | 생존자 높이를 정렬한 하위 중앙값 | 맵 구간, 낙묵석 난도·해금 |
| 카메라 상단 높이 | 현재 카메라 위쪽을 게임 높이로 환산 | 일반 아이템·일반 장애물 선행 배치 |
| 현재 최고 기록 높이 | `ScoreManager.Height` | 날씨·풍맥 예약 |
| 카메라 프레임 높이 | 가장 높은 생존자 | 화면 구도 |

두 마리면 낮은 개체, 24마리면 낮은 순서 12번째 개체가 진행 기준이다. 한 분신이
아이템으로 홀로 튀어 올라가도 맵 구간과 낙묵석 난도가 갑자기 앞당겨지지 않는다.

### 카메라 규칙

- 본체 여부와 무관하게 가장 높은 생존자를 Y축으로만 추적한다.
- 수평 이동은 추적하지 않아 좌우 분신 때문에 화면이 흔들리지 않는다.
- 일반 추적선은 화면 높이 55%다.
- 급상승 안전 상한은 화면 높이 90%다.
- 같은 높이 반복 점프로 카메라가 계속 올라가지 않는다.
- 일반 낙하는 아래로 따라가지 않아 추락 위험을 유지한다.
- 선두가 죽고 남은 먹떼가 아래에 고립된 경우에만 0.5초 동안 화면 46% 지점으로 한 번 재구도한다.
- 점프 피드백은 줌 0.025, 흔들림 0.055, 지속 0.28초다.
- 일시정지와 게임오버 중에는 카메라 연출을 멈춘다.

## 10. 장애물과 위험물

### 먹가시

- 30m부터 등장
- 수직 간격 12~16m
- 폭 1.2
- 좌우 왕복
- 초반 속도 0.55~0.8

### 어린 동양 용

- 60m부터 등장, 첫 등장 보장
- 폭 3.2
- 4프레임, 프레임 간격 0.2초
- 좌우 진동형 수묵 장애물
- 해태와 동시에 활성화하지 않는다.
- 초등학생이 그린 듯 단순하고 귀여운 한국 수묵 동물이라는 아트 기준을 유지한다.

### 해태 벽 장애물

- 320m부터 등장, 첫 유효 출현 보장
- 왼쪽 또는 오른쪽 벽을 무작위 선택
- 느낌표, 반투명 붉은 띠, 얇은 갈필 경로로 먼저 경고
- 플레이어나 먹선을 추적하지 않고 위에서 아래로 한 번 곧게 지나간다.
- 경고 약 1.2→1.1초
- 하강 통과 약 1.45→1.25초
- 용, 낙묵석, 상승기류의 주요 경고와 겹치지 않게 예약한다.
- 한 생존자에게 피해를 준 뒤에도 화면 아래로 계속 퇴장한다.

### 낙묵석

- 30m부터 등장, 첫 등장은 약 3초 뒤
- 초반 간격 7~10초
- 200m 이후 5.5~7.5초
- 동시에 최대 1개
- 경고 0.9초
- 초기 속도 4, 가속 8, 최대 속도 9
- 모든 생존자와 가장 먼 후보 X를 선택한다.
- 캐릭터와 일반 사용자 먹 발판을 부술 수 있다.
- 풍맥 같은 특수 발판은 부수지 않는다.

### 위험 동시성

`HazardConcurrencyGate`가 큰 동물, 낙묵석, 상승기류 경고를 조절한다. 경고를 여러 개
겹쳐 피할 수 없는 상황을 만들지 않는 것이 원칙이다.

## 12. 점수, 최고 기록과 먹빛 보상

### 점수

- 점수는 한 판의 최고 높이다.
- 로컬 최고 기록은 `PlayerPrefs` 표시값이다.
- 온라인 권한이나 보상의 신뢰 근거가 아니다.
- 최고 기록을 넘는 순간 플레이 HUD에 `신` 낙관으로 알린다.
- 디버그·촬영 기능을 사용한 판은 기록과 먹빛 보상에서 제외한다.

### 먹빛

정상 게임오버의 **한 판 최고 고도**를 계정 누적 거리에 한 번 더한다. 누적 거리 문턱을
통과할 때마다 영구 성장 재화 먹빛 1개를 받는다. 한 판에 여러 문턱을 넘으면 여러
개를 한꺼번에 받는다. 총 39개를 모두 받으면 추가 먹빛은 없지만 누적 거리는 계속
통계로 남는다.

| 보상 번호 | 문턱 간격 | 구간 지급 | 구간 종료 누적 거리 |
|---:|---:|---:|---:|
| 1~5 | 20m | 5개 | 100m |
| 6~13 | 50m | 8개 | 500m |
| 14~26 | 100m | 13개 | 1,800m |
| 27~39 | 150m | 13개 | 3,750m |

중도 로비 복귀, 디버그 판, 이미 정산한 run ID는 누적 거리와 먹빛을 바꾸지 않는다.

## 13. 영구 성장 먹나무

### 최종 구조

- 분류: 생존, 도약, 먹 운용
- 분류당 노드: 13개
- 전체 노드: 39개
- 모든 노드 비용: 먹빛 1개
- 분류당 구조: 공용 뿌리 1 + A/B/C 각 3단계 + 각 줄기 결실 1
- 해금 기록: 모두 영구 보존
- 실제 한 판 적용: 공용 뿌리 + 선택한 한 줄기만
- 한 판 최대 활성 노드: 분류당 5개, 전체 15개
- 이미 구매한 다른 줄기는 무료로 선택 전환
- 새 줄기를 구매하면 그 줄기가 즉시 선택됨
- 결실 전이라도 한 줄기의 일반 노드를 하나 이상 소유하면 그 줄기를 선택할 수 있음
- 활성 줄기를 임의로 `없음`으로 비울 수는 없으며, 다른 소유 줄기로 교체하거나 전체 초기화해야 함
- 게임 시작 시 불변 스냅샷으로 고정하며 플레이 도중 성장 화면 변경은 현재 판에 반영하지 않음
- 노드 초기화: 두 번 확인, 구매 노드 전액 환급, 누적 거리·보상 이력·정산 ID 유지
- Editor의 검수 편의상 모든 열매가 해금되어 보일 수 있으나 실제 런에는 선택한 줄기만 적용
- 제출 빌드에는 999 먹빛이나 성장 DEBUG 조작을 노출하지 않음

```text
                       A1 ─ A2 ─ A3 ─ 결실
                      /
분류 공용 뿌리 ─────── B1 ─ B2 ─ B3 ─ 결실
                      \
                       C1 ─ C2 ─ C3 ─ 결실
```

## 16. 오디오와 피드백

### BGM

- 파일: `Assets/Resources/MukJump/Audio/InkdropAscent.mp3`
- 제작: 팀 Suno Pro 계정
- 반복 재생
- 로비 0.32, Playing 0.48, 일시정지 0.20, 게임오버 0.18 기준
- 상태별 목표 음량으로 `0.45 volume unit/s` 속도로 이동한다. 실제 전환 시간은 현재와
  목표 음량 차이에 따라 달라진다.
- 옵션의 BGM 볼륨과 곱해 적용

### SFX

- 붓 그리기: 획이 길고 빠를수록 loop와 pitch가 입력에 반응
- 화면 붓 전환
- 벽 충돌
- 점프, 착지
- 유효/무효 획 확정
- 아이템 획득
- 해태 경고
- 피격, 방어막 파괴
- 분신 생성
- 캐릭터 사망 slime squish
- 게임오버 ink spill
- 신기록 낙관

실제 오디오 파일이 없을 때도 `GameFeedbackController`가 짧은 procedural tone/noise를
폴백으로 제공한다. `VfxAudioManager`는 일반 효과음용 `AudioSource` 6개를 round-robin으로
재사용한다. 여기에 `BrushDrawingAudio` 1개와 `PriorityAccentAudio` 1개가 따로 있어 씬
빌더가 피드백용 총 8개를 미리 만든다. BGM `AudioSource`는 별도다. 이 구조는 런타임에
오디오 출력을 새로 만들며 발생하던 FMOD 전환 경고도 피한다.

### VFX 원칙

- Unity Particle/VFX Graph 플러그인에 의존하지 않고 SpriteRenderer·LineRenderer와 풀을 사용
- 피드백은 짧고 목적이 분명해야 함
- 마지막 사망, 방어막 파괴, 낙묵석, 아이템 중심, 벽 방향, 신기록은 Low에서도 유지
- 화면을 덮는 반투명 파티클과 큰 Additive 중첩을 피함

| 품질 | line | drop | ring segments | persistent ring | weather | composite |
|---|---:|---:|---:|---:|---:|---:|
| Low | 4 | 6 | 20 | 24 | 4 | 1 |
| Medium | 5 | 10 | 26 | 36 | 7 | 2 |
| High | 6 | 12 | 32 | 48 | 10 | 3 |

기기 성능을 샘플링해 지속적으로 낮은 FPS가 나오면 30초 쿨다운을 두고 한 단계
내린다. low-memory 신호에는 즉시 Low로 전환한다. 로비, 일시정지, 게임오버와 재개
구간은 성능 표본에서 제외한다.

## 17. 기술 아키텍처

### 핵심 계층

```text
입력
  PointerInput
      ↓
게임 조정
  GameManager ─ ScoreManager ─ RunGrowthController
      ↓             ↓                  ↓
플레이어       기록·정산       불변 성장 스냅샷
  PlayerController + AutoJump + CharacterAnimator
      ↓
드로잉
  StrokeCapture → BezierSmoother → PlatformCollider
      ↓
월드 콘텐츠
  ItemSpawner / ObstacleSpawner / FallingInkRockSpawner
  WindWeatherController / HeightZoneController / RestPlatformSpawner
      ↓
표현
  CameraFollow / HUD / UI Views / GameFeedback / VFX Pools
```

### 주요 책임

| 시스템 | 책임 |
|---|---|
| `GameManager` | 상태, 생존자 registry, 분신 생성, 진행 높이, 정산, 재시작·로비 전환 |
| `ScoreManager` | 현재 높이, 로컬 최고 기록, 저장 재시도 |
| `StrokeCapture` | 입력, 스무딩, 유효 구간, 먹 장부, 먹 발판 생성 |
| `PlatformCollider` | 먹선 렌더·충돌·자연/용량 소멸 |
| `PlayerController` | 체력, 방어막, 피해, 추락, 특수 상승, 사망 |
| `AutoJump` | 접지, 충전, 방향·힘, 2단 점프, 벽 자동점프 |
| `RunGrowthController` | 판 시작 스냅샷, 판당 결실 사용권·예약 |
| `PermanentGrowthProfile` | 먹빛, 구매, 선택, 누적거리, 저장·복구 |

| `FallbackInkStyle` | API·네트워크 없는 절차적 갈필 폴백 |

### 생명주기와 풀링

아래 숫자는 별도로 표시한 동시 활성 상한을 제외하면, 반납된 비활성 인스턴스를 풀이
보관하는 `maxRetained` 값이다. 풀이 비면 새 인스턴스를 만들 수 있으므로 활성 수의
하드캡으로 읽으면 안 된다.

- 아이템 풀 8
- 일반 장애물 풀 10
- 해태 풀 2
- 낙묵석 풀 2, 동시 활성 상한 1
- 먹물방울 합성 VFX 풀 3
- 사망 먹 자국 풀 20
- UI 탭 먹자국 풀 32
- 반복 객체는 생성·반납 책임을 한 소유자에 둔다.
- 풀 반납 시 코루틴, 이벤트, 속도, collider, renderer와 material 상태를 초기화한다.
- 런타임 생성 Sprite, Texture2D, Material, AudioClip, PhysicsMaterial2D는 소유자가 해제한다.
- 외부 에셋 참조는 빌린 자원이므로 파괴하지 않는다.

### 결정론

게임 규칙 난수는 세션 seed에서 기능별 스트림으로 분리한다.

- Items
- Obstacles
- FallingRocks
- Weather
- Platforms
- Player

표현 전용 흔들림과 장식은 별도 연출 난수를 사용할 수 있지만 판정·스폰 스트림에
영향을 주면 안 된다.

VFX 호출 순서가 아이템이나 장애물 배치를 바꾸면 안 된다. 게임 판정에
`UnityEngine.Random` 전역 상태를 직접 쓰지 않는다.

### 현재 코드 경계와 자동화 수준

현재 저장소에는 `.asmdef`·`.asmref`와 `.github/workflows` CI가 없다. 따라서 위 계층은
논리적 책임 구조이며, Runtime은 주로 `Assembly-CSharp`, Editor와 테스트는
`Assembly-CSharp-Editor`에 함께 컴파일된다. `Core.Contracts → Gameplay → Presentation
→ Bootstrap`은 향후 분리 방향이지 현재 완성된 어셈블리 구조가 아니다. Core UI와
Gameplay의 상호 참조를 먼저 정리하지 않고 asmdef부터 추가하면 순환 참조가 생길 수 있다.
테스트 통과 기록도 로컬 증거이며 per-push 자동 검증으로 표현하지 않는다.

### 씬 생성

`Assets/Scenes/Main.unity`는 100% `Assets/Editor/MukJumpSceneBuilder.cs`가 만든다.

- 씬 YAML 직접 편집 금지
- Inspector 수동 배치 금지
- UI·오브젝트·Sprite 연결 변경은 씬 빌더 수정
- 메뉴: `MukJump > Build Main Scene`
- 테스트용 빌드는 preview scene에서 격리하며 실제 Main·ProjectSettings를 바꾸면 안 됨

### 싱글톤과 도메인 리로드

`GameManager`, `ScoreManager`, `SketchToInkService` 같은 싱글톤은 `Instance`를
`OnEnable`에서 다시 할당한다. Play 중 스크립트 재컴파일로 static이 초기화돼도 현재
씬과 이벤트 연결을 복구하기 위한 계약이다.

## 18. 저장, 복구와 데이터 경계

### 저장 대상

- 로컬 최고 기록
- 먹빛 보유량
- 구매한 39 stable node ID
- 계보별 선택 A/B/C
- 누적 거리와 받은 보상 단계
- 정산 완료 run ID
- BGM/SFX와 튜토리얼 완료 같은 로컬 옵션

영구 성장 저장은 `schemaVersion=1`, 현재 `balanceVersion=7` 계약을 사용한다. 과거
노드 ID를 삭제·재사용하지 않고 의미를 마이그레이션한다.

PlayerPrefs 키:

| 키 | 역할 |
|---|---|
| `MukJump.PermanentGrowth.v1` | primary |
| `.backup` | 마지막 검증 backup |
| `.quarantine` | 교체 전 primary 원문 |
| `.backup.quarantine` | 교체 전 backup 원문 |
| `.backup.pending` | backup 동기화 미완료 marker |
| `.backup.pending.target` | 동기화할 canonical JSON |
| `.reset.pending` | reset/restore 중단 marker |

최근 정산 run ID는 최대 64개를 보존한다.

### 영구 성장 저장 원칙

1. 현재 메모리 상태를 canonical JSON으로 만든다.
2. 중단 감지용 backup 동기화 target과 pending marker를 먼저 기록한다.
3. 논리적 데이터 커밋은 primary를 먼저 확정한다.
4. 확정된 primary와 같은 내용으로 backup을 동기화한다.
5. marker와 target을 정리한다.
6. 손상·미래 버전 저장을 자동으로 빈 저장으로 덮지 않는다.

### 복구

- primary, backup, quarantine을 분리한다.
- JSON 손상, 필수 필드 누락, 미래 schema/balance는 읽기 전용 복구 상태로 진입한다.
- 복구 중 구매, 갈래 선택, 정산, 게임 시작을 막는다.
- 검증된 backup이 있으면 `백업 복원`을 제공한다.
- 없으면 2회 확인 `새로 시작`을 제공한다.
- 교체 전 거부된 원문은 quarantine에 보존한다.
- primary→backup 사이 앱 종료를 pending target으로 다음 실행에서 이어 처리한다.
- reset과 restore는 별도 marker로 중단 후 재실행을 구분한다.
- 정상 게임오버 정산은 run ID로 멱등 처리해 중복 먹빛을 막는다.

### 점수와 성장 저장의 관계

먹빛·누적거리 정산이 확정된 뒤에만 새 최고 기록을 저장한다. 최고 기록 baseline 읽기나
쓰기 실패는 결과창에서 자동 재시도 상태로 구분한다. 사용자가 포기하면 그 판에서
포기되는 기록·먹빛 범위를 문구로 분명히 안내한다.

로컬 저장은 보안 경계가 아니다. 치팅 방지나 경쟁 랭킹이 필요하면 별도 서버 권한
모델을 설계해야 하며 현재 `PlayerPrefs`를 신뢰하면 안 된다.

## 19. 성능, 품질과 테스트

### 모바일 성능 원칙

- 투명 오버드로를 최소화한다.
- 큰 반투명 파티클 여러 장을 겹치지 않는다.
- 반복 생성은 풀링한다.
- 매 프레임 `FindObjectsByType`, Material 생성, 배열 할당을 피한다.
- 카메라·바람은 `GameManager`의 재사용 생존자 버퍼를 사용한다.
- 24분신 상황에서도 체력바 Sprite 텍스처를 공유한다.
- Opaque Texture, Depth Texture, camera HDR와 MSAA는 현재 비활성 방향을 유지한다.

### 자동 테스트 범위

`Assets/Editor/Tests/`에는 다음 영역의 EditMode/물리 통합 회귀 테스트가 있다.

- 드로잉·스무딩·먹 장부·발판 소멸
- 플레이어 체력·추락·방어막·분신·벽
- 카메라와 하위 중앙값 진행
- 아이템 확률과 장애물·해태·낙묵석
- 바람·맵·풍맥
- 로비·튜토리얼·일시정지·게임오버·Safe Area
- 영구 성장 39노드·선택·런 스냅샷·복구 트랜잭션
- VFX 품질·풀·자원 해제
- 촬영 시나리오와 제출 안전성

현재 저장소에는 44개 테스트 소스와 `[Test]`, `[TestCase]`, `[UnityTest]` 선언 479개가
있다. 문서에 남은 마지막 전체 실행 증거는 472/472이며, 그 뒤 추가된 결실 전용 검증은
13/13만 별도로 확인됐다. 따라서 **현재 HEAD 전체 479개 통과**라고 주장하면 안 된다.
테스트 개수는 품질 보증의 대체물이 아니며, 최종 제출 전 실제 Unity Test Runner와
실기기 검수를 별도로 수행한다.

### 실기기 체크리스트

- iPhone 노치·홈 인디케이터와 비대칭 Safe Area
- Android 9:16·20:9·펀치홀 해상도
- 최소 레이아웃 프리셋 540×960, 1080×2400, 1179×2556, 1536×2048 태블릿
- 튜토리얼·옵션·게임오버·성장 팝업 글자 잘림과 hit area
- 붓과 먹 게이지 크기·잔량 회복 표시
- 24분신, 개별 체력바, 최고 생존자 카메라
- 15~30분 장시간 플레이, GC Alloc, 발열 후 FPS
- GLES3와 Vulkan
- pause/resume, 앱 background/foreground, low-memory
- BGM/SFX 음량과 AudioSource/FMOD 오류
- 저장 손상·backup 복원·노드 초기화

코드가 존재한다는 이유만으로 위 실기기 인증이 끝났다고 쓰지 않는다. 현재 확인 근거는
iPhone 실기기 캡처와 Android 세로 해상도 프리셋이며 Android 다기종 장시간 실측은
제출 전 별도 확인 대상이다.

## 20. 빌드와 실행

- Unity 6000.3.10f1
- URP 2D 17.3.0
- Input System 1.18.0

- 최소 Android API 25
- 세로 Portrait, upside-down과 landscape 비활성
- ARM64 기준 제출
- 패키지 ID `com.teamswooord.mukjump`
- 앱 버전 1.0, version code 1
- Target API는 현재 자동값 0이므로 제출 시점 요구 버전으로 명시 확인
- release keystore는 저장소에 설정돼 있지 않으므로 제출 서명 별도 준비
- 회원가입, 로그인, API 키, 인터넷 없이 플레이 가능
- 패키지 식별자와 Android Target API는 최종 제출 설정에서 재확인
- 현재 저장소에는 최종 APK/AAB가 없으므로 제출 직전 별도 빌드·설치 검증 필요

### 플레이 영상

- 요구 길이: 30~60초 실제 플레이
- 권장 녹화: 1080×1920, H.264, 30fps, 오디오 켜기
- 가이드: `docs/submission/NAN2026-recording-guide.md`

- Recorder 패키지는 현재 manifest에 없으며 필요하면 `com.unity.recorder@5.1.7`을
  Package Manager에서 설치한다. 호환성을 확인하기 전 manifest를 임의 수정하지 않는다.

### NAN 제출물과 현재 상태

Android 설치 빌드·실기기 검증·영상 녹화·YouTube 링크는 남은 제출 작업이다.

## 21. AI 활용 방식

먹점프는 AI를 런타임 의존 서비스가 아니라 **개발 전 공정의 공동 제작 도구**로 썼다.

- 게임 기획 후보와 밸런스 구조
- Unity C# 구현과 회귀 테스트
- 코드 리뷰, 저장 트랜잭션과 경계 조건 감사
- 캐릭터, 아이템, 배경, 용·해태, UI 콘셉트 이미지 생성
- 크로마 제거, 투명화, 크기·피사체 경계 정규화
- VFX·SFX 설계와 절차적 폴백
- Suno BGM 프롬프트와 생성
- 문서, 촬영 시나리오, 제출물 초안

주요 도구는 Claude/Claude Code, OpenAI Codex, ChatGPT/OpenAI ImageGen, Suno,
Pillow, AVFoundation, Unity Test Framework와 Roslyn/Bee 정적 검증이었다.

### 사람의 책임

- 어떤 아이디어를 채택·폐기할지 결정
- 실제 모바일 화면에서 가독성과 터치성 검수
- 기획을 단순화하고 핵심 조작과 충돌하는 기능 삭제
- 생성 이미지의 스타일·형태·라이선스 확인
- 물리와 밸런스 체감 테스트
- 최종 커밋·제출·공개 범위 결정

### 런타임 AI에 대한 정확한 표현

플레이어 먹선은 `SketchToInkService`와 `FallbackInkStyle`의 로컬 절차적 갈필 표현을
거친다. 현재 빌드는 OpenAI, ChatGPT나 다른 원격 모델을 호출하지 않는다. AI는 아트
방향과 개발 산출물을 만드는 과정에 사용됐으며, 네트워크가 없어도 게임은 동일하게
끝까지 동작한다.

전체 AI 사용 이력과 프롬프트, 사람의 검수 내용은 `docs/ai-usage-log.md`가 원본이다.

## 25. 현재 알려진 문서·구현 주의점

1. 게임오버 후 실제 흐름은 현재 **로비 복귀**다. 즉시 재도전이라고 적힌 옛 문구는 stale이다.
2. 현재 성장으로 가능한 본체 최대 체력은 4다. 코드 안전 상한 5를 기획 최대치로 쓰지 않는다.
3. 황금 붓은 자연 건조를 멈추지 않는다.
4. 피격 렌더 확대는 체력 단계당 약 6.5%이며 물리 크기는 바뀌지 않는다.
5. 카메라 최고 생존자, 난도 하위 중앙값, 최고 기록 높이를 혼동하지 않는다.
6. 성장 화면의 `노드 초기화 없음`이라고 적힌 옛 `CLAUDE.md` 문장은 stale일 수 있다.
   현재는 환급형 노드 초기화가 있다.
7. 상단 HUD 일부 BestFit은 공통 UI 원칙과 다른 기술 부채다.
8. 고객센터·계정연동은 실제 서비스가 아니다.
9. iPhone 실기기 캡처가 있지만 Android 다기종 장시간 테스트 완료를 과장하지 않는다.
10. 제출 전 폰트와 Pngtree 붓획 라이선스 증빙을 재확인한다.
