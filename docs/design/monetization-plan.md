# 먹점프 광고 배치 규칙

먹점프는 **메인 로비 상단에만 배너**를 표시하고, 실제 플레이·성장·설정·튜토리얼·
일시정지·게임오버 화면에서는 배너를 숨긴다. 보상형 광고는 게임오버 부활에만 사용한다.
광고 공급자가 초기화되지 않았거나 광고 재고가 없으면 관련 버튼을 숨기며, 광고 실패를
이유로 게임 진행을 막지 않는다.

## 확정 배치

| 위치 | 형식 | 조건 | 보상·처리 |
|---|---|---|---|
| 메인 로비 상단 | 적응형 배너 | 로비 본문만 열려 있을 때 | 성장·옵션·플레이 진입 즉시 숨김 |
| 모든 먹방울 전멸 결과창 | 보상형 | 판당 1회, 광고 준비 완료 시 | 원본을 1 HP로 부활하고 안전선에서 재개 |

첫 판 방어막 보상형과 결과 전면 광고 정책은 코드에 확장 지점만 유지하고 현재 출시에서는
노출하지 않는다. 첫 실행, 튜토리얼, 플레이 중, 일시정지 화면에는 강제 광고를 표시하지
않는다. 부활 광고와 영구 성장의
`숨 고르기 결실`은 별도 권리이며, 성장 부활이 먼저 소모된 뒤 완전히 전멸했을 때만
광고 부활을 제안한다.

## 플랫폼 연결

- Apps in Toss WebGL: `AIT.LoadFullScreenAd()`로 미리 로드하고
  `AIT.ShowFullScreenAd()`의 `userEarnedReward` 이벤트에서만 보상을 지급한다.
- iOS·Android 스토어 앱: Google Mobile Ads Unity 플러그인과 UMP를 사용한다. 동의
  상태를 갱신하고 광고 요청이 허용된 뒤에만 SDK를 초기화하며, 설정 화면에서 개인정보
  선택 화면을 다시 열 수 있다.
- 에디터: 로비에는 `Google 테스트 광고` 배너를, 보상형 요청에는 보상 완료·취소를
  선택할 수 있는 모의 전체화면 광고를 표시한다.
- Development Build: Google 공식 테스트 앱 ID와 테스트 광고 단위를 강제로 사용한다.
- Release Build: 먹점프 전용 앱 ID·배너·보상형 단위가 같은 게시자 번호이고 설정의
  검증 완료가 켜진 경우에만 빌드를 허용한다.
- 공급자가 없거나 준비되지 않으면 `MonetizationAds`의 기본 구현이 항상 `false`를
  반환하므로 출시 화면에 고장 난 광고 버튼이 나타나지 않는다.

Apps in Toss 공식 광고 가이드:
https://developers-apps-in-toss.toss.im/unity/porting-tutorials/iaa.html

## 연결 전에 필요한 값

1. Apps in Toss 보상형·배너 `adGroupId`
2. AdMob에서 **먹점프 앱을 별도로 등록**해 받은 iOS·Android 앱 ID
3. 각 앱에 만든 로비 적응형 배너·게임오버 보상형 광고 단위 ID
4. AdMob 개인정보 메시지 게시와 App Store·Google Play 데이터 안전성 응답
5. 광고 종료·앱 백그라운드·네트워크 실패 뒤 부활과 오디오 복귀 실기기 확인

SHIFT에서 발견한 앱 ID는 `ca-app-pub-2944517353618559` 계열이지만 최근 광고 단위는
`ca-app-pub-9163142359221291` 계열이고 배너 단위가 없다. 따라서 이 값은 설정 에셋에
후보로만 기록하며 먹점프 운영 광고에는 사용하지 않는다.
