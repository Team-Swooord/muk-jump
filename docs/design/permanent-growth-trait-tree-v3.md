# 영구 성장 특성 트리 v3 + 도약 v4 확장

> 기준일: 2026-08-02
> 상태: 1차 구현 완료 · Unity 실플레이 밸런스 QA 대기
> 범위: 로비의 영구 성장만 해당한다. 한 판 전용 `증강`과 월드 아이템은 유지한다.

## 1. 결론

v2의 `생존 8 / 도약 12 / 먹 운용 19`는 먹나무의 모양은 갖췄지만 실제 구조는
11개 저장 트랙의 같은 수치를 39칸으로 펼친 레벨업 목록에 가까웠다. v3 기반 위에
도약만 5단계 세 갈래로 확장해 다음 계약을 사용한다.

1. 총 45개를 `생존 13 / 도약 19 / 먹 운용 13`으로 구성한다.
2. 모든 열매는 요청대로 **성장 먹물방울 1개**로 한 번만 해금한다.
3. 일반 열매는 해금 즉시 항상 적용하고, 규칙을 크게 바꾸는 `비기`는 계보마다
   하나만 장착한다.
4. 생존·먹 운용은 13개 구조를 유지하고 도약은
   `뿌리 1 + 세부 가지 3×(일반 5 + 비기 1) = 19개`로 구성한다.
5. 비기는 모두 구매할 수 있다. 구매를 상호 배타로 만들지 않고 장착만 상호
   배타로 만들어 영구적인 오선택을 없앤다.
6. 로비에서 비기를 무료로 바꾸되 별도 프리셋은 만들지 않는다. 계보별로
   `생존 1 + 도약 1 + 먹 운용 1`의 현재 장착 상태만 저장한다.
7. 점수 배율, 아이템 출현 확률, 시작 분신 수는 영구 성장에 넣지 않는다.

구현 기준 파일은 `PermanentGrowthCatalog`, `PermanentGrowthProfile`,
`PermanentGrowthRunSnapshot`이다. 아래 stable ID와 의미는 저장 호환 계약이므로
수치 조정이 필요해도 ID를 바꾸지 않는다.

붉은사막 느낌은 기능을 복제한다는 뜻이 아니라, 사용자가 제시한 `REFORMS` 화면처럼
밝은 종이 위를 큰 수묵 줄기와 여러 가지가 가득 채우고 열매 노드가 자연스럽게
붙는 화면 구성을 뜻한다. 먹점프에서는 랜덤한 한 판 성장을 `증강`이 담당하고,
영구 먹나무는 `작은 단계 성장 → 조건부 심화 → 계보별 비기 하나 장착`만 사용한다.

## 2. 참고 구조와 먹점프식 번역

- 붉은사막 참고점은 밝은 전면 캔버스, 한 덩어리의 큰 수묵 구조, 여러 갈래로
  흐르는 가지와 최소한의 고정 글자다. 검은 패널이나 별도 세팅 목록은 붙이지 않는다.
- 비기는 자기 가지뿐 아니라 같은 계보의 다른 일반 열매도 요구한다. 한 줄만
  달려가 최종 효과를 여는 것을 막는다.

## 3. 공통 해금·장착 규칙

### 3.1 해금 그래프

생존·먹 운용은 3단계, 도약은 아래처럼 5단계 가지를 사용한다.

```text
                         A1 ─ A2 ─ A3 ─ (A4 ─ A5) ─ KA
                        /
계보 뿌리 R ──────────── B1 ─ B2 ─ B3 ─ (B4 ─ B5) ─ KB
                        \
                         C1 ─ C2 ─ C3 ─ (C4 ─ C5) ─ KC
```

- `R`은 해당 계보의 첫 열매다.
- A/B/C의 일반 열매는 앞 열매를 순서대로 요구한다.
- 비기 K를 열려면 자기 가지의 마지막 열매와 뿌리를 포함해 해당 계보 일반 열매를
  총 6개 이상 보유해야 한다.
- 따라서 첫 비기는 일반 열매 6개 + 비기 1개, 최소 7방울에 열린다.
- 같은 계보의 비기는 모두 해금할 수 있지만 활성 비기는 정확히 최대 하나다.
- 첫 비기를 구매하면 자동 장착하고, 이후 구매는 현재 장착을 임의로 바꾸지 않는다.

최고 고도 조건은 붙이지 않는다. 막힌 플레이어가 성장을 통해 난도를 넘는 시스템인데
필요한 성장까지 고도 뒤에 잠그면 실패가 실패를 강화하기 때문이다. 깊이는 비용 상승이
아니라 선행 열매 수로 제어한다.

### 3.2 노드 역할과 시각 위계

| 종류 | 역할 | 먹나무 표현 |
|---|---|---|
| 뿌리 | 계보 공통의 작은 기초 효과 | 보통 봉오리, 계보 표식 1개 |
| 일반 수치 | 2~5% 또는 0.05~0.15초의 작은 성장 | 같은 계열 실루엣에 큰 붓덩어리 한 조각 변화 |
| 규칙 열매 | 조건·재사용 대기시간·행동을 바꿈 | 일반보다 12% 큰 먹원과 이중 테두리 |
| 비기 | 출전에 장착하는 강한 패시브 | 가장 큰 열매, 해금 빨강, 장착 금빛 고리 |

아이콘 원본에는 빨강·금빛·숫자·레벨 점을 넣지 않는다. 상태색과 고리는 UI가
합성한다. 같은 가지는 중심 상징을 공유하되 540×960 화면에서 구분되도록 외곽
윤곽과 내부 큰 덩어리를 최소 10% 바꾼다.

생존은 `개체 내구 / 피격 안정 / 먹떼 연계` 세 방향이다. 기본 체력 +1은
24마리에서 잠재적으로 추가 피격 24회가 되므로 내구 가지의 마지막 일반 열매에 둔다.

|---|---|---|---|---|---|
| S00 | 먹피의 씨 | 뿌리 | 장애물 피격 뒤 무적 +0.05초 | 없음 | 작은 먹핵과 열린 보호호 |

- 기본 체력 `3 → 4`
- 피격 뒤 무적 `0.55 → 0.70초`
- 새 분신 기본 보호 `1.00 → 1.15초`
- 피격이 아이템처럼 위로 솟는 느낌을 줄이지 않도록 상승 반동은 낮추고,
  장애물에서 빠져나오기 위한 최소 속도는 남긴다.
- 추락을 직접 막는 일반 열매는 없다. 추락 난도는 도약 C가지와 발판 설계가 담당한다.

## 5. 도약 계보 — 19개

도약은 `준비시간 / 점프 힘 / 점프 높이` 세 방향이다.
점프 힘은 무조건 높을수록 좋은 공격력이 아니다. 과도하면 발판·아이템·카메라를
건너뛰므로 한 판 `도약`까지 합친 장거리 점프 배율을 1.30 안쪽으로 둔다.

| ID | 이름 | 종류 | 효과 | 선행 | 아이콘 핵심 |
|---|---|---|---|---|---|
| J00 | 도약의 씨 | 뿌리 | 자동 점프 준비시간 -1% | 없음 | 짧게 감긴 화살 |
| J-A1~A5 | 고른 박자 I~V | 수치 | 각 준비시간 -1%, 다섯 칸 -5% | 순차 | 먹청록 박자선의 미세한 단계차 |
| J-KA | 벽의 먹발 | 비기 | 하강 중 측면 벽에 붙어 최소 0.22초, 최대 1.2초 머물고 충전 뒤 안쪽 자동점프 | J-A5 + 도약 일반 6개 | 벽에 붙은 먹발과 안쪽 화살 |
| J-B1~B5 | 돋는 먹발 I~V | 수치 | 각 기본 자동 점프 힘 +1%, 다섯 칸 +5% | 순차 | 쪽빛 주줄기의 커지는 도약선 |
| J-KB | 다섯 번째 먹자리 | 비기 | 먹떼 대표의 일반 1차 자동점프 5회마다 폭 3.4m 단방향 안전 발판 1개, 수명 6초 | J-B5 + 도약 일반 6개 | 다섯 점과 금빛 먹선 |
| J-C1~C5 | 높은 먹발 I~V | 수치 | 각 정점 높이 +1.25%, 다섯 칸 +6.25%. 이륙 수직속도에는 제곱근 적용 | 순차 | 옅은 자주먹으로 높아지는 두 획 |
| J-KC | 겹친 먹발 | 비기 | 대표의 일반 자동점프 첫 정점에서 이륙 수직속도 40%로 2단점프, 먹떼 공용 12초 | J-C5 + 도약 일반 6개 | 겹친 두 발과 두 정점 |

도약 완성 상시값:

- 공용 뿌리까지 준비시간 상시 `-6%`, 추가 조건부 충전 보너스는 없다.
- 기본 점프 힘 `+5%`, 정점 높이 `+6.25%`다.
- 한 판 `도약 +20%`와 합친 단일 도약 수직속도 최대치는
  `1.05 × sqrt(1.0625) × 1.20 = 약 1.299배`다.
- 2단점프는 현재 속도에 더하지 않고 첫 이륙 수직속도의 40%로 교체한다.
- 세 비기는 모두 해금할 수 있지만 한 판에는 하나만 장착해 구조 패시브 연쇄를 막는다.

- 기본 발판 수명 `+4%`
- 한 판 성장 최대치와 합치면 최대 먹 `1.06×1.40=1.484`, 먹 회복
  `1.08×1.48=1.598`, 먹비 발판 수명 `0.72×1.04×1.30=0.973`이다.
  먹비 구간의 짧은 발판 정체성은 남는다.
- 한 판 `굳은 획`의 발판별 보호를 먼저 소비하고, 그 보호가 없는 두 번째
  낙묵석부터 장착 비기 `굳은 먹결`의 공용 쿨다운을 검사한다. 두 효과가 서로
  무효화되지 않는다.

## 7. 성장 먹물방울 경제

45개를 전부 한 방울로 바꾸면서 현재의 큰 보상과 구 비용을 일부만 남기면 첫
100m 판 한 번에 성장판 절반 이상이 열릴 수 있다. 비용·보상·저장 변환은 반드시
같은 기능 커밋에서 교체한다.

### 7.1 지급 규칙

- 첫 정상 게임오버: 고도와 관계없이 1개 보장
- 이후 정상 판: `먹떼 진행 고도 12m 이상`이며 `실제 플레이 20초 이상`이면 1개
- 최초 최고 기록 `100 / 250 / 500 / 750 / 1000m`: 각각 보너스 1개
- 디버그 사용, 중도 포기, 이미 정산한 도전 ID: 0개
- 한 판에 여러 최초 이정표를 넘으면 모두 합산

정산 멱등성은 마지막 한 판만 비교하지 않는다. 최근 정산 run ID를 제한된 목록으로
저장해 `A → B → A 재호출`도 다시 지급하지 않는다. 일시정지·증강 선택·화면 전환은
20초 조건의 실제 플레이 시간에서 제외한다.

12m는 첫 보장 먹분신을 경험하는 지점이다. 25m로 올리면 현재 20m 부근에서 막힌
초보자가 첫 보상 뒤 성장까지 막히므로 사용하지 않는다. 20초 조건은 12m 즉시
고의 추락 반복만 늦추는 최소 안전장치다.

### 7.2 진행 속도

- 이정표 다섯 개를 모두 받으면 40번, 받지 못하면 45번의 보상 판에 완성한다.
- 첫 비기는 최소 7방울, 세 계보의 첫 비기는 최소 21방울에 장착 가능하다.
- 문서상 1판 1~3분이면 전체 완성 34~117분이지만 실제 플레이 로그가 아닌 목표치다.

## 8. 비기 장착 규칙

- 장착 칸은 `Survival / Leap / InkHandling` 세 개다.
- 각 장착 칸에는 해당 계보에서 해금한 비기 하나 또는 `없음`만 저장한다.
- 프리셋·세팅 A/B·빠른 교체 목록은 만들지 않는다.
- 먹나무에서 해금한 비기를 직접 선택해 무료 장착하고, 현재 장착 상태 하나만 저장한다.
- 플레이 시작 시 장착 상태를 스냅샷으로 고정한다. 판 중 구매·교체는 없다.
- 비기 구매 시 첫 비기만 자동 장착한다. 두 번째 이후에는 선택 확인을 거쳐야
  현재 장착 비기를 바꾼다.
- 해금된 일반 열매는 비기 장착과 관계없이 항상 적용한다.

UI는 해금된 비기를 빨간 열매, 현재 세팅의 비기를 금빛 외곽 고리로 표시한다.
빨간 점 장식을 따로 추가하지 않는다.

## 9. 저장·코드 구조 변경

`PermanentGrowthNodeDefinition`은 이제 개별 열매의 이름·아이콘·효과를 직접
소유한다. v3 구현은 다음 경계를 저장·런타임·UI가 함께 지키도록 구성한다.

1. 노드가 stable `Id`, `DisplayName`, `IconKey`, `EffectId`, `EffectValue`,
   `ParentIds`, `Branch`, `NodeKind`를 직접 소유한다.
2. `NodeKind`는 `Root / Stat / Mechanic / Keystone` 네 종류로 확장한다.
3. 비기에 `RequiredOwnedCountInBranch=6`, `KeystoneGroup`을 저장한다.
4. 프로필에는 45개 node ID의 소유 여부와 활성 비기 ID 세 개만 저장한다.
5. `balanceVersion=2` 저장은 v3로 순차 마이그레이션해 ID·지갑·정산 이력·장착을
   보존하고, 기존 도약 비기 보유자는 해당 길의 새 4·5단계를 완료 처리한다.
6. 구 지갑은 구 남은 비용 대비 진행 비율만 새 남은 노드 수에 비례 변환한다.
7. 한 계보의 구 level 합계가 새 13개를 넘으면 초과 단계는 한 단계당 먹빛 1개로
   환급하되 지갑+남은 노드 상한을 넘지 않는다.
8. 현재의 큰 보상식과 전부 1인 비용은 한 커밋에서 동시에 교체한다.

## 10. 한 판 증강과의 중복 규칙

| 영구 성장 | 한 판 증강 | 처리 |
|---|---|---|
| 깊은 먹심 최대 체력 +1 | 먹두께 공용 완충 | 서로 다른 자원이라 모두 적용 |
| 먹결 도약 | 도약 +20% | 곱연산 후 긴 발판 최대 배율 1.30 이하 |
| 최대 먹·회복·수명 | 큰 벼루·먹샘·긴 여운 | `기본×영구×한 판×구간` 순서 유지 |
| 굳은 먹결 18초 공용 보호 | 굳은 획 발판별 보호 | 발판별 보호 먼저, 공용 보호 나중 |
| 없음 | 겹친 획 +1 슬롯 | 영구 성장에는 슬롯 증가를 넣지 않아 선택 가치 유지 |
| 없음 | 길운 아이템 간격 | 영구 성장에는 아이템 확률·간격을 넣지 않음 |

## 11. 밸런스 검증 기준

Unity 테스트는 수치가 코드에 들어갔는지만 확인한다. 재미와 난도는 아래 실제 판
데이터를 함께 봐야 한다.

- 정상 판 고도·실제 플레이 시간·사망 원인(`추락 / 장애물`)
- 30m 도달률과 첫 증강 25m 도달률
- 먹이 10% 아래였던 시간 비율과 먹 고갈 횟수
- 발판의 자연 소멸·예산 밀림·낙묵석 파괴 횟수
- 각 일반 열매 구매율, 계보별 비기 장착률, 비기 발동 횟수
- 분신 수와 최대 체력 +1 전후의 유효 피격 횟수

최소 30판의 동일 버전 QA에서 같은 계보 비기 장착률이 60%를 넘거나 15% 아래면
그 비기는 과대 또는 과소 효용 후보로 본다. 발동형 비기가 평균 0.5회/판보다 적으면
조건이 보이지 않거나 너무 어렵고, 제한형 비기가 설계 쿨다운마다 거의 항상 발동하면
쿨다운이 짧은지 확인한다.

## 12. 구현 순서

1. v3 노드 ID·부모·비기 장착 데이터 구조와 저장 마이그레이션을 먼저 테스트한다.
2. 모든 비용 1과 새 정산식을 같은 커밋에서 적용한다.
3. 상시 수치 열매를 구현하고 `영구×한 판×구간` 상한 테스트를 추가한다.
4. 규칙 열매와 비기를 계보별 한 묶음씩 구현한다.
5. 먹나무를 `13/19/13` 세 주가지와 각 3개 곁가지로 배치한다.
6. 45개 고유 아이콘과 9개 비기 아이콘의 큰 실루엣 차이를 검증한다.
7. 단일 장착 상태, 무료 교체, 시작 시 스냅샷을 실제 세로 Game View에서 검증한다.
8. 최소 30판 QA 뒤 수치만 조정하고 노드 의미·stable ID는 유지한다.
