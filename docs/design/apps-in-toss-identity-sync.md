# 앱인토스 계정·성장 동기화 결정

## 결정

먹점프 앱인토스판에는 Apple·Google 로그인과 별도 로그인 선택 화면을 넣지 않는다.
게임용 `getUserKeyForGame`으로 사용자를 식별하고, `순위`는 공식 토스 게임센터를 연다.
영구 성장은 이 사용자별 자체 서버 저장으로 동기화한다. 현재 무현금성 게임 진행에는
추가 `appLogin` 동의 화면을 기본 흐름에 넣지 않는다. iOS·Android 네이티브의 기존
Apple/Google·뒤끝 동기화 경로는 별개로 유지한다.

앱인토스의 로그인 정책은 다른 소셜·간편 로그인을 허용하지 않는다.
[서비스 오픈 정책 §2-3](https://developers-apps-in-toss.toss.im/intro/guide).
같은 게임의 같은 사용자는 삭제·기기 변경 뒤에도 동일한 게임 hash를 받는다.
[사용자 식별키](https://developers-apps-in-toss.toss.im/documentation/common/authentication/hash-key).
이 키가 있다고 저장 데이터까지 자동 복원되는 것은 아니다. 로컬 Storage의 삭제·기기 변경
보존에는 자체 서버가 필요하다. [공식 FAQ](https://developers-apps-in-toss.toss.im/faq.html).

## 현재 구현과 남은 구현의 구분

| 항목 | 현재 상태 |
| --- | --- |
| 토스 게임 사용자 확인 | SDK hash와 게임센터 프로필 확인, 로컬 소유자 대조 구현 |
| 공식 순위 | 정상 정산된 최고점 제출, 소유자별 재시도, 순위 열기 구현 |
| 성장·먹빛 저장 | 기기 내 PlayerPrefs·백업·미정산 복구 구현 |
| 기기 간 성장 복원 | **미구현**. WebGL `SaveNow`와 `NotifyRunSettled`는 no-op |
| 토스 성장 서버·DB·mTLS | 이 저장소에서 배포된 연동 경로를 확인하지 못함 |

`OnlineReady`는 현재 코드에서 사용자 확인이 끝났다는 뜻이지 성장 동기화 완료가 아니다.
새 옵션은 이를 동기화 완료로 표시하지 않는다. 서버가 준비되기 전 출시본에
‘기기 변경 후 성장 복원’을 제공한다고 안내해서는 안 된다.

## 옵션에 남길 것

- 배경음·효과음·진동·움직임 줄이기, 음량 조절, 튜토리얼, 고객센터, 순위, 정책, 닫기.
- 기본 화면의 게스트 소개·조작 반복 설명은 제거한다.
- 앱인토스에서는 네이티브 로그인/로그아웃/계정 삭제/클라우드 충돌 창/내장 TOP 10 및
  네이티브 UMP용 광고 선택 항목을 **생성하지 않는다**. 토스 SDK의 동의 UI는 변경하지 않는다.
- 사용자 확인이 실패하면 `기록 확인`과 실제 오류, `다시 확인`만 보여준다.
  확인 중 입력·시작 차단과 다른 소유자 기록 보호는 유지한다. 성공하면 옵션으로 돌아온다.
- 네이티브의 계정 삭제·서버/기기 기록 교체 경고는 짧게 남긴다. 안전 경고를 장식 문구처럼 지우지 않는다.

## 서버 동기화 설계 — 다음 구현 기준

이 절은 토스가 자동 제공하는 기능이 아니라 먹점프가 구현할 저장 계약이다.

1. **식별·접근 제어**: 게임 hash는 HTTPS 본문/헤더로만 전달하고 URL·분석·오류 로그에 남기지 않는다.
   파트너 서버가 mTLS로 식별키 검증 API를 호출한다. 검증 실패·네트워크 실패는 정상 로그인이나
   신규 사용자로 간주하지 않는다. 서버가 결정한 사용자에만 짧은 세션의 읽기/쓰기를 허용하며
   요청 본문의 임의 `ownerHash`로 다른 저장 슬롯을 고르게 하지 않는다.
2. **저장 단위**: 사용자별 `bestHeight`, 성장 balance/schema, 먹빛·구매·누적 거리·보상 문턱,
   튜토리얼, 서버 `revision`, 서버 시간, 처리된 operation/run ID를 하나의 논리 레코드로 관리한다.
   소리·진동·움직임 줄이기는 기기 설정으로 유지한다.
3. **서버 판정**: 구매·초기화·정산은 operation ID와 기대 revision으로 요청한다. 재화/단계/비용을
   서버가 검증하고 트랜잭션으로 처리한다. 동일 operation 재전송은 원래 결과를 반환한다.
   서버 중복 방지 장부를 로컬의 최근 64개 run 이력으로 대체하지 않는다.
4. **충돌**: 최고점은 max 병합 가능하나 먹빛·구매·누적 거리의 합산 또는 필드별 max 병합은 금지한다.
   revision 충돌은 최신 서버 상태를 다시 읽고 명시적인 미처리 연산만 재검증한다.
   오래된 기기의 전체 스냅샷이 최신 구매를 덮어쓰지 못하게 한다.
5. **로컬 복구**: 사용자별 캐시/outbox에 먼저 안전하게 기록하고 통신 실패 시 재시도한다.
   서버 조회 실패를 ‘저장 없음’으로 해석해 빈 데이터로 업로드하지 않는다.
   기존 로컬 저장의 최초 이관은 서버 레코드가 없을 때 단 한 번 서버 승인으로 처리한다.
6. **소유자 전환**: 성장뿐 아니라 최고점·백업·복구 표식·미정산 run·대기 점수를 모두 사용자별로
   격리한 후 원자적으로 전환한다. 현재의 소유자 불일치 차단을 단순 삭제하지 않는다.
   앱 복귀 시 식별자 재검증과 진행 중 판의 소유자 고정도 함께 구현한다.

검증 API는 `POST /api-partner/v1/apps-in-toss/users/anon-key/verify`, `x-anon-key`를 사용한다.
mTLS 인증서는 **서버에만** 둔다. 현 API 문서는 성공 값을 boolean으로, 구 안내는 문자열로
표기하므로 연동 전 실제 응답을 확인하고 HTTP 상태·`resultType`·성공 값을 엄격히 검사한다.
[식별키 API](https://developers-apps-in-toss.toss.im/api/user-key),
[서버 인증](https://developers-apps-in-toss.toss.im/api/auth).

### 보안 한계

mTLS는 파트너 서버를, 식별키 API는 hash의 유효성을 확인한다. 현재 문서에 nonce·서명·기기
바인딩 등 요청자의 별도 소유 증명 계약은 없다. 따라서 유효한 hash만으로 현재 요청자의
소유를 재인증했다고 단정하지 않는다. 초기 hash 유출/재사용 위험은 자체 세션만으로 사라지지
않으며 로그 비노출·짧은 세션·접근 제어·속도 제한·서버 경제 검증을 함께 적용한다.
유료 재화·네이티브 계정 연결·민감한 계정 삭제로 확장할 때는 토스 `appLogin` 인가코드 기반
추가 인증을 별도로 검토한다. 앱별 hash만으로 iOS/Android 계정과 자동 연결하지 않는다.

## 완료 게이트

- 파트너 서버/DB와 mTLS 인증서 준비 및 실제 식별키 검증.
- 두 기기 성장 복원, 재설치 복원, 조회 실패 후 빈 저장 덮어쓰기 방지.
- 동시 구매·초기화·정산 재시도에서 재화 복제/중복 보상 없음.
- 토스 계정 전환 시 캐시·미정산·순위 대기열 격리.
- 실제 토스 QR 환경에서 검증. Editor/샌드박스 mock 결과는 실제 동기화 증거가 아니다.

이번 작업은 옵션 정리·플랫폼별 UI 제외·위 동기화 방식 결정까지다. 서버 생성·배포·데이터
이관·토스 콘솔 변경은 실행하지 않았다. 서로 다른 두 읽기 전용 검토(공식 문서/현 코드)를
교환해 이 경계를 확인했다.

## 이번 코드 검증

- 현재 런타임, Editor/검사 코드, `UNITY_WEBGL` 플레이어 분기를 Unity 번들 Roslyn으로 각각
  컴파일해 오류 0건을 확인했다. 출력은 `/tmp`에 두고 Unity의 DLL을 직접 교체하지 않았다.
- 옵션 설명 미생성, 플랫폼별 로그인/UMP/내장 순위 미생성, 필수 확인의 대기/실패/성공 복귀,
  정상 상태에서도 저장 재시도·재연결 경고 보존 검사 10건을 추가했다.
- 읽기 전용 교차검토에서 정상 인증 상태의 저장 실패 안내가 숨겨질 수 있다는 지적을 받아
  Phase 기반 필터를 제거했다. 알려진 정상 문구만 생략하도록 수정한 뒤 재검토에서 해소를 확인했다.
- Unity 실행 검사는 에디터가 요청에 응답하지 않아 진행하지 못했다. 기존 XML/촬영은 이번
  변경의 통과 증거로 사용하지 않는다. 실제 토스 QR·두 기기 성장 동기화 검증도 아직 미실시다.
