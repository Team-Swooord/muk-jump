# 로비 · 영구 성장 · 도감 · 옵션 UI 규격

> 기준일: 2026-07-30 · 영구 성장 계보 개정: 2026-07-31
> 기준 화면: 세로형 `1080×1920`
> 목적: 로비에서 **시작 → 영구 성장 확인 → 도감 탐색 → 옵션/가이드**를
> 작은 글씨나 모호한 버튼 없이 한눈에 이해하게 한다.

이 문서는 현재 UI 개편의 단일 설계 규격이다. 구현 세부는 바뀔 수 있지만
영구 성장과 한 판 두루마리의 경계, 로비 버튼 보정, 글자 가독성, 색 사용 원칙은
후속 UI 작업에서도 유지한다.

## 1. 반드시 분리할 두 성장

| 구분 | 로비 `성장` | 플레이 중 `증강` |
|---|---|---|
| 시점 | 게임 시작 전 로비 | 한 판 진행 중 |
| 재화/획득 | 정상 게임오버에서 얻은 `먹빛` | 월드의 성장 두루마리 획득 |
| 지속 시간 | 게임을 꺼도 영구 저장 | 현재 판에서만 유지 |
| 내용 | 생존·도약·먹 운용 3계보, 총 10노드 | 먹두께·도약·큰 벼루 등 현재 판 선택 |
| UI | `PermanentGrowthView` | `GrowthChoiceView` |
| 저장/상태 | `PermanentGrowthProfile` | `RunGrowthController` |
| 초기화 | 저장 삭제 전까지 유지 | 새 도전에서 모두 초기화 |

두 시스템은 enum, 저장 데이터, 선택 후보, 화면을 공유하지 않는다. 최종 플레이 수치는
`직렬화 기본값 × 영구 성장 × 현재 판 증강 × 구간 배율` 순서로 합성한다.
로비의 `성장`을 “다음 판 첫 두루마리 예약”처럼 설명하거나 표시하지 않는다.

## 2. 조사 근거와 먹점프 적용 판단

다시 설계하며 다른 게임의 이미지·문구·코드를 복제하지 않는다.

## 3. 영구 적용 UI 규칙

### 3.1 타이포와 터치

- 모든 주요 텍스트는 `InkPalette.UiFont`와 합성 `Bold`를 기본으로 한다.
- 권장 기준은 화면 제목 64px, 카드 제목 42px, 본문 34px, 보조 정보 30px,
  로비 메뉴 46px이다. 작은 화면에서 개별 글자를 줄이지 말고 패널 전체를 Safe Area
  안에서 균등 축소한다.
- 주요 버튼 높이는 기준 화면에서 120px 이상으로 확보한다.
- `Best Fit`은 사용하지 않는다. 문구가 길면 줄바꿈·영역 확대·문구 축약 순으로 해결한다.
- 먹색 본문과 한지 배경 사이에 얇은 외곽선을 사용하되, 글자의 획을 뭉개는 두꺼운
  테두리는 쓰지 않는다.
- 영구 성장 화면은 단일 `Std` 굵기의 합성 Bold가 축소 화면에서 가늘어지므로,
  제목 2.5px·부제와 재화 2px·본문 1.5~1.8px의 동일 글자색 외곽선으로 획만
  보강한다. 대비용 검은 테두리처럼 보이거나 자간을 메울 정도로 두껍게 만들지 않는다.
- 버튼은 눌렀을 때 약 `0.97` 배로 줄어드는 100~160ms 반응과 작은 먹물 터치
  피드백을 제공한다. 비활성 버튼에는 터치 연출을 내지 않는다.
- 장식용 빨간 점은 금지한다. 빨강은 신기록·위험·구매 확정 같은 실제 의미가 있을
  때만 낙관이나 상태색으로 제한한다.

### 3.2 로비 버튼의 영구 보정

로비 버튼 PNG의 피사체가 왼쪽으로 치우쳐 있으므로 Transform 중앙값만 맞추면
텍스트가 시각적으로 삐뚤어 보인다. 사용자가 조정한 `최고 102` 표시 칸을 기준으로
아래 보정을 **시작·성장·도감·옵션과 이후 같은 PNG를 쓰는 모든 버튼**에 적용한다.

| 항목 | 기준값 |
|---|---:|
| 버튼 배경 크기 | `610.273 × 130.157` |
| 버튼 배경 X 보정 | `+89` |
| 텍스트 X/Y 보정 | `-87 / -5` |
| 텍스트 영역 | `400 × 80` |
| 텍스트 크기/굵기 | `46px / Bold` |

이 값은 씬 Inspector에서 수동 조정하지 않고 `LobbyMenuLayout` 한 곳에서 관리한다.
`MukJumpSceneBuilder`와 구버전 씬의 런타임 보정이 같은 값을 읽으므로, Play 중이던
이전 Main 백업이 복원돼도 시작·성장·도감·옵션이 즉시 같은 배치를 사용한다.
스프라이트를 교체하면 같은 눈금값을 무조건 유지하는 대신 새 피사체의
시각 중심을 측정하되, 네 버튼에는 항상 동일한 보정을 한 번에 적용한다.

### 3.3 공용 행동 버튼

- 로비의 `시작·성장·도감·옵션` 네 버튼은 위 전용 PNG와 수동 보정을 유지한다.
- 그 외 `다음·이전·강화·닫기·옵션으로·계속하기·로비로`와 설정의 텍스트
  버튼은 `MukJump/UI/Common/action_button_brush` 한 장을 공유한다.
- 공용 행동 버튼 글자는 Bold 40px 이상, 일반 텍스트 버튼은 Bold 36px 이상을
  유지하며 한지 위에서도 획이 사라지지 않는 얇은 먹색 외곽선을 사용한다.
- 작은 버튼에서 모서리 조각만 남지 않도록 9-slice 테두리를 두지 않고 원본 붓획
  전체를 Simple 방식으로 축소·확대한다. 화면별 코드는 위치·크기·문구만 소유하고
  그림을 다시 만들지 않는다.
- 흰 알파 마스크에 `InkPalette.Ink`를 입혀 눌림·비활성 색 전환이 동작하게 한다.
- 증강 카드, 도감 카드, 영구 성장 가지, 원형 일시정지 아이콘과 디버그 버튼은
  의미가 다른 선택면이므로 공용 행동 버튼 스킨을 적용하지 않는다.

### 3.4 로비 계층과 움직임

버튼은 위에서 아래로 `시작 → 성장 → 도감 → 옵션` 한 열로 배치한다. 기준 앵커 Y는
각각 `0.460 / 0.385 / 0.310 / 0.235`이며, 가장 가능성이 높은 행동인 `시작`을
기존보다 위에 둔다. 버튼 내부의 수동 보정은 바꾸지 않고 메뉴 그룹 앵커 X만
`0.50`의 화면 중앙에 두며 최고 기록도 같은 중앙 레일을 사용한다. 현재 선택된
메뉴 배경은 100% 먹 농도, 나머지 세 메뉴의 배경은 78% 농도로 표시하며 로비의
기본 선택은 `시작`이다. 네 버튼의 글자 농도는 항상 100%를 유지한다.
실제 포커스로 오해할 수 있는
상시 선택 커서는 두지 않으며, 버튼마다 크기나 정렬 방법은 달리하지 않는다.

### 3.4.1 성장 화면 글자 최소 규격

- 계보 제목 36px, 계보 요약 25px, 노드명 34px, 노드 단계 28px 이상.
- 최종 패시브 노드는 이름 36px, 단계 29px 이상으로 한 단계 더 강조한다.
- 상세판은 성장명·설명·현재/다음 효과 32px 이상, 비용·잠금 이유 28px 이상이다.
- 세 계보는 화면 중심의 동일 폭 세로 열을 사용하고, 노드 전체 터치 영역은
  최소 `100×100px`, 최종 패시브는 최소 `126×126px`로 유지한다.
- 노드 안에는 이름과 단계만 두고 긴 설명·비용·선행 조건은 `920×330` 공용
  상세판 한 곳에서만 보여 준다. 동일 정보를 각 노드에 반복하지 않는다.
- 노드와 상세판 텍스트에 자동 축소와 `Overflow`를 사용하지 않는다. 상세 설명은
  필요한 경우 두 줄을 허용하되 아이콘·강화 버튼과 영역을 겹치지 않는다.

로비 하단에는 먹방울과 시작 먹선을 표시하지 않는다. 실제 첫 점프에 필요한 플레이어와
화면 폭 `-5.35~+5.35`의 영구 시작 먹선은 물리 구조로만 준비하고, `시작`을 누른
순간 함께 표시해 자동 점프 물리로 전환한다. `LobbyWorldSetup`이 이 표시 경계를
소유하며 Unity가 구버전 Play 씬을 복원해도 기존 왕복 이동을 비활성화한다.

### 3.5 입력·전용 화면·모달

- 로비의 Canvas는 보이는 동안 `interactable=true`, `blocksRaycasts=true`를 유지한다.
- 성장과 도감은 로비 위의 팝업이 아니라 불투명 한지 배경을 가진 전용 전체 화면이다.
  `LobbyScreenNavigator`가 로비·성장·도감 중 하나만 표시한다.
- 로비↔성장/도감 이동은 `BrushTransitionView`를 사용한다. 화면이 완전히 덮이기
  전에는 기존 화면을 유지하고, 덮인 시점에 목적 화면으로 교체하며, 드러남이
  끝나야 목적 화면 입력을 연다.
- 전환 중 연속 탭과 게임 시작은 무시한다. 투명 전체 화면 blocker가 뒤 UI를 막고
  장식 붓획은 레이캐스트를 받지 않는다.
- 옵션만 로비 위 모달로 유지한다. 닫힌 모달은 `alpha=0`, `interactable=false`,
  `blocksRaycasts=false`를 함께 적용한다.
- EventSystem은 Input System UI 모듈과 에디터 입력 복구 가드를 유지한다.
- 버튼의 그래픽은 레이캐스트를 받을 수 있어야 하지만, 장식 이미지와 먹물 이펙트
  오버레이는 입력을 가로채지 않는다.
- 성장·도감 전용 화면과 옵션 모달은 한 번에 하나만 열고, 플레이 드로잉 입력으로
  전달하지 않는다.

### 3.6 화면 공통 정보 위계

- 레퍼런스의 회색 기하 도형은 복제하지 않고 `비대칭 정렬·넓은 여백·단일 주 행동`
  원칙만 먹점프의 한지와 먹 농도로 번역한다.
- 도감은 왼쪽의 큰 제목·짧은 안내와 오른쪽 계보 필터를 한 상단 띠로 묶고,
  그 아래에 얇은 먹선, 큰 그림 카드, 하단 페이지 이동 순서로 읽히게 한다.
- 옵션은 왼쪽 제목과 오른쪽 버전을 한 줄에 두고 `UID → 소리 → 도움과 정보 →
  닫기`의 네 덩어리만 유지한다.
- 일시정지에서는 `계속하기`를 100%, `로비로`를 72% 먹 농도로 구분한다.
  결과창은 `도전 끝 → 이번 고도 → 최고 고도·먹빛 → 로비 복귀` 순서로 왼쪽
  정렬해 가장 큰 수치가 먼저 읽히게 한다.
- 자주 보는 로비·일시정지에는 반복 입장 stagger나 장식 동작을 추가하지 않는다.
  기존 100~180ms 눌림·열림 반응만 유지한다.

## 4. 영구 성장 화면

전용 화면 첫 시선에서 `보유 먹빛 → 세 성장 계보 → 선택한 단계와 비용`이
순서대로 읽혀야 한다.

- `생존·도약·먹 운용`을 동일 폭의 세 세로 계보로 표시하고, 아래 기초 노드에서
  위 최종 패시브까지 실제 연결선을 그린다.
- 총 10개 노드는 큰 아이콘, 짧은 이름과 현재/최대 단계만 보여 준다. 노드를
  누르면 하단 상세판에 `현재 → 다음` 수치, 설명, 비용과 선행 조건을 갱신하며,
  실제 구매는 상세판의 단일 `강화` 버튼에서만 확정한다.
- 잠긴 노드도 선택 가능해야 하며 `먹심 Lv.1 필요`처럼 잠금 이유를 상세판에서
  정확히 알려 준다. 잠금 상태의 탭이 구매로 이어져서는 안 된다.
- 기존 저장에서 이미 level>0인 노드는 grandfather 처리해 잠금 상태로 되돌리지
  않으며, 새 선행 조건을 충족하지 않아도 남은 단계를 계속 강화할 수 있게 표시한다.
- 미구매 경로는 옅은 먹, 구매 단계는 짙은 먹으로 구분한다. 처음 해금된 노드는
  마른 봉오리에서 붉은 열매로 바뀌고, 완성 표식은 절제된 금빛을 쓴다.
  장식용 빨간 경로나 붉은 나무 채움은 사용하지 않는다.
- 구매 가능/불가능은 색만으로 구분하지 않고 비용과 버튼 활성 상태를 함께 보여 준다.
- 최대 단계는 상세판의 강화 버튼 문구를 `완성`으로 바꾸고 비활성화한다.
- 처음 0→1단계를 여는 해금은 대각선 먹획 두 개가 화면을 잠깐 감싸고,
  `잠금 → 중앙 먹물 파열 → 성장 해금·성장명 → 금빛 먹고리` 순서로 1.26초 안에
  끝낸다. 한 장의 먹빛 장막과 재사용 UI만 사용하며 입력은 가리지 않는다.
- 2단계 이후 레벨업은 같은 고정 UI 계층과 타임라인을 0.86초로 압축해
  `Lv.N → 중앙 먹물 파열 → 성장 강화·성장명 → 금빛 먹고리` 순서로 재생한다.
  나무·가지에 별도의 붉은 마스크를 덮지 않으며 검은 진행도와 붉은 열매 상태는
  구매 직후 확정한다. 선택한 열매의 화면 위치에만 짧은 붉은 번짐을 겹친다.
- 구매 실패나 재화 부족에는 레벨업 연출을 재생하지 않는다.
- 전용 성장 아트와 UI는 앱 로비 시작 때 미리 만들지 않는다. 붓 전환이 화면을
  완전히 덮은 최초 진입 때 한 번 생성하고, 이후에는 같은 스프라이트 캐시와
  비활성 Canvas를 재사용한다.

## 5. 먹결 도감

도감 전용 화면의 첫 시선은 설명 목록이 아니라 **큰 그림을 고르는 화면**이다.

- 한 페이지에 네 장을 2×2로 배치해 모바일에서도 아이콘을 크게 유지한다.
- 카드 앞면은 큰 아이콘, 이름, 번호, `사용 가능/기획 중` 상태만 보여 준다.
- 카드를 누르면 X축이 접히는 약 0.22~0.26초 뒤집기 동작으로 뒷면을 연다.
- 뒷면에는 이름, 효과 설명, 계열, 단계, 최대 레벨을 표시한다. 다시 누르면 앞면으로
  돌아간다.
- 페이지 이동과 필터는 고정된 카드 네 장의 내용만 교체한다. 100개 GameObject를
  한꺼번에 생성하지 않는다.
- `RuntimeReady`만 현재 판 선택 후보가 될 수 있다. `Planned`는 도감에서 미래
  계보를 설명할 뿐 선택·레벨 변경을 일으키지 않는다.
- 잠금 상태는 그림을 완전히 숨기지 않는다. 형태를 볼 수 있게 하되 상태 문구와
  낮은 명도로 구분한다.

## 6. 옵션과 4장 게임 가이드

옵션은 설정과 도움말을 한곳에서 다시 찾게 하는 로비 전용 화면이다.

### 6.1 게임 가이드

가이드는 언제든 다시 열 수 있고, 시작을 강제 차단하지 않는다.

1. **먹방울은 스스로 뛰어요** — 캐릭터를 직접 움직이는 게임이 아님을 먼저 설명한다.
2. **착지할 곳에 한 획을 그려요** — 다음 착지점을 손가락 선으로 만든다.
3. **선의 기울기가 방향을 정해요** — 발판 각도와 점프 방향의 관계를 보여 준다.
4. **먹을 아끼며 더 높이 올라요** — 제한된 먹과 최고 고도 목표를 마무리로 설명한다.

각 장은 큰 기존 성장 심벌 하나와 한 문장만 사용한다. 이전/다음/닫기 버튼을 크게
두고 현재 페이지 `1/4`를 함께 표시한다.

### 6.2 설정 항목

- 제목 바로 아래에는 버전과 플레이어 UID를 두며, UID는 로컬에서 생성한
  `MUK-XXXXXXXX` 형식이고 한 줄 전체를 탭하면 복사한다.
- BGM과 효과음은 같은 높이의 2열 카드로 묶는다. 각 카드에는 현재 퍼센트,
  슬라이더, `켜짐/꺼짐`을 함께 표시해 색만으로 상태를 구분하지 않는다.
- 도움과 정보는 `언어 / 고객센터`, `계정 연동 / 튜토리얼`의 2×2로 배치한다.
  고객센터와 튜토리얼은 같은 오른쪽 열이며 튜토리얼이 바로 아래에 온다.
- 언어는 실제 전환 기능이 없으므로 `한국어 · 고정`, 고객센터는 `준비 중`을
  명시한다. 튜토리얼은 기존 4장 가이드를 실제로 연다.
- 계정 연동은 Google Play와 Apple을 하나의 항목으로 묶되 실제 인증을 하지 않는
  `준비 중` 목업이다. 로그인 성공처럼 보이게 하거나 계정·토큰을 저장하지 않는다.
- 알림·진동·쿠폰처럼 참고 화면에만 있고 구현되지 않은 항목은 추가하지 않는다.
  오디오와 가이드 확인 여부만 로컬 설정에 저장한다.
- 주요 버튼 높이는 120px 이상이며, 좁고 긴 화면에서는 `900×1510` 옵션 두루마리
  전체를 Safe Area 안으로 균등 축소한다.

## 7. 검수 기준

- Game View에서 시작·성장·도감·옵션 네 버튼이 첫 탭에 모두 반응한다.
- 네 버튼의 배경 크기, 텍스트 영역, 글자 크기, 시각 중심이 동일하다.
- 로비 버튼 순서가 `시작 → 성장 → 도감 → 옵션`이며 하단 먹방울·시작 먹선이
  로비 화면에 노출되지 않는다.
- 로비↔성장/도감은 붓 전환의 덮임 시점에만 교체되고, 전환 중 뒤 UI·연속 탭·
  게임 시작이 차단된다.
- 전용 화면의 `로비` 버튼으로 같은 전환을 거쳐 돌아오며 로비 입력이 정확히 한 번
  복구된다.
- 모든 주요 문구가 세로형 작은 화면에서 자동 축소 없이 읽힌다.
- 성장 가지를 고르는 것만으로 재화가 차감되지 않으며, 하단 상세판의 강화 버튼을
  누른 성공 구매에만 레벨업 먹물 연출이 나온다.
- 도감 카드 앞면의 그림이 가장 크고, 탭하면 설명 뒷면으로 뒤집힌다.
- 옵션의 네 가이드 장, 두 오디오 카드, UID, 언어·고객센터·계정 목업을 확인할 수 있다.
- 고객센터 바로 아래에 튜토리얼이 있으며, 닫힌 옵션은 뒤 UI 입력을 가로채지 않는다.
- 장식용 빨간 점이 없고, 먹물 터치 오버레이가 버튼 입력을 막지 않는다.
- 닫은 옵션 모달과 숨긴 전용 화면이 뒤 UI의 레이캐스트를 가로채지 않는다.
