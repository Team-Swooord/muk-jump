# 로비 · 영구 성장 · 도감 · 옵션 UI 규격

> 기준일: 2026-07-30
> 기준 화면: 세로형 `1080×1920`
> 목적: 로비에서 **시작 → 영구 성장 확인 → 도감 탐색 → 옵션/가이드**를
> 작은 글씨나 모호한 버튼 없이 한눈에 이해하게 한다.

이 문서는 현재 UI 개편의 단일 설계 규격이다. 구현 세부는 바뀔 수 있지만
영구 성장과 한 판 두루마리의 경계, 로비 버튼 보정, 글자 가독성, 색 사용 원칙은
후속 UI 작업에서도 유지한다.

## 1. 반드시 분리할 두 성장

| 구분 | 로비 `성장` | 플레이 중 `두루마리` |
|---|---|---|
| 시점 | 게임 시작 전 로비 | 한 판 진행 중 |
| 재화/획득 | 정상 게임오버에서 얻은 `먹빛` | 월드의 성장 두루마리 획득 |
| 지속 시간 | 게임을 꺼도 영구 저장 | 현재 판에서만 유지 |
| 내용 | 먹그릇·숨고르기·먹결·발놀림 4축 | 먹두께·도약·큰 벼루 등 현재 판 선택 |
| UI | `PermanentGrowthView` | `GrowthChoiceView` |
| 저장/상태 | `PermanentGrowthProfile` | `RunGrowthController` |
| 초기화 | 저장 삭제 전까지 유지 | 새 도전에서 모두 초기화 |

두 시스템은 enum, 저장 데이터, 선택 후보, 화면을 공유하지 않는다. 최종 플레이 수치는
`직렬화 기본값 × 영구 성장 × 현재 판 두루마리 × 구간 배율` 순서로 합성한다.
로비의 `성장`을 “다음 판 첫 두루마리 예약”처럼 설명하거나 표시하지 않는다.

## 2. 조사 근거와 먹점프 적용 판단

| 공식 자료 | 확인한 원칙 | 먹점프 적용 |
|---|---|---|
| [Apple HIG — Onboarding](https://developer.apple.com/design/human-interface-guidelines/onboarding) | 온보딩은 빠르고 재미있고 선택 가능해야 하며, 설정/도움말에서 다시 볼 수 있어야 한다. 한 번에 전체 설명보다 실제 맥락에 가까운 짧은 안내가 낫다. | 옵션 안에 다시 열 수 있는 4장 가이드를 둔다. 한 장에는 한 행동만 설명하고 시작을 막지 않는다. |
| [Apple HIG — Typography](https://developer.apple.com/design/human-interface-guidelines/typography) | 글자 크기·굵기·간격으로 위계를 만들고, 서체 수를 줄이며, 자동 축소에 기대지 않는다. | 헬스셋 조릿대 하나와 Bold 위계를 사용한다. 본문 영역을 먼저 넓히고 `Best Fit`으로 글자를 작게 만들지 않는다. |
| [Apple HIG — Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons) | 버튼은 충분히 큰 터치 영역, 일관된 크기와 명확한 눌림 상태가 필요하다. | 로비 버튼 크기를 통일하고, 실제 레이캐스트 영역을 시각 영역과 일치시킨다. 탭 시 짧은 축소와 먹물 피드백을 제공한다. |
| [Vampire Survivors — Steam 공식 페이지](https://store.steampowered.com/app/1794680/Vampire_Survivors/) | 한 판에서 모은 자원으로 다음 생존자를 위한 영구 업그레이드를 구매하는 단순한 메타 루프를 명시한다. | 먹빛을 영구 성장 하나에만 사용하고, 현재 판 두루마리와 화면·문구를 분리한다. |
| [Hades — Nighty Night Update](https://www.supergiantgames.com/blog/hades-the-nighty-night-update-patch-notes/) | Mirror의 상호 배타 선택, 두 행씩 점진 해금, Permanent Record의 진행 정보, Codex 항목 개선을 함께 다룬다. | 성장 화면은 4축의 현재/다음 차이를 비교하고, 도감은 잠금·계보·구현 상태를 읽는 화면으로 유지한다. |
| [Hades — 공식 업데이트 모음](https://www.supergiantgames.com/blog/hades-updates/) | 재능 최대 단계 연출, 도감 이미지, 글자 크기, 통일된 텍스트 표현과 메뉴 조작성을 반복 개선했다. | 레벨업은 짧고 명확한 먹물 연출로 확정 피드백을 주고, 도감은 설명보다 큰 그림을 먼저 보여 준다. |

위 자료는 구조를 검토하기 위한 참고다. 레이아웃과 수묵 표현은 먹점프 전용으로
다시 설계하며 다른 게임의 이미지·문구·코드를 복제하지 않는다.

## 3. 영구 적용 UI 규칙

### 3.1 타이포와 터치

- 모든 주요 텍스트는 `InkPalette.UiFont`와 합성 `Bold`를 기본으로 한다.
- 권장 기준은 화면 제목 64px, 카드 제목 42px, 본문 34px, 보조 정보 30px,
  로비 메뉴 37px이다. 작은 화면에서 개별 글자를 줄이지 말고 패널 전체를 Safe Area
  안에서 균등 축소한다.
- 주요 버튼 높이는 기준 화면에서 120px 이상으로 확보한다.
- `Best Fit`은 사용하지 않는다. 문구가 길면 줄바꿈·영역 확대·문구 축약 순으로 해결한다.
- 먹색 본문과 한지 배경 사이에 얇은 외곽선을 사용하되, 글자의 획을 뭉개는 두꺼운
  테두리는 쓰지 않는다.
- 버튼은 눌렀을 때 약 `0.97` 배로 줄어드는 100~160ms 반응과 작은 먹물 터치
  피드백을 제공한다. 비활성 버튼에는 터치 연출을 내지 않는다.
- 장식용 빨간 점은 금지한다. 빨강은 신기록·위험·구매 확정 같은 실제 의미가 있을
  때만 낙관이나 상태색으로 제한한다.

### 3.2 로비 버튼의 영구 보정

로비 버튼 PNG의 피사체가 왼쪽으로 치우쳐 있으므로 Transform 중앙값만 맞추면
텍스트가 시각적으로 삐뚤어 보인다. 사용자가 조정한 `최고 102` 표시 칸을 기준으로
아래 보정을 **시작·성장·도감·옵션과 이후 같은 PNG를 쓰는 모든 버튼**에 적용한다.

| 항목 | 기준값 |
|---|---:|
| 버튼 배경 크기 | `610.273 × 130.157` |
| 버튼 배경 X 보정 | `+89` |
| 텍스트 X/Y 보정 | `-87 / -5` |
| 텍스트 영역 | `400 × 80` |
| 텍스트 크기/굵기 | `37px / Bold` |

이 값은 씬 Inspector에서 수동 조정하지 않고 `LobbyMenuLayout` 한 곳에서 관리한다.
`MukJumpSceneBuilder`와 구버전 씬의 런타임 보정이 같은 값을 읽으므로, Play 중이던
이전 Main 백업이 복원돼도 시작·성장·도감·옵션이 즉시 같은 배치를 사용한다.
스프라이트를 교체하면 같은 눈금값을 무조건 유지하는 대신 새 피사체의
시각 중심을 측정하되, 네 버튼에는 항상 동일한 보정을 한 번에 적용한다.

### 3.3 로비 계층과 움직임

버튼은 위에서 아래로 `시작 → 성장 → 도감 → 옵션` 한 열로 배치한다. 기준 앵커 Y는
각각 `0.460 / 0.385 / 0.310 / 0.235`이며, 가장 가능성이 높은 행동인 `시작`을
기존보다 위에 둔다. 버튼마다 크기나 정렬 방법을 달리하지 않는다.

로비 하단에는 먹방울과 시작 먹선을 표시하지 않는다. 실제 첫 점프에 필요한 플레이어와
화면 폭 `-5.35~+5.35`의 영구 시작 먹선은 물리 구조로만 준비하고, `시작`을 누른
순간 함께 표시해 자동 점프 물리로 전환한다. `LobbyWorldSetup`이 이 표시 경계를
소유하며 Unity가 구버전 Play 씬을 복원해도 기존 왕복 이동을 비활성화한다.

### 3.4 입력·모달

- 로비의 Canvas는 보이는 동안 `interactable=true`, `blocksRaycasts=true`를 유지한다.
- 닫힌 모달은 `alpha=0`, `interactable=false`, `blocksRaycasts=false`를 함께 적용한다.
- EventSystem은 Input System UI 모듈과 에디터 입력 복구 가드를 유지한다.
- 버튼의 그래픽은 레이캐스트를 받을 수 있어야 하지만, 장식 이미지와 먹물 이펙트
  오버레이는 입력을 가로채지 않는다.
- 성장·도감·옵션 모달은 한 번에 하나만 열고, 플레이 드로잉 입력으로 전달하지 않는다.

## 4. 영구 성장 화면

화면 첫 시선에서 `보유 먹빛 → 네 성장축 → 구매 비용`이 순서대로 읽혀야 한다.

- 4축을 스크롤이 필요 없는 큰 네 행으로 표시한다.
- 각 행은 큰 아이콘, 이름, 짧은 설명, 6단계 표시, `현재 → 다음` 수치, 비용 버튼으로
  고정한다.
- 구매 가능/불가능은 색만으로 구분하지 않고 비용과 버튼 활성 상태를 함께 보여 준다.
- 최대 단계는 구매 버튼 대신 `완성`으로 표시한다.
- 성공한 레벨업은 아이콘 위치에서 먹이 번지고 금빛이 짧게 드러난 뒤 `성장` 낙관이
  찍히는 연출을 사용한다. 연출은 약 0.55초 안에 끝내고 입력 결과를 가리지 않는다.
- 구매 실패나 재화 부족에는 레벨업 연출을 재생하지 않는다.

## 5. 먹결 도감

도감의 첫 화면은 설명 목록이 아니라 **큰 그림을 고르는 화면**이다.

- 한 페이지에 네 장을 2×2로 배치해 모바일에서도 아이콘을 크게 유지한다.
- 카드 앞면은 큰 아이콘, 이름, 번호, `사용 가능/기획 중` 상태만 보여 준다.
- 카드를 누르면 X축이 접히는 약 0.22~0.26초 뒤집기 동작으로 뒷면을 연다.
- 뒷면에는 이름, 효과 설명, 계열, 단계, 최대 레벨을 표시한다. 다시 누르면 앞면으로
  돌아간다.
- 페이지 이동과 필터는 고정된 카드 네 장의 내용만 교체한다. 100개 GameObject를
  한꺼번에 생성하지 않는다.
- `RuntimeReady`만 현재 판 선택 후보가 될 수 있다. `Planned`는 도감에서 미래
  계보를 설명할 뿐 선택·레벨 변경을 일으키지 않는다.
- 잠금 상태는 그림을 완전히 숨기지 않는다. 형태를 볼 수 있게 하되 상태 문구와
  낮은 명도로 구분한다.

## 6. 옵션과 4장 게임 가이드

옵션은 설정과 도움말을 한곳에서 다시 찾게 하는 로비 전용 화면이다.

### 6.1 게임 가이드

가이드는 언제든 다시 열 수 있고, 시작을 강제 차단하지 않는다.

1. **먹방울은 스스로 뛰어요** — 캐릭터를 직접 움직이는 게임이 아님을 먼저 설명한다.
2. **착지할 곳에 한 획을 그려요** — 다음 착지점을 손가락 선으로 만든다.
3. **선의 기울기가 방향을 정해요** — 발판 각도와 점프 방향의 관계를 보여 준다.
4. **먹을 아끼며 더 높이 올라요** — 제한된 먹과 최고 고도 목표를 마무리로 설명한다.

각 장은 큰 기존 성장 심벌 하나와 한 문장만 사용한다. 이전/다음/닫기 버튼을 크게
두고 현재 페이지 `1/4`를 함께 표시한다.

### 6.2 설정 항목

- BGM: 슬라이더와 켜기/끄기 버튼
- 효과음: 슬라이더와 켜기/끄기 버튼
- 플레이어 UID: 로컬에서 생성한 `MUK-XXXXXXXX` 형식, 탭하면 복사
- Google Play 연동: 실제 인증을 하지 않는 `준비 중` 목업 버튼
- Apple 연동: 실제 인증을 하지 않는 `준비 중` 목업 버튼

목업 연동 버튼은 로그인 성공처럼 보이게 하거나 계정·토큰을 저장하지 않는다.
오디오와 가이드 확인 여부만 로컬 설정에 저장한다.

## 7. 검수 기준

- Game View에서 시작·성장·도감·옵션 네 버튼이 첫 탭에 모두 반응한다.
- 네 버튼의 배경 크기, 텍스트 영역, 글자 크기, 시각 중심이 동일하다.
- 로비 버튼 순서가 `시작 → 성장 → 도감 → 옵션`이며 하단 먹방울·시작 먹선이
  로비 화면에 노출되지 않는다.
- 모든 주요 문구가 세로형 작은 화면에서 자동 축소 없이 읽힌다.
- 성장 구매 전후 수치와 비용이 한 행에서 보이고, 성공 시에만 레벨업 먹물 연출이 나온다.
- 도감 카드 앞면의 그림이 가장 크고, 탭하면 설명 뒷면으로 뒤집힌다.
- 옵션의 네 가이드 장, 두 오디오 설정, UID, 두 목업 연동 버튼을 모두 확인할 수 있다.
- 장식용 빨간 점이 없고, 먹물 터치 오버레이가 버튼 입력을 막지 않는다.
- 닫은 모달이 투명한 상태로 뒤 UI의 레이캐스트를 가로채지 않는다.
