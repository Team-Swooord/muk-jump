# 로비 · 영구 성장 · 옵션 UI 규격

> 최종 갱신: 2026-08-05
> 기준 해상도: 1080×1920, 세로 모바일

## 1. 화면 구조

로비의 주 메뉴는 `시작 → 성장 → 옵션` 세 개만 사용한다.

- `시작`: 현재 로비 선택 상태의 기본값. 즉시 플레이를 시작한다.
- `성장`: 붓 전환 뒤 영구 성장 전체 화면으로 이동한다.
- `옵션`: 로비 위에 옵션 모달을 연다.
- 플레이 중 무작위 증강·성장 카드·도감 화면은 사용하지 않는다.

`LobbyView`는 버튼과 상태 표현만 담당하고 게임 규칙을 계산하지 않는다.
`LobbyScreenNavigator`는 로비와 영구 성장 중 하나만 활성화한다. 화면을 완전히
덮은 붓 전환 콜백에서 목적 화면을 바꾸고, 드러남이 끝난 뒤 입력을 다시 연다.

## 2. 로비 메뉴 정렬

세 메뉴는 하나의 중앙 레일에 세로 배치한다. 기존 전용 붓획 PNG가 왼쪽으로 치우친
시각 중심을 가지므로 배경과 텍스트 보정을 분리한다.

- 메뉴 그룹 앵커 X: `0.50`
- 배경 크기: `610.273 × 130.157`
- 배경 시각 보정 X: `+89`
- 텍스트 시각 보정: `-87 / -5`
- 텍스트 영역: `400 × 80`
- 메뉴 글자: Bold 46px, 100% 먹 농도
- 현재 선택 배경: 100% 먹 농도
- 나머지 배경: 78% 먹 농도

선택 상태는 화면 상태를 따라간다. 로비 기본은 `시작`, 성장 화면 전환 중과 성장
화면에서는 `성장`, 옵션이 열려 있으면 `옵션`을 진하게 표시한다. 버튼 배경이
바뀌어도 글자는 옅어지지 않는다.

로비에서는 하단 먹방울과 시작 먹선을 숨긴다. `시작`을 누른 순간 두 오브젝트를
함께 표시하고 물리를 푼다. UI 포인터를 드로잉 입력으로 전달하지 않는다.

## 3. 공통 글자와 버튼

- 기본 서체: 헬스셋 조릿대 Std
- 제목과 주 행동: Bold
- 보조 설명: Normal. 과도한 합성 Bold와 두꺼운 외곽선을 쓰지 않는다.
- 예외: 영구 성장 노드 상세창은 이름·효과·비용·행동 버튼을 포함한 모든 글자를
  Normal로 통일하고 합성 외곽선을 사용하지 않는다.
- 성장 저장을 읽지 못하면 시작을 막고 성장 화면 위 복구 안내를 연다. 검증된
  backup이 있으면 복원 버튼을, 없으면 2회 확인 초기화 버튼을 제공한다.
- 자동 글자 축소는 금지하고, 충분한 줄바꿈 영역을 먼저 확보한다.
- 행동 버튼 글자는 40px 이상, 일반 버튼 글자는 36px 이상을 기준으로 한다.
- 터치 영역은 보이는 붓획보다 넓게 잡되 이웃 버튼과 겹치지 않는다.

로비의 세 전용 메뉴 PNG는 유지한다. `강화하기`, `닫기`, `계속하기`, `로비로`,
`다음`, `이전` 같은 텍스트 행동 버튼은
`Assets/Resources/MukJump/UI/Common/action_button_brush.png`를 공유한다.
성장 노드, 원형 일시정지 아이콘, 디버그 버튼에는 이 스킨을 강제로 적용하지 않는다.

빨강은 신기록, 위험, 실제 해금 열매처럼 규칙상 의미가 있을 때만 사용한다.
장식용 빨간 점은 만들지 않는다.

## 4. 영구 성장 전체 화면

성장 화면은 로비 팝업이 아니라 불투명 한지 배경을 가진 전용 전체 화면이다.

- 고정 UI: 뒤로, 먹방울 아이콘 + 먹빛 숫자
- 지도: 큰 먹나무 전체를 쓰는 양축 드래그 영역
- 분류: 생존 / 도약 / 먹 운용
- 구조: 분류마다 뿌리 1 + 세 경로×(일반 3 + 비기 1), 전체 39개
- 배경 나무: 약 42% 불투명도
- 실제 가지·먹 받침·분류 표찰: 100% 불투명도

나뭇가지는 자연스럽게 휘지만 부모–자식 선이 끊기면 안 된다. 노드 뒤에는 진한 먹
원형 받침을 두어 밝은 한지와 큰 나무 위에서도 실루엣이 읽혀야 한다. 잠금 봉오리,
해금 빨간 열매, 선택 먹고리, 장착 금빛 고리는 별도 레이어로 합성한다.

지도에는 노드명과 긴 설명을 반복하지 않는다. 노드를 누르면 고정 한지 팝업을 열어
다음 정보만 표시한다.

1. 노드 아이콘과 이름
2. 현재 또는 해금 효과
3. 다음 효과 또는 비기 설명
4. 비용 또는 잠금 조건
5. `강화하기`, `장착`, `해제` 중 하나의 주 행동

팝업 중에는 지도 드래그를 잠근다. 잠긴 노드 선택이 구매로 이어지면 안 된다.
구매 성공 때만 짧은 먹 번짐과 금빛 고리를 재생하고, 나무 전체를 빨갛게 칠하지 않는다.

## 5. 옵션 모달

옵션은 로비 위에 머무는 모달이다.

- 로컬 UID와 복사 버튼
- BGM / SFX 음량 및 음소거
- 언어
- 고객센터
- 계정 연동 목업
- 튜토리얼 4장 가이드

고객센터와 튜토리얼은 같은 열에서 위아래로 배치한다. 좁은 화면에서는 옵션 한지
전체를 균등 축소한다. 계정 연동은 실제 인증 없이 `준비 중` 안내만 제공하며 외부
로그인 토큰이나 자격 증명을 저장하지 않는다.

## 6. 입력·연출 안전 규칙

- 화면 전환 중 전체 화면 blocker 하나만 Raycast를 받는다.
- 장식 붓획과 먹물 피드백은 Raycast를 받지 않는다.
- 비활성 버튼에는 탭 연출을 재생하지 않는다.
- UI 탭은 발판 획으로 전달하지 않는다.
- Safe Area 밖 지도는 보여도 되지만 뒤로·재화·확정 버튼은 Safe Area 안에 둔다.
- 성장 화면 표현 객체는 최초 진입에 한 번 만들고 이후 재사용한다.

## 7. 확인 목록

- 시작·성장·옵션이 같은 중앙 레일에 놓였는가?
- 현재 화면에 맞는 버튼 배경만 진하고 모든 글자는 선명한가?
- 텍스트가 붓획 밖으로 튀어나오거나 자동 축소되지 않는가?
- 성장 지도에 39개 노드와 세 큰 분류가 읽히는가?
- 부모–자식 먹선이 끊기지 않고 터치 영역이 겹치지 않는가?
- 옵션을 닫거나 성장에서 돌아오면 `시작` 상태가 복원되는가?
- 전환 중 연속 탭과 뒤 UI 입력이 차단되는가?
- 최종 플레이 검증은 사용자가 요청한 시점에만 진행한다.

## 8. 모바일 화면·Safe Area 계약

전체 화면 한지 배경, 붓 전환, 비상호작용 먹물 연출은 화면 끝까지 그린다. 반면
로비 기록·메뉴, 옵션, 성장 고정 HUD, 게임 상단 HUD, 맵·날씨 안내, 일시정지,
결과창과 하단 먹 게이지는 `MobileUiLayout`이 산출한 Safe Area 안에 둔다. iOS 노치·다이내믹
아일랜드와 Android 상태/내비게이션·제스처 영역을 같은 규칙으로 처리한다.

- 모든 세로 UI Canvas는 `1080×1920`, 높이 기준 축척을 공유한다.
- 게임 방향은 세로 Portrait로 고정하되 Android 멀티윈도우·태블릿의 세로 비율 변화는
  Safe Area와 fit-scale로 수용한다.
- 고정 패널은 Safe Area의 논리 폭·높이보다 크면 비율을 유지한 채 전체를 축소한다.
- 좌우 인셋이 비대칭이면 상단 HUD와 로비 콘텐츠의 중심도 Safe Area 중심으로 옮긴다.
- 하단 먹 게이지는 IMGUI 좌표의 Y축을 변환한 뒤 홈 인디케이터 위에 배치한다.
- 일시정지 아이콘은 보이는 원형을 `78×78`로 유지하되 실제 탭 영역은 최소
  `120×120`으로 분리한다.
- 화면 크기·Safe Area가 실행 중 바뀌면 옵션·성장·HUD·일시정지·결과창을 다시
  계산한다.
- 회귀 계산은 540×960, Android 1080×2400, iPhone 1179×2556,
  1536×2048 태블릿과 좌우 인셋이 있는 좁은 화면을 포함한다.

근거는 Unity `Screen.safeArea`, Apple Layout의 시스템 안전영역, Android
edge-to-edge/insets 지침이다. Device Simulator는 배치·기본 입력 확인용이며 실제
성능과 제조사별 시스템 UI 확인은 실기기에서 수행한다.
