# 성장 화면 가독성 — 2026-09-04

사용자가 제공한 집중형 성장 화면에서 설명과 하단 효과/구매 문구가 작다는 피드백을 반영한다.
현재 집중 아이콘 + 네 선택 탭 + 한 구매 행동 구조, Nanum Brush Script 및 한지 버튼 원화는 유지한다.
emil-design-eng의 화면 일관성·실제 기기에서의 확인 원칙에 따라 새로운 장식 대신 읽기 크기와 명암을 교정한다.

| Before | After | Why |
| --- | --- | --- |
| 하단 효과 32px, 옅은 한 줄 | 56px, 진한 먹색, 주제/수치 두 줄 | 좁은 휴대폰 폭에서도 효과와 수치를 읽을 수 있게 함 |
| 구매 40px, 높이 128 | 64px, 높이 160 | 한지 안에 큰 글씨와 여백 확보 |
| 화면/선택 설명 42px | 56px, 진한 먹색 | 배경과 겹쳐도 설명이 묻히지 않게 함 |
| 선택 이름 40px | 56px | 아이콘 아래 선택 이름 강조 |
| 보유 먹빛 52px / 아이콘 68 | 68px / 아이콘 84 | 재화 식별성 유지 |
| 로비 40px / 되돌리기 36px | 로비 52px / 초기화 44px | 주 행동보다는 작게, 읽을 수 있는 크기로 유지 |
| 선택 영역 220×240 | 220×336 | 두 줄 효과와 아이콘/이름/밑줄의 비중첩 확보 |

- 기준은 1080×1920 디자인 단위다. 공통 CanvasScaler 또는 다른 화면의 공통 버튼 크기는 변경하지 않는다.
- 360pt 폭 기준 하단 효과 명목 크기 18.7pt, 구매 21.3pt 이상. 실제 글리프 먹획 크기는 서체 특성상 더 작으므로 렌더도 확인한다.
- `체력\n+1칸`, `최대 먹\n+12.5%`, `먹 소모\n-3%`, `점프\n+1.25%`는 기존 카탈로그에서 계산한다. 성장 효과/가격/저장 규칙 변경 없음.
- 비활성 구매 버튼도 행동 문구는 TextDark/alpha 1. 비용은 버튼 위 별도 행이며 부족/복구 때 Red/alpha 1로 표시한다. 비활성 상태는 기존 한지 면/낙관과 interactable로 유지한다.
- 저장 복구 모달 본문은 별도 42px 규격을 유지해 긴 복구 문구가 기존 영역에서 잘리지 않게 한다.
- 검증: TextGenerator 두 줄/전체 글자 생성, 높이/폭 미절단, 터치/자식 영역 비중첩,
  1080×1920·1179×2556·1440×3200에서 실제 축척과 최소 글자 크기. 테스트 렌더는 `output/growth-readability/`.
- UI는 런타임 PermanentGrowthView가 생성한다. 씬 YAML을 수정하지 않는다.

## 가독성을 유지하는 수묵 장식

| Before | After | Why |
| --- | --- | --- |
| 중앙 아이콘이 배경 위에 바로 떠 있음 | 밝은 먹종이 워시와 기존 `pg_selected_ring` 350×350 | 아이콘에 초점을 모으되 제목과 5px 간격 확보 |
| 네 선택지가 흩어져 보임 | 한 장의 밝은 붓띠와 옅은 구분선 세 개 | 개별 카드 테두리 없이 선택 영역을 묶음 |
| 선택 표시는 평평한 선뿐 | 아이콘 뒤 9% 붉은 먹 번짐과 갈필 밑줄 | 선택 하나만 의미 있는 빨강으로 강조 |

- 장식은 `GrowthOrnaments` 뒤쪽 계층 및 탭 아이콘 뒤에서만 그린다. 모두 `raycastTarget=false`.
- 기존 링과 캐시된 붓/먹 번짐 마스크만 재사용한다. 새 이미지·셰이더·매 프레임 장식 애니메이션 없음.
- 56px 설명·효과, 64px 구매, 터치 영역, 재화/성장 규칙 및 로비 배경은 그대로 유지한다.
- 선택을 반복해도 객체를 추가하지 않고 활성 상태만 바꾼다. 테스트에서 선택 번짐 정확히 하나,
  입력 비차단, 장식 레이어 순서, 제목/완료 문구/구매와 장식 경계 간격을 검사한다.
- 이번 장식 변경도 런타임/에디터 Roslyn 컴파일 종료 코드 0, `git diff --check` 통과.
  로그는 `output/growth-readability/compiler/ornament-*-compile.log`다. 읽기 전용 교차검토에서
  추가 P0–P2 문제는 없었다. 새 장식의 Unity 테스트 실행·실제 화면 검증은 아직 하지 않았다.

## 비용 분리와 효과 띠 마감

| Before | After | Why |
| --- | --- | --- |
| 버튼 안 `먹빛 N · 키우기` | 위에 `먹빛 N개 필요`, 버튼은 `키우기` | 비용을 먼저 읽고 행동을 누르도록 분리 |
| 효과 띠 가장자리가 배경에 묻힘 | 18% 먹색 갈필 가장자리 두 줄 | 얇은 마감으로 네 항목을 하나로 묶음 |
| 선택 아이콘만 강조 | 선택 효과 뒤에도 7% 붉은 먹 번짐 | 효과 숫자까지 같은 선택 상태로 연결 |

- 비용행: 중심 `(0,-626)`, `720×100`, 고정 56px. 구매: `(0,-800)`, `720×160`, 64px.
- 초기화: 우상단 `(430,860)`, `200×120`, 44px. 보유 먹빛 `(415,720)`와 20px 세로 간격,
  제목과 70px 가로 간격을 확보한다. 비용→구매 44px, 구매→디자인 하단 80px를 확보한다.
  실제 Safe Area 축척은 기존 규칙 그대로다.
- 비용은 카탈로그의 1/2/3/5를 사용하며 선택·구매·환급 시 즉시 갱신한다. 부족해도 실제 가격을 표시한다.
  완료/선택 없음/복구는 비용행을 상태 안내로 바꾸고 `0개 필요`는 표시하지 않는다.
- 글씨·아이콘·효과 수치·개별 탭의 위치/크기는 유지한다. 장식은 캐시된 붓 마스크를 재사용하고 입력을 받지 않는다.
- 비용 분리 변경의 런타임/에디터 컴파일도 종료 코드 0이며 로그는
  `output/growth-readability/compiler/cost-row-*-compile.log`다. 읽기 전용 교차검토에서
  추가 P0–P2 문제는 없었다. Unity 내 테스트와 새 화면 렌더는 아직 실행하지 않았다.

## 제목 정리와 보조 버튼 통일

| Before | After | Why |
| --- | --- | --- |
| `먹방울 키우기`와 다음 도전 안내 문장 | 제목 `성장`만 | 중복 설명을 없애 화면을 간결하게 유지 |
| 하단의 큰 `성장 되돌리기` | 우상단 작은 한지 `초기화` | 보조 행동을 줄이고 제목/먹빛과 겹치지 않게 배치 |
| 왼쪽 위 로비 텍스트 | 같은 한지의 `220×120` 버튼, 52px | 구매·되돌리기와 재질 및 눌림 피드백 통일 |

- 성장 전용 helper가 세 버튼의 한지·색상·0.97 눌림·고정 글자 크기를 소유한다.
  주 행동 붉은 획은 구매 버튼 하나에만 남긴다. 메인 로비의 전용 버튼 PNG는 변경하지 않는다.
- `초기화`/`한 번 더`는 44px와 같은 영역을 유지한다. 0.35초 연속 탭 방지,
  3초 확인 만료, 환급 및 구매 잠금 규칙은 바꾸지 않는다.
- 회귀 테스트에 제목/안내 제거, 한지 버튼 3개, 우상단 초기화와 제목·재화의 비중첩,
  모든 동적 문구의 TextGenerator 미절단, 확인 후 환급/연속 탭 방지/확인 만료 검사를 포함한다.
- 제목/보조 버튼 변경의 런타임·에디터 Roslyn 컴파일은 모두 종료 코드 0이다
  (최신 우상단 초기화: `output/growth-readability/compiler/reset-top-*-compile.log`). 읽기 전용 교차검토에서
  새 P0–P2 문제는 발견되지 않았다. 추가한 테스트의 Unity 실행과 실제 화면 확인은 아직 하지 않았다.

## 진행 먹방울 확대

| Before | After | Why |
| --- | --- | --- |
| 27×27, 중심 간격 42px | 64×64, 중심 간격 80px | 작은 휴대폰에서도 진행 칸을 식별 |
| 미성장 18% 옅은 점 | 불투명 먹 테두리 + 48×48 밝은 한지 속 | 색 농도뿐 아니라 빈 모양/채움으로 구분 |
| 항상 네 칸 기준 정렬 | 실제 3/4칸 기준 중앙 정렬 | 체력 성장 표시가 왼쪽으로 치우치지 않음 |

- 위치 Y=-150. 설명과 16px, 선택 탭과 15px, 표시끼리 16px 이상의 여백을 둔다.
- 기존 캐시된 먹방울 마스크만 재사용한다. 새 이미지 파일/폰트/숫자/애니메이션을 추가하지 않는다.
- 미소유 내부 한지 네 개만 최초 생성해 재사용하며 모든 진행 그래픽은 입력을 받지 않는다.
  모든 성장을 마치면 마크 전체를 숨기고 완료 문구를 표시하는 기존 동작을 유지한다.
- 테스트 계약: 네 성장의 모든 단계, 구매·환급·선택 왕복 후 채움, 중앙 정렬, 완료 교체,
  입력 비차단, 객체 수 불변, 설명·탭 비중첩, 세 가지 휴대폰 해상도에서 명목 높이 20pt 이상.
- 진행 표시 변경의 런타임·에디터 Roslyn 컴파일은 종료 코드 0이다
  (`output/growth-readability/compiler/progress-*-compile.log`). 읽기 전용 검토에서 새 P0–P2는 없었다.
  추가 테스트의 Unity 실행과 실제 화면 검증은 아직 하지 않았다.

## 현재 검증 상태

- 보유 먹빛 원화만 `pg_inklight_sumukhwa_v1`로 후속 교체했다. 84px와 위치를 유지하며
  진행 칸의 위 규격은 그대로다. [원화·생성 프롬프트·범위](inklight-sumukhwa.md).

- Unity 6000.5.9f1에 포함된 Roslyn과 현재 프로젝트의 응답 파일로 런타임/에디터 어셈블리를 별도 출력 경로에서 컴파일했다. 두 실행 모두 종료 코드 0이며 기존 obsolete API 등의 경고만 있다. 로그는 `output/growth-readability/compiler/`에 있다.
- 변경 파일의 `git diff --check` 통과. 프로젝트 `Logs/Editor.log`와 기본 Unity Editor.log에서 `error CS|Exception` 일치 없음.
- 읽기 전용 교차검토에서 설명/완료 문구/선택 탭/구매/되돌리기 영역의 겹침을 확인하고 간격을 보완했다.
- 열린 Unity는 아직 수정 후 스크립트를 불러오지 않았고 자동 테스트 요청도 소비하지 않았다. 이번 변경의 EditMode 테스트와 화면 렌더는 **미실행**이며 이전 배경 작업의 테스트 통과 수치를 이번 검증으로 간주하지 않는다.
- 뒤늦게 테스트가 실행되어 사용자의 Play를 중단하지 않도록 이번에 만든 대기 요청 파일은 제거했다. 에디터 새로고침 후 `MukJump > Diagnostics > Run All EditMode Tests`로 실행하고, 성장 화면을 다시 열어 확인해야 한다. GUI 원격 조작은 하지 않았다.
- 예정된 PNG는 실제 UI/폰트를 격리된 WorldSpace 프리뷰에 투영하는 검사다. 실제 Overlay/Device Simulator/실기기 캡처를 대체하지 않는다.
