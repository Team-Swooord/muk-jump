# 먹점프 (Ink Jump) — 프로젝트 브리핑

> 이 문서는 외부 AI 도구(ChatGPT 등)에게 프로젝트 컨텍스트를 전달하기 위한 종합 브리핑
> 자료입니다. 게임 기획부터 현재 구현 상태까지 이 문서 하나로 파악할 수 있도록 작성했습니다.

## 1. 한 줄 소개

> "선 하나가 발판이 되고, 발판 하나가 그림이 된다"

NHN NAN 2026 · Game × AI Hackathon 제출작. Unity 기반 모바일(Android) 세로 화면
드로잉 클라이밍 게임. 팀명 Team-Swooord, 2인 팀.

## 2. 게임 개요

| 항목 | 내용 |
|---|---|
| 장르 | 캐주얼 아케이드 클라이밍 (드로잉 플랫포머, 점프킹 계열) |
| 플랫폼 | 모바일 Android APK, 세로 화면 |
| 엔진 | Unity 6 (6000.3.10f1), URP, 2D |
| 타겟 | 전 연령, 캐주얼 퍼즐·아케이드 유저 |
| 플레이 타임 | 1회 1~3분, 반복 도전형 (하이스코어 경쟁) |
| 코어 루프 | 관찰 → 발판 스케치 → 자동 점프 → 상승/추락 복귀 → 생존/재도전 |

## 3. 핵심 메커닉

- 캐릭터(먹방울이)는 **일정 주기마다 자동으로 점프**한다. 플레이어는 점프 자체를
  조작할 수 없다.
- 플레이어는 화면 하단(한지 여백)에 **손가락으로 선을 그어 발판을 생성**한다.
- 발판의 **위치·각도·길이**가 다음 점프의 궤적(방향, 높이)을 결정한다.
- 그린 발판에는 가파른 대각선에서도 붙을 수 있지만 화면 양옆에는 보이지 않는
  반동 경계를 유지한다. 경계 안쪽 0.95m의 획은 확정되지 않고, 상승 중 벽 접촉은
  세로 상승분을 끊어 가장자리 무한벽타기를 막는다. 하강 접촉도 별도 매달림 없이
  화면 안쪽으로 반사한다.
- 발판을 잘못 그리거나 타이밍을 놓치면 캐릭터가 굴러 떨어진다.
- 전략의 핵심은 "내 점프 컨트롤"이 아니라 **"그림으로 만드는 길"**.
- 플레이어가 대충 그린 스케치는 AI로 탐색·제작한 수묵 아트 방향을 반영한 로컬
  갈필 스타일러가 즉시 붓질 질감의 발판으로 완성한다. 현재 제출 빌드는 원격 API를
  호출하지 않으며 네트워크·API 키 없이 동일하게 동작한다.

## 4. 캐릭터 — 먹방울이

번진 먹방울과 한지 붓자국을 모티프로 만든 팀의 독자 수묵 캐릭터.

**비주얼 스펙 (확정)**
- 몸통: 먹 번짐 텍스처의 불규칙한 스파이크형 검은 원 (붓 터치로 그린 잉크 블롯 실루엣)
- 눈: 크고 둥근 흰색 타원 + 검은 원형 동공. **눈썹·입·안광(하이라이트) 없음** —
  표정은 눈 모양과 다리 포즈로만 표현
- 다리: 팔 없이 다리만 존재. 기본(대기) 포즈는 무릎이 몸통 옆으로 뾰족하게 튀어나온
  산(山) 모양 실루엣 — 몸통 아래에서 위로 짧게 붙었다가 몸통 바깥쪽 높은 지점(무릎)
  까지 솟은 뒤, 다시 아래 발까지 길게 떨어지는 꺾인 선. 발끝에는 작은 훅 모양 표시
- 그림자 없음 (땅 그림자는 게임 내 조명/이펙트로 별도 처리)
- 원본 파일: `Assets/Art/Character/Player/character_muk_bangul_v3.png` (1024×1024, 투명 배경)

**애니메이션 상태 (구현 완료)**
- idle · crouch · launch · rise · apex · fall · dive · land의 8프레임
- 사망 시 먹 번짐으로 바뀌고 해당 위치에 한지 먹 자국이 남음

### 먹떼(대량 분신) 기획

- 초반 목표: 공격 장애물이 없는 30m 안에서 12m 첫 먹분신을 반드시 보여 주어 한 캐릭터를
  살리는 게임이 아니라 여러 먹방울을 모으는 게임이라는 정체성을 먼저 학습시킨다.
- 성장 리듬: 아이템 간격은 10~16m, 먹분신 비중은 30m의 35%에서 250m 이후 50%까지
  증가한다. 먹분신은 기본 한 마리를 만들며 먹떼 성장 단계마다 획득 1회 생성 수가
  +1되어 최대 다섯 마리를 함께 만든다. 전체 생존 상한은 24마리다.
- 실패 리듬: 일부 분신이 죽어도 남은 떼로 계속 전진하고 마지막 한 마리에서만
  게임오버가 된다. 점수는 기존처럼 가장 높은 캐릭터의 최고 고도만 사용한다.
- 가시성·공정성: 카메라는 가장 높은 생존 먹방울을 따라 선두를 놓치지 않고, 위험물·
  맵 해금은 하위 중앙값을 따라 소수 선두가 난도를 조기 해제하지 않게 한다. 새 분신은
  획득한 캐릭터의 보이는 외곽 바로 옆에 같은 높이로 배치한다. 화면 가운데에서는
  좌우를 번갈아 쓰고 가장자리에서는 안쪽을 우선한다. 중앙 진행 고도는
  세션 중 내려가지 않아 맵 경계가 점프 하강 때 왕복하지 않고, 낙묵석은 모든 생존
  분신에서 가장 먼 X 후보를 고른다.
- 획득 연출: 새 분신 위치에는 눈·다리 없는 둥근 먹 몸통이 0.12초 동안 맺히고,
  현재 캐릭터 프레임이 0.18초 동안 작게 튀어나와 완성된다. 연출 전용 렌더러는
  분신마다 하나만 고정해 재사용한다.
- 성능 예산: 물리 캐릭터는 최대 24마리다. 자기 충돌은 Player 레이어로 끄고,
  분신 방어막 입자와 동시 사망 음원·진동을 축소·병합한다.

### 영구 성장 먹나무

- 로비의 `성장`은 게임 시작 전에만 여는 영구 성장 전용 화면이다. 정상 게임오버
  결과에서 얻은 단일 재화 `먹빛`으로 노드를 해금하며, 소유 노드와 재화는 게임을
  꺼도 저장한다. 구 장착 필드는 저장 호환용일 뿐 플레이 효과나 UI 장착에 쓰지 않는다.
- 정상 성장 저장은 검증된 백업을 함께 보관한다. 손상·미래 버전 저장을 발견하면
  원본을 보존한 채 플레이 진입을 막고 성장 화면에서 백업 복원 또는 확인 초기화를
  선택하게 한다. 정산 저장 실패도 결과창에 숨기지 않고 표시한다.
- 큰 분류는 `생존 / 도약 / 먹 운용` 세 가지다. 각 분류는 공통 뿌리와 세 개의
  단일 수치 잔가지로 이루어진 13개 stable ID다. 전체는 39개이며 비용은 모두 먹빛 1개다.
- 정상 게임오버의 결과 고도를 계정 누적 거리에 더하고 누적 거리 39단계마다
  먹빛 1개를 지급한다. 단계 간격은 20m×5, 50m×8, 100m×13, 150m×13이며
  마지막 문턱은 3750m다. 분신 높이와 이동 경로는 중복 합산하지 않는다.
- 마지막 열매도 별도 비기가 아니라 같은 수치의 4단계다. 모든 노드는 해금 즉시
  함께 적용하며 교체·장착하지 않는다.
  플레이 시작 시 소유 노드 전체를 불변 스냅샷으로 고정한다.
- 생존은 `체력 +1×4 / 피격 무적 +0.04초×5 / 먹분신 1회 생성 +1×4`, 도약은
  `준비 -1.5%×4 / 힘 +1%×5 / 높이 +1.5625%×4`, 먹 운용은
  `총량 +37.5%×4 / 획 소모 -2%×5 / 회복 +10%×4`다. 총 먹자리는 기본
  3.2m에서 8.0m까지 성장한다.
- 영구 성장 화면은 큰 수묵 먹나무 한 그루 위에 세 큰 가지와 자연스러운 잔가지를
  배치한다. 지도를 드래그해 탐색하고 노드를 누르면 고정 한지 팝업에서 이름·효과·
  잠금 조건·비용을 확인한 뒤 `강화하기`를 누른다.
- 플레이 중 무작위 증강, 성장 두루마리, 증강 카드 선택과 도감은 사용하지 않는다.
  도전 중 변수는 발판 그리기, 아이템 4종, 장애물, 바람과 맵 구간이 담당한다.
- 모든 캐릭터는 기본 내구 1칸이다. 생존의 먹피 경로 네 노드를 열 때마다 +1되어
  최대 5칸이 된다. 성장한 판에서는 피해마다 기존 8프레임 움직임을 유지한 채 몸만
  단계적으로 부풀고, 마지막 칸 소진 시 사망한다. 루트·Collider는 키우지 않으며
  새 분신은 해당 판의 최대 체력을 모두 채운 상태로 시작한다.
- 상세 노드·선행 조건·저장 호환 계약은
  `docs/design/permanent-growth-trait-tree-v3.md`와 `docs/architecture.md`를 따른다.

## 7. 현재 구현 상태 (2026-08-03 기준)

Unity 프로토타입의 코어 루프, 아트 통합, 장애물과 아이템 시스템이 구현됐다.

**완료된 기능**
- 자동 점프: 첫 점프는 접지 중 충전하고, 이후에는 점프 정점부터 다음 충전을 시작한다.
  발판 표면 노멀이 점프 방향을, 발판 길이가 점프력을 결정 (`AutoJump.cs`)
- 드로잉 발판: 터치/마우스 스트로크 캡처 → Chaikin 스무딩 → 리샘플링 → EdgeCollider2D
  발판 생성 (`StrokeCapture.cs`, `BezierSmoother.cs`, `PlatformCollider.cs`)
- 발판은 양방향 실선 충돌과 대각선 접착을 지원한다. 직접 그린 획은 3.4초 동안
  선명하게 남은 뒤 1.1초 동안 처음 그린 쪽부터 자연스럽게 마른다. 기본 총 먹자리
  3.2m는 2.5~3m 실전 획 약 하나를 남기는 기준이며, 총량을 넘겨도 가장 먼저
  그린 획의 시작점부터 같은 방식으로 비주얼과 `EdgeCollider2D`가 같이 줄어든다.
  하단 게이지는 그리는 중인 획과 화면에 보이는 먹선 길이를 합산하고, 화면에 남은
  먹선의 총길이가 실제로 줄어드는 비율만큼 다시 채워진다. 남은 게이지가 비어도
  드로잉은 막지 않으며 새 획으로 오래된 길을 교체한다.
  캐릭터 반경과 겹친 부분은 잘라내고 가장 긴 안전 구간을
  살려 물리 밀어내기 악용과 입력이 통째로 사라지는 불편을 함께 방지한다.
- 발판 비주얼은 Main UI의 `LineSprite` 텍스처를 LineRenderer 붓결로 사용하고,
  해당 오브젝트가 없으면 절차적 갈필 텍스처로 폴백한다.
- 장애물: 게임 고도 30m 전은 안전하다. 이후 12~16m 간격의 좌우 이동 먹가시와
  저고도 7~10초·고고도 5.5~7.5초 간격으로 예고 후 수직 낙하하는
  낙묵석이 등장하며, 60m부터 초등학생이 굵은 먹선으로 그린 듯한 긴 동양 용이
  첫 슬롯에 보장된 뒤 5fps 4프레임으로 통통 움직이는 좌우 이동 변형으로 섞인다.
  320m부터는 좌·우 한쪽의 붓먹 느낌표와
  반투명 붉은 세로 띠가 1.1~1.2초 동안 선택된 벽을 예고한다. 첫 경고 구간 뒤
  붉은 한지색 먹해태 수문장이 화면 위 바깥에서 실체화해 같은 벽을 따라 화면 아래
  바깥까지 직선으로 내려온다. 플레이어 위치를 읽거나 경로를 꺾지 않으며 먹선·시작
  지형·풍맥에도 막히지 않는다. 한 하강은 방어막·무적 여부와 관계없이 살아 있는
  한 캐릭터까지만 처리한다. 용과 해태를 합쳐 한 화면에 한 마리만 등장하고 해태는
  낙묵석 경고·강풍과 겹치면 예약 또는 실제 예고를 미룬다. 프레임별 불투명 몸체 중심 피벗과 실제
  몸통보다 작은 고정 충돌 판정을 사용한다. 낙묵석은 드로잉 발판을 파괴한다.
  장애물과 아이템은 고정 X가 아니라 기기별 카메라 폭을 사용해 좌우로 분산된다.
- 아이템 4종: 먹물방울(먹떼 전체 50m 점프·상승 중 보호), 황금 붓(8초 무한 먹),
  먹 방어막(피해 또는 추락 1회 방지, 보유 중 재획득은 소비하지 않음),
  먹분신(12m 첫 슬롯 보장·35→50% 가중 출현·기본 1마리와 성장 보너스 0~4를
  함께 생성·전체 최대 24마리·마지막 사망 시 게임오버).
  아이콘은 같은 굵기의 검정 외곽선과 제한된 수묵 팔레트로 통일했다.
- 사망: 물리를 정지하고 먹 번짐을 펼친 뒤 해당 위치에 한지 먹 자국을 남긴다.
  성능을 위해 최신 자국 20개까지 유지한다.
- 추락: 화면 하단에 닿은 개체는 방어막을 우선 소모하고, 없으면 체력 1칸을 잃는다.
  체력이 남으면 화면 안쪽 안전선으로 옮긴 뒤 35m 높이로 다시 튀어오르며,
  마지막 체력을 잃은 개체만 사망한다.
- 체력·피격 가시성: 개체 머리 위에 최대 체력 수만큼 분리된 칸을 표시하고, 체력이
  줄 때마다 캐릭터 그림이 단계적으로 커진다. 실제 피해에는 밝은 플래시와 붉은 먹
  번짐·링·충돌음·약한 진동을 함께 사용하되 물리 크기는 유지한다.
- 체력 성장: 기본 1칸에서 `S00 → S-A1 → S-A2 → S-A3`가 각각 +1을 제공해 최대
  5칸이 된다. 네 노드는 먹빛 1개씩이며 다른 생존 경로의 피격 유예와 분리한다.
- 로비: 저장된 최고 고도를 표시하며 게임오버 결과에서 터치하면 로비로 돌아와
  영구 성장을 확인한 뒤 `시작` 버튼으로 다음 도전을 시작한다.
  메뉴는 `시작 → 성장 → 옵션` 순서이며, 세 버튼은 최고 기록 칸에서
  검수한 동일한 배경·텍스트 오프셋과 Bold 46px을 사용한다. 메뉴 축은 화면
  중앙에 두고, 보조 버튼은 배경만 옅게 하며 글자는 모두 선명하게 유지한다.
  로비 하단의 먹방울과
  시작 먹선은 숨기고, `시작`을 누른 순간 첫 점프용 플레이어와 먹선을 표시한다.
  성장은 로비 팝업이 아니라 붓 전환으로 이동하는 전용 전체 화면이다.
  최초 접속은 로비 입력을 기다리지 않고 게임 화면으로 바로 진입하며, 월드를 완전히
  멈춘 5단계 한지 팝업이 먹선·발판·체력·날씨·맵을 충분한 설명으로 소개한다. 마지막
  `시작하기` 뒤에만 자동 점프와 기록 시간이 시작된다. 완료 여부는 설치 프로필에
  한 번 저장해 버전이 바뀌어도 강제로 다시 띄우지 않으며 옵션에서는 언제든 다시 본다.
  옵션에는 다시 볼 수 있는 같은 5장 가이드, BGM/SFX 2열 카드, 로컬 UID와
  언어·고객센터·계정 연동 목업을
  둔다. 도움 메뉴는 2×2이며 고객센터 바로 아래에서 튜토리얼을 연다.
  플레이 중 상단 HUD는 한 장의 한지 붓획 안에 풍향·`고도 4m`·`최고 494m`를
  굵은 한 줄씩 3열로 표시한다. 소형 캡션은 제거하고 10,000m부터 km 단위로 압축한다.
  도전 시작 시점의 최고 고도를 처음 넘는 순간 최고 기록 숫자가 붉게 바뀌고
  작은 `신` 낙관이 찍혀 해당 플레이가 끝날 때까지 유지된다.
- 플레이 중 우측 상단 쉼 버튼으로 한지 일시정지판을 연다. 현재 캐릭터·분신·발판·
  아이템·날씨 상태를 보존한 채 `계속하기` 또는 붓 전환 뒤 `로비로`를 선택한다.
  고도·최고 기록·풍향·알림·결과창의 글자 크기·굵기·먹색 대비도
  작은 화면 기준으로 상향했다.
- UI의 장식용 빨간 점은 사용하지 않는다. 빨강은 신기록·위험·성장 확정과
  영구 성장에서 실제 해금된 먹나무 열매처럼 규칙상 의미가 있을 때만 낙관이나 상태색으로
  제한하고, 버튼 탭에는 입력을 막지 않는
  짧은 먹물 피드백을 사용한다. 상세 영구 규격은
  `docs/design/lobby-ui-overhaul-2026-07-30.md`를 따른다.
- 제출 UI에는 개발용 DEBUG 창을 표시하지 않는다. 아이템·무적·맵 전환·풍향·상승기류·
  풍맥 발판 검증은 사용자 입력과 분리된 자동 테스트 및 내부 API로 수행한다.
- 풍맥 발판은 아래에서 위로 통과할 수 있다. 빠른 풍맥 상승은 위에 착지했을 때만
  발동하고, 일반 대각선 드로잉 발판의 전방향 매달리기는 그대로 유지한다.
- 로컬 수묵 스타일: `SketchToInkService.cs`가 `FallbackInkStyle`의 런타임 갈필
  텍스처를 즉시 적용한다. 미구현 원격 요청 scaffold는 제거했고 API 키 없이 완전히
  플레이한다.
- 게임 루프: 가장 높은 생존 먹방울이 화면 높이 55% 부근에 오면 평소 위로만 따라가고,
  그 개체 사망 시에만 다음 최고 생존자로 한 번 재구도하는 선두 카메라,
  고도 점수 + 최고 기록(PlayerPrefs), 추락 피해 생존 시 복귀,
  마지막 생존자 사망 뒤 터치 재도전.
  같은 높이의 반복 점프는 카메라를 누적 상승시키지 않으며 50m 급상승에는 화면
  상단 90% 이탈 방지선이 적용된다.
- 카메라는 가장 높은 생존 먹방울을 따라가고, 위험물·맵 진행만 하위 중앙값을 사용해
  소수 선두의 먹물방울 부스트가 난도를 조기 해금하지 않게 한다. 새 분신은 화면 안
  획득 캐릭터의 바로 옆에 같은 높이로 배치하며, 분신 방어막 입자와 같은
  프레임 동시 사망 피드백을 축소·병합한다. 드로잉 안전 검사는 캐릭터 중심의 고정
  원 대신 실제 Collider2D 외곽을 사용하고, 먹떼가 커져도 발판 Edge 반경보다 큰
  0.08m 여백을 유지해 선 잘림을 완화하면서 밀어내기 악용을 막는다.
- 점수는 최고 고도만 사용한다. 250m마다 고요한 산길 → 바람 고개 → 먹비 골짜기 →
  낙묵 협곡이 순환하며, 횡풍 세기·총 먹자리·낙묵석 빈도가 달라진다.
- 최고 고도에는 설계상 끝이 없다. 가장 높은 한 마리의 최고 점수 1,000m는 기록 목표,
  먹떼 하위 중앙 진행 고도 1,000m는 기본 산수화 코스 완료와 무한 우주 구간 진입
  목표로 분리한다. 가정된 목표 퍼널 시나리오의 먹떼 진행 고도 1,000m 첫 도달 중앙값은
  18판이다. 70% 아이템 획득·무피격 상한 실험은 1,000m까지 80.83%가 24마리에
  도달했고, 도달자 고도 중앙값은 831.6m다. 실제 플레이 로그가 아닌 입력 확률 기반
  목표 퍼널·상한 시나리오이므로 현재 게임의 예측값으로 사용하지 않는다.
  추가 조정 전 여러 테스터의 반복 수동 기록으로 보정하며 전체 조건과 결과는
  `docs/balance-report-2026-07-27.md`를 기준으로 한다.
- 모든 맵에서 먹선·한지 스타일 상단 풍향 아이콘 방향으로 약한 횡풍이 캐릭터를 민다.
  풍향은 28~45초 동안 유지한 뒤 먹선이 흐르듯 천천히 전환하고, 강풍 예고·상승기류·회복
  중에는 방향 유지 타이머가 흐르지 않는다. 첫 180~260m 뒤,
  이후 220~340m마다 1.35초 예고와 5.5초 상승기류가 발생해 낙하를 멈추고 아주 천천히
  떠오르게 한다. 기존 점프·먹물방울의 빠른 상승과 중력값은 유지한다.
- 안전 먹 발판·휴식·피격 면역은 제거했다. 발판 색은 일반 먹색과 풍맥 청회색으로
  구분하고 풍맥 발판에는 같은 붓결의
  검정 외곽선을 사용한다. 색상용 자식 선에는 콜라이더를 두지 않아 물리는 바뀌지 않는다.
- 배경은 0m 산길, 250m 바람 능선, 500m 먹비 계곡, 750m 검은 절벽 이후 1000m부터
  먹빛 성문·월련 성해·천하수의 밝은 동양 수채화 우주 3종을 무한 순환한다.
  다음 순환은 좌우 반전하며, 구간별 날씨·절벽 먹선은 맵과 독립적으로 적용한다.
- 점프·착지·유효/무효 드로잉·벽 충돌·아이템·사망에 수묵 링·붓획·먹방울 피드백을
  표시한다. 손가락으로 그리는 동안의 붓 마찰음, 화면 전환 붓칠음, 캐릭터 사망음과
  게임 종료음을 포함한 짧은 효과음은 자체 제작 PCM WAV와 출처가 기록된 외부 MP3를
  함께 사용한다.
- 아이템이 화면 위쪽에 들어오면 얇은 먹 링과 통통 튀는 예고를 표시한다. 강한 점프에는
  작은 카메라 줌·흔들림, 유효 피격에는 0.055초 순간 정지, 착지·방어막·사망에는
  강도를 구분한 모바일 진동을 적용한다. 결과 두루마리는 위·아래 말림이 실제로 펼쳐진다.
- 이동 먹가시·어린 용·낙묵석은 상향된 렌더 순서를 유지하고 본체의 명암·알파를 보존한 채
  붉은 한지색으로 치환해 배경과 구분한다. 먹해태도 같은 공용 명암 치환 재질을 쓰되
  원화의 검은 먹선을 남기며, 좌·우 느낌표·반투명 붉은 띠·얇은 갈필 경로로 위험을 구분한다.
  별도 받침·외곽선·과도한 크기 펄스는 사용하지 않는다. 낙묵석은 0.9초 동안 더
  진하게 예고하고 화면 가장자리 안쪽에서 생성한다.
- 아이템·이동 장애물·낙묵석·짧은 피드백·먹물점프 합성 연출은 각 기능이 소유하는
  지연 오브젝트 풀로 재사용한다. 먹물점프 합성 풀은 모든 분신이 게임 전체 3묶음을
  공유한다. 황금 붓 지속 상태는 별도 월드 연출 없이 하단 먹 게이지 채움만 금빛으로
  바꾸고 기존 붓 아이콘은 그대로 유지한다.
  게임오버 UI, 붓 전환, 아이템 효과, 전역 바람선·구간 날씨선도 실제 첫 사용 전에는
  생성하지 않는다.
  DEBUG 고도 이동은 지나간 스폰 예약을 생성 없이 건너뛰어 한 프레임 생성 폭증을 막는다.
- Suno Pro에서 팀이 생성한 국악풍 `Inkdrop Ascent`를 반복 재생하며 로비·플레이·
  게임오버 상태에 맞춰 음량을 부드럽게 바꾼다.
- 입력: Device Simulator/터치/마우스/펜을 모두 지원하는 `PointerInput` 헬퍼
- 씬은 코드로 자동 구성 (`MukJumpSceneBuilder.cs`, 메뉴 `MukJump > Build Main Scene`)
  — 협업 시 씬 파일 머지 충돌 방지
- 아이템·장애물·낙묵석·날씨·풍맥·플레이어 규칙은 세션 seed에서 분리된 난수 스트림을
  사용해 VFX 호출 순서와 무관하게 재현 가능하다.
- 제출 전 자동 검증은 실제 Play 상태 물리 통합 검사를 포함한 Unity 전체 회귀 테스트를
  통과했으며 상세 결과와 잔여 위험은
  `docs/code-audit-2026-07-26.md`에 기록한다.
