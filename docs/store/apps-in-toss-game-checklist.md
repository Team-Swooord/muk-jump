# 먹점프 앱인토스 출시 체크리스트

점검일: 2026-09-22, 대상: `codex/apps-in-toss-web` / 먹점프 `mukjump`

기준: [토스 공식 게임 출시 가이드](https://developers-apps-in-toss.toss.im/checklist/app-game)

아래 60개 행은 공식 항목 순서대로 대응한다. **코드 확인은 휴대폰 토스 앱에서의 합격을 뜻하지 않는다.** 실기기 표시가 남은 항목을 검증하지 않고 콘솔의 완료 체크를 하지 않는다.

## 현재 출시 판정

- 검증 중. 아직 전체 통과 / 심사 제출 가능 상태로 판정하지 않았다.
- 인앱 광고 그룹 두 개를 사용자 동의 후 생성: `먹점프 부활 보상형`(부활 1회), `먹점프 상단 배너`(문구 강조). 콘솔에서 실제 ID 발급·구글 반영 완료를 확인해야 한다.
- 신규 테스트 버전 `20260922-2` 업로드 및 QR 생성 확인. 공식 테스트 광고용이며 운영 광고 ID가 발급되기 전 출시용으로 제출하지 않는다.
- 토스 사용자 식별과 기기 내 저장은 구현되어 있다. 기기 변경 시 성장 데이터 복원용 자체 서버는 미구현이다. 게임센터 순위 제출과 성장 저장은 다른 기능이다.
- IAP, 초대 보상, 웹보드는 제공하지 않는다. 해당 항목은 통과가 아니라 해당 없음이다.

## 이번 수정 및 검증 기록

- 토스 광고 provider를 공통 광고 진행 상태에 연결. 열린 광고의 임의 90초 종료 제거, 웹뷰 정지 시간을 광고 시작 실패 시간에서 제외.
- Android back/home → 종료 확인. 확인 중 중복 종료 요청 차단, 종료 실패 복구, 본인이 걸었던 일시정지만 해제.
- 종료 확인·백그라운드에서 배너 차단.
- 세로 방향 요청, 웹뷰 pull-to-refresh / bounce / 페이지 스와이프 차단. 무시되는 템플릿 직접 수정에 의존하지 않고 추적되는 빌드 코드가 재적용.
- 1차 자동 검사: 501개 중 499 통과, 옵션 화면의 기존 고정 좌표 검사 2개 실패. 이미 적용된 축소 설정판의 위치와 다른 검사였음을 기존 `MainSettingsHasThreeCompactTogglesNoMotionOptionAndReadableLabels` 및 `RefreshSettingsLayout`과 대조하여 수정. 게임 UI를 검사에 맞춰 이동시키지 않았다.
- 최종 자동 검사: **502 통과 / 0 실패 / 0 건너뜀**, 범위 `toss-release-checklist` (계정 식별, 광고, 일시정지, 저장, 안전영역, 옵션, 튜토리얼, 시작 화면, 종료 확인).
- 재컴파일 내부 결과 `failed=false`, `mukjump_audit` 씬 소스 최신·누락 스크립트 0·안전 문제 0 확인.
- 콘솔 기존 업로드 `20260922-1` / SDK 3.0.1 / 메모 `테스트 광고 버전` / 검토 필요. 이 번들은 이번 수정 전 버전이며 출시용으로 간주하지 않는다.
- 신규 업로드: **20260922-2**, 2026-09-22 15:13 KST, SDK 3.0.1, 상태 `검토 필요`. 메모 `체크리스트 수정 검증 / 테스트 광고 / 출시 제출 금지`. 콘솔 테스트 화면의 해당 버전 QR와 배포 ID `01a0c7b4-4d42-7bd0-babf-7c40ffe943c8` 확인. 검토 요청·정식 출시는 실행하지 않았다.
- 산출물: `ait-build/mukjump-test-only-20260922-060118.ait`, 50,829,213 bytes, runtimeVersion `0.84.0`. SHA-256 `070064b8e98da3bdbb859469c3329b184b027004de6ffeb5e7f636bb22ec09d0`.
- 로컬 실제 WebGL에서 종료 확인창 표시, 취소 버튼, 뒤로가기의 확인창 열기/닫기를 확인. 외부 QA 버튼 클릭 시 iframe이 포커스를 잃어 렌더링이 멈추지만 캔버스 포커스 복귀 후 정상 진행됨을 확인했다. 이 결과는 Android 네이티브 뒤로가기 또는 토스 호스트 X 검증을 대신하지 않는다.
- 브라우저 오류 로그 없음. QA 브리지의 Analytics read-only와 미지원 FSR 셰이더 경고가 있으며, 이를 전체 기기 그래픽/통계 검증 통과로 해석하지 않는다.
- 번들 생성 후 웹뷰 설정 재생성 규칙을 SDK가 보존하는 USER_CONFIG 내부로 보완하고 관련 1개 검사를 추가 재실행하여 통과. 업로드 번들의 동일한 4개 웹뷰 옵션은 이미 활성화되어 있었다. 마지막 씬 재생성·감사에서 소스 최신, 누락 스크립트 0, 안전 문제 0, 재컴파일 `failed=false` 재확인.
- 사용자 승인으로 30분 간격 후속 확인 활성화: `먹점프 토스 광고 반영 후 빌드 검증` (`automation-3`). 기존 두 광고 그룹의 실제 ID 발급 후 설정 연결·관련 검사·출시 후보 재빌드를 이어간다. 대기 상태가 동일하면 알림을 반복하지 않으며 실기기 미확인 항목은 완료 처리하지 않는다.

## 실기기 최종 시나리오

1. 최신 QR 빌드를 Android와 iPhone 토스에서 실행. 첫 화면까지 걸린 시간, 노치/닫기 버튼, 회전, 드래그를 확인.
2. 새 사용자 식별 → 한 판 → 게임오버 저장 → 완전 종료 → 재진입. 고도·시간·먹빛·성장·스킨·게임센터 점수 확인.
3. 설정 BGM/SFX/진동 OFF, OS 무음/진동 OFF, 홈 이동·복귀, 잠금·해제를 각각 확인.
4. 옵션/성장/꾸미기/스킬 팝업/게임/일시정지/게임오버에서 뒤로가기 및 호스트 X 확인. 취소하면 원래 화면과 중지 상태가 유지되어야 함.
5. 공식 테스트 광고로 중간 닫힘, 완주, 중복 클릭, 백그라운드, no-fill을 검증. 운영 광고는 출시에 필요한 최소 노출 확인만 하고 임의 클릭/반복 노출로 수익을 발생시키지 않음.
6. 운영 광고 반영 후 새 출시용 번들로 47·54번을 확인하고, 미확인 항목을 완료 처리하지 않은 상태로 제출 가능 여부 재판정.
