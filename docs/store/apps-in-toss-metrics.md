# 앱인토스 운영 지표

이 문서는 먹점프의 분석 이벤트와 콘솔에서 확인할 수 있는 범위를 정한다. Unity 내부 화면은 URL 변경이 없으므로 화면 진입을 별도 이벤트로 보낸다. 분석 전송은 게임 진행·저장·광고 보상을 기다리게 하지 않으며, 실패한 요청을 자동 재전송하지 않는다.

## 이벤트 계약

| 이벤트 | 발생 조건 | 전송 필드 | 해석 |
| --- | --- | --- | --- |
| `mukjump_screen_view` | 로비·플레이·게임오버·성장·꾸미기·설정·튜토리얼·언어·계정·기록·개인정보 화면이 바뀔 때 | `screen_name` 고정 목록 | 화면 진입. 노출만으로 기능 완료를 뜻하지 않음 |
| `mukjump_run_started` | 정상 판을 한 번 시작할 때 | `growth_level` 0–32 | 플레이 시작 |
| `mukjump_first_stroke` | 해당 판의 첫 먹선 | 없음 | 조작 시작. 반복 획은 전송하지 않음 |
| `mukjump_run_completed` | 사망 후 기록과 성장 저장이 모두 끝난 정상 판에서 한 번 | `score` 0–정수 최대값, `new_best` 0/1, `duration_seconds` 0–86400, `stroke_count` 0–1000000 | 정상 정산 완료. 중도 이탈·디버그·복원 기록·부활 대기는 제외 |
| `mukjump_tutorial_completed` | 첫 튜토리얼 완료와 진행 저장 성공 | 없음 | 건너뛰기·저장 실패는 제외 |
| `mukjump_growth_completed` | 성장 업그레이드 성공 | `level` 1–8 | 성장 선택 완료 |
| `mukjump_rewarded_ad_flow` | 보상형 광고 로드·열림·보상 콜백·닫힘·실패 등 단계가 바뀔 때 | `stage` 고정 열거형 | 흐름 진단. 표시 요청이나 열림만으로 실제 보상 지급을 뜻하지 않음 |
| `mukjump_rewarded_ad_outcome` | 받아들인 보상형 표시 요청이 종료될 때 한 번 | `result`: `granted` / `closedwithoutreward` / `failed` / `cancelled` | SDK 결과별 종료. `granted`는 보상 콜백을 받은 요청으로, 닫힘·실패·provider 정리에서 종료될 수도 있음 |

`schema_version`은 1이다. 이벤트 이름·화면·광고 단계·결과는 허용 목록으로 검사한다. 계정 ID, 토스 HASH, 닉네임, 광고 그룹 ID, 원문 오류, 자유 텍스트, 위치, 개별 먹선 좌표는 보내지 않는다. 숫자는 지정 범위 밖이거나 숫자 형식이 아니면 버린다. 디버그 WebGL에서는 운영 분석을 수집하지 않는다.

## 운영 판독

집계표에는 조회 기간·시간대·필터(OS, 앱 버전)·단위(이벤트 건수 또는 중복 제거 사용자 수)를 함께 기록한다. 콘솔 DAU·WAU·MAU는 각 기간의 활성 사용자 정의에 따른 중복 제거 수이며, 아래 이벤트 건수나 이들의 합계가 아니다. 현재 이벤트에는 사용자 식별자를 추가하지 않았으므로 Unity 측에서 고유 사용자 수를 역산하지 않는다.

| 질문 | 계산 기준 | 주의 |
| --- | --- | --- |
| 시작 후 실제 조작 | `first_stroke` / `run_started` | 동일 기간 이벤트 수 비율이며 고유 사용자 전환율과 다름 |
| 정상 판 완료 | `run_completed` / `run_started` | 판별 비율. 부활한 판도 최종 정산 한 번만 셈 |
| 성장 사용 | `growth_completed`와 성장 화면 진입 | 화면 진입 후 여러 번 업그레이드할 수 있어 단순 비율은 사용자 전환율이 아님 |
| 광고 중도 닫힘·실패 | `rewarded_ad_outcome.result`별 건수 | SDK mock 성공을 운영 광고 노출 성공으로 해석하지 않음 |
| 진입 지연·성능 | 실기기 측정 로그와 번들 크기 | 분석 이벤트 시각만으로 초기 10초·입력 2초 합격을 주장하지 않음 |

광고 단계는 **요청 → 준비 완료 → 표시 시도 → 화면 열림 → 유효 노출 → 닫힘·완주 → 보상 반영**으로 나눠 읽는다. 앱 이벤트의 `opened`는 화면 열림, `rewardearned`는 SDK 보상 콜백이다. `granted`는 보상 콜백을 받은 요청의 최종 판정으로, 이후 닫힘 콜백 없이 실패 또는 provider 정리로 끝나도 기존 보상 정책에 따라 기록될 수 있다. 실제 광고망의 유효 노출·과금이나 게임의 부활 반영을 단독으로 증명하지 않는다. 각 단계의 전환율을 계산할 때는 같은 요청 집합·기간의 직전 단계 건수를 분모로 쓰고, 시도 건수와 고유 사용자 수를 섞지 않는다. 배너는 보상형 흐름과 별도로 판독한다.

콘솔에는 `7일 이후 재방문 유저 활성`과 사용자 정의 대표 전환 `먹점프 정상 플레이 완료` → `mukjump_run_completed`가 등록되어 있다. 보조 지표는 튜토리얼·성장 완료다. 등록 상태와 실제 집계 수치를 구분한다. 콘솔에 이벤트가 보이더라도 특정 사용자의 전체 여정, 기기 변경 복원, 광고 수익·eCPM, 정확한 D7 코호트를 증명하지 않는다. 출시 후 실제 수신과 다음 날 집계·리뷰를 확인해 이벤트별 수치와 앱 화면을 함께 대조한다.

2026-09-23 콘솔에는 `mukjump_screen_view` 23건과 시작·첫 먹선·튜토리얼 완료·성장 완료·판 완료 각 1건이 수신된 것으로 표시됐다. 전송 수신은 확인됐지만 같은 사용자의 연속 여정이나 신규 빌드의 모든 기능 성공으로 해석할 수 없다. 대표 전환은 직접 조합한 `먹점프 정상 플레이 완료` → `mukjump_run_completed`로 설정했고, 튜토리얼·성장 완료를 보조 지표로 추가했다. 콘솔 안내에 따라 설정 뒤 실제 집계는 다음 날 확인한다.

같은 날 사용자 정의 매개변수 `screen_name`, `score`, `schema_version`, `new_best`, `level`, `growth_level`의 한국어 정의를 저장하고 각 상세 화면에서 확인했다. 이는 매개변수 등록 증거이며, 각 값의 수신·집계나 새 번들의 `duration_seconds`, `stroke_count`, 광고 `stage`·`result` 수신 증거는 아니다. 기간별 판 완료율은 해당 기간의 정상 완료 **이벤트 건수 ÷ 시작 이벤트 건수**로 계산한다. 기간 경계에서 시작과 완료가 갈라질 수 있고, 재시도·여러 판을 한 사람이 할 수 있으므로 고유 사용자 전환율과 구별한다. 사용자 전환율을 말할 때는 콘솔의 고유 사용자 기준 분자·분모와 집계 기간을 먼저 확인한다. `7일 이후 재방문`은 콘솔 지표 이름 그대로 표기하고 D7 코호트 잔존율로 해석하지 않는다.

광고 성과 탭은 일·주·월 및 OS별 다운로드·노출·eCPM·총 예상수익과 배너/전면형/리워드 추이를 지원한다. 현재 값은 `-` 또는 `아직 데이터 확인 불가`이며 매일 오전 10시 갱신 안내가 표시된다. 광고 분석 탭의 광고 노출 빈도, eCPM, 앱 사용 시간 대비 광고 비중 그래프에는 `지금은 샘플 데이터예요` 안내가 표시되어 있다. 이 값은 먹점프의 실광고 성과가 아니다. [토스 인앱 광고 가이드](https://developers-apps-in-toss.toss.im/guide/monetization/in-app-ad)의 광고 분석 최소 SDK는 2.7.0이며 현재 Unity SDK 3.0.1은 숫자상 충족한다. 샘플 안내의 원인은 실제 광고 노출 부재·배포 반영·집계 지연 등과 구분되지 않았으므로 실기기 impression과 콘솔 수집 시각을 대조해야 한다.

광고 성과의 `총 예상수익`은 확정 지급액이 아니다. 실제 수익·정산액은 콘솔의 확정 또는 지급 명세가 제공될 때 그 기간·통화·정산 기준과 함께 별도로 확인한다. 앱 자체의 `mukjump_rewarded_ad_flow`·`mukjump_rewarded_ad_outcome`는 광고 진행과 보상 판정 진단용이며, 광고 네트워크의 유효 노출 수·eCPM·수익을 대신하지 않는다.

## 비용·실험 판독 경계

| 지표 | 정의와 필요한 자료 | 현재 상태 |
| --- | --- | --- |
| 광고 eCPM | 같은 기간·통화의 광고 수익 ÷ 유효 노출 수 × 1,000 | 콘솔의 실제 노출·수익 집계가 없어 계산 불가. 샘플 그래프는 제외 |
| CPI | 캠페인 비용 ÷ 그 캠페인에 귀속된 신규 설치 수 | 캠페인 비용과 귀속 설치 수가 없어 계산 불가 |
| ROAS | 같은 캠페인에 귀속된 매출 ÷ 비용 × 100% | 비용·귀속 매출·관측 기간이 없어 계산 불가 |
| D7·D30 잔존/ROAS | 설치일별 코호트와 설치 후 7일·30일의 관측 창을 고정 | `7일 이후 재방문` 설정과 동일하지 않으며 현재 코호트 자료 없음 |

자료가 없는 값은 **0이 아니라 미확인**으로 적는다. 화면, 광고 빈도 또는 튜토리얼을 비교할 때는 가설과 바꿀 변수 한 가지, 주 지표, 게임 진행·불만·수익 같은 안전 지표, 대상 집단, 기간과 중단 기준을 먼저 정한다. 작은 표본이나 일시적인 차이만으로 승자를 선언하지 않는다. 실험을 위해 계정 ID·토스 HASH 등 새 식별 정보를 분석 이벤트에 추가하지 않는다.
