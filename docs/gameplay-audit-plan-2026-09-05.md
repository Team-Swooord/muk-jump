# 플레이 버그 검수 및 TestFlight 계획

## 분류 원칙

- 확정 버그: 재현 절차와 기대 결과를 기록하고 실패 테스트 → 최소 수정 → 재실행.
- 의도 확인: 최신 사용자 요청과 충돌하거나 난이도·보상·규칙을 바꾸는 사안은 계획/선택지로 분리. 승인 전 밸런스를 변경하지 않음.
- 자동 검사 통과만으로 실제 터치·광고 SDK·기기 검증까지 완료했다고 간주하지 않음.

## 순서와 완료 조건

1. 현재 전체 회귀 기준선 확보. 2026-09-05 기준 1159개 중 1154개 통과, 5개 실패.
   성장 구매 후 가격·초기화·진행표시 fixture, 성장 로비 버튼 판별, 라이선스 동봉 사본을 분리 조사한다.
2. 입력·발판: 빠른 드래그, 캐릭터 겹침, 짧은 꼬리, 금지 띠, 수명·FIFO·파괴 후 물리, 일시정지 중 입력.
3. 플레이: 자동 점프, 피격·방어막 중복, 50m 상승, 분신 상한/사망/카메라, 아이템·장애물 충돌.
4. 세션: 사망 → 테스트 광고 취소/보상 → 재사망 → 정산/로비/재시작, 성장 구매/초기화, 최고 기록, 앱 복귀.
5. 수정별 회귀 + 반복 Play 시나리오 + 전체 자동 테스트 재실행. 에디터 로그와 실제 결과 저장.
6. `main`에 검증된 작업만 명시적으로 커밋. 기존 타 작업자의 stage·dirty 변경은 섞지 않음. 겹친 파일은 변경 구간을 분리하고 분리 불가능하면 소유자/사용자 확인.
7. Unity QA(Test Ads) export → 먹점프 Bundle ID/Team/빌드 번호/Apple 로그인/SDK/암호화 확인 → Xcode Archive → 배포 검증 → App Store Connect Upload → TestFlight 처리 상태 확인.

## 의도 확인 목록 — 변경 보류

- I-01: 화면 좌우 0.95m 먹선 금지 띠, 최소 0.6m, 3.4초 유지+1.1초 소멸/FIFO는 현재 규칙이다. 체감상 선이 없어지는 경우와 실제 결함을 구분한다. 금지 띠 축소·최소 길이·수명 변경은 별도 승인.
- I-02: 드로잉 도중 일시정지 버튼 영역에 진입하면 현재 미완성 획을 취소한다. 잘라 확정할지/그대로 취소할지는 UX 결정이며 아직 변경하지 않음.
- I-03: 과거 문서의 39노드·4.8m와 최신 4선택지·5.2m 구현이 혼재한다. 과거 문서를 근거로 현재 밸런스를 되돌리지 않음.
- I-04: Computer Use의 빠른 드래그에서 먹선이 확인되지 않은 경우가 있다. 실제 입력 이벤트를 사용하는 회귀 테스트는 통과했으나 네이티브 조작 속도/포커스와 게임 결함을 아직 분리하지 못했다. 실기기 드래그 검증을 생략하지 않음.

## 2026-09-05 검증 결과

- 확정 재현 3건: 화면 전환 중 백그라운드 이동 시 일시정지 누락, 전환 중 전경 복귀 시 재개 누락, 로비에서 숨겨진 뒤 Playing 진입 시 뒤에서 플레이 진행.
- `GameManager`에서 시스템 일시정지를 전환 중에도 반영하고, 전환 종료 후 시스템 소유 정지만 재개한다. 사용자 메뉴/첫 안내 소유권은 보존하며, 숨겨진 동안 도착한 계속하기 콜백과 씬 해제 시 전역 시간 복원도 검사한다.
- 30회 전환/가시성 반복을 포함한 경계·먹선·실제 Physics2D 회귀 **69/69 통과**.
- 기존 실패 5개는 성장 EditMode fixture의 활성화 구독 누락, 공통 버튼 스프라이트 판별, 배포 라이선스 사본 불일치였다. 성장 구매 로직 자체의 런타임 버그로 보고하지 않는다.
- 구름 복귀 테스트는 두 에디터 틱을 두 렌더 프레임으로 오인했다. `Time.frameCount`로 실제 프레임 진행을 확인하도록 수정했으며 배경 런타임은 변경하지 않았다.
- 최종 전체 실행: **1168/1168 PASS, FAIL 0, SKIP 0**, 13:57 KST. EnterPlayMode 기반 실제 물리/입력 검사 포함. 이것이 모든 기기와 모든 플레이 경로의 무결함 보장은 아니다.
- 증거: `output/gameplay-audit/2026-09-05/baseline-1159.xml`, `background-reproduction-3-failures.xml`, `gameplay-boundary-69-pass.xml`, `full-1168-pass.xml`.
- 수동 Unity Play: 로비 시작, 자동 점프, 일시정지 → 계속하기 → 다시 일시정지 → 로비 복귀를 확인. 에디터 광고 화면은 시뮬레이션이며 실제 AdMob 광고 노출/보상 완료 증거로 취급하지 않는다.
- 커밋 대기: `main`에는 기존 작업자의 stage 43개 및 다수의 UI/VFX/광고/저장 변경이 섞여 있다. 기존 변경 포함 범위를 사용자에게 확인 요청했으며, 무관한 stage·작업 기록은 건드리지 않음.
