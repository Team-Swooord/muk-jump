# 먹점프 VFX 적용 기준

이 문서는 `docs/VFX/SKILL.md`의 범용 Unity 2D URP Android 지침을 먹점프의 실제
구조에 맞게 적용한 결과다. 충돌·점프·아이템 수치 같은 게임 규칙과 VFX 품질을
분리하고, 기존의 `SpriteRenderer`·`LineRenderer` 미감에 수묵 마스크 파티클을
더한다. 일반 점프·착지·유효 획·분신 응집은 실제 `ParticleSystem` 3개를 공유한다.

## 1. 호환성 감사

| 항목 | 현재 값 | 적용 판단 |
|---|---|---|
| Unity | 6000.5.9f1 | 현재 프로젝트 버전을 기준으로 컴파일·테스트 |
| URP | 17.5.0, 2D Renderer | 외부 렌더 패키지 추가 없음 |
| Input System | 1.20.0 | VFX에서 입력 API를 직접 사용하지 않음 |
| Color Space | Linear | 유지 |
| Depth / Opaque Texture | Off / Off | 현재 2D 연출에 불필요하므로 유지 |
| Render Scale / SRP Batcher | 1.0 / On | 유지 |
| Android | IL2CPP, ARM64, Swappy On | 유지 |
| Graphics API | Auto | Vulkan·GLES3 실기 비교 전에는 변경하지 않음 |
| 카메라 HDR / MSAA | 생성 씬에서 Off / Off | 후처리 없는 수묵 2D에 맞춰 비활성화 |

현재 효과는 Shader Graph, Visual Effect Graph, UI 파티클 플러그인에 의존하지 않는다.
스킬 문서의 패키지·셰이더 예제는 그대로 복사하지 않았고, 실제 병목이 프로파일러로
확인될 때만 도입을 검토한다. 저장소는 `main` 단일 브랜치를 유지한다.

## 2. 품질 단계

| 단계 | 순간 선 | 순간 방울 | 순간 고리 | 지속 고리 | 날씨 선 | 합성 VFX | 장식 비율 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Low | 4 | 6 | 20 | 24 | 4 | 1 | 42% |
| Medium | 5 | 10 | 26 | 36 | 7 | 2 | 70% |
| High | 6 | 12 | 32 | 48 | 10 | 3 | 100% |

품질 단계가 낮아져도 다음 정보는 유지한다.

- 마지막 캐릭터의 사망 먹 번짐
- 방어막 파괴
- 낙묵석의 착탄 위치와 충돌
- 아이템 획득의 중심 문양
- 벽 충돌 방향
- 최고 기록 낙관

Normal 방울은 최대 10개로 제한해 `Important` 전용 2개를 남긴다.
`Important` 피드백에는 선 7개·방울 12개까지, `Critical`에는 기존 하드 상한인
선 8개·방울 16개까지 예약한다. 예산 부족 시 먼저 줄이는 대상은 보조 방울, 섬유,
잔상, 두 번째 고리와 날씨 선이다.

## 3. 자동 품질과 복원력

- 초기 권고는 기기명이 아니라 시스템 메모리, 그래픽 메모리와 셰이더 레벨로 계산한다.
- 플레이 중 5초 워밍업 뒤 12초 평균 FPS를 측정한다.
- 목표 60fps에서는 47fps 미만, 목표 45fps에서는 35fps 미만, 목표 30fps에서는
  26fps 미만이 지속될 때 한 단계만 낮춘다.
- 강등 후 30초 동안 재강등하지 않는다.
- 로비, 일시정지, 게임오버, 앱 복귀 직후의 프레임은 표본에서 제외한다.
- `Application.lowMemory`를 받으면 즉시 Low로 낮춘다.
- 수동 품질 단계 검증은 사용자 HUD가 아니라 내부 모니터 회귀 테스트에서 수행한다.

## 4. 풀링과 프레임 비용

- `GameFeedbackController`: 선 8개·방울 16개의 하드 상한을 유지하고 현재 품질 예산과
  Critical 예약 슬롯까지 로비에서 프리웜한다. 사망은 핵심 방울 4개를 먼저 확보하고
  나머지 장식 방울만 품질에 따라 생략한다.
- `InkContactParticles`: 점프·착지·유효 획·분신용 먹 튐/갈필 가루/납작한 번짐을 3개 방출기와
  2개 공유 Material로 초기화한다. 별도 활성 입자 예산은 Low 37, Medium 62, High 90.
  점프·착지는 기존 24분신 대표 접촉 병합 뒤 한 번만 방출한다. 유효 획 정착과 분신
  응집도 같은 상한을 공유한다. World simulation, 방출 직후 Pause,
  게임 시간의 수동 Simulate만 사용한다. 움직임 줄이기에서는 추가 입자 0개,
  품질 강등·비활성화·게임오버 때 Clear한다. 게임 난수와 독립된 시각용 seed를 쓴다.
- `InkDropJumpVfxPool`: 최대 3묶음을 공유하고 품질별 동시 사용은 1/2/3이다.
  로비에서 현재 단계 상한인 1/2/3묶음을 모두 프리웜한다.
- `InkDropJumpVfxInstance`: 여러 작은 코루틴 대신 하나의 시뮬레이션 루프로
  모든 잔상·방울·고리를 갱신한다. 출발 먹 튐과 최대 몸높이 3.8배의 후행 붓 꼬리를
  분리하고 2.1초 이내 반납한다. 시각 난수 독립·재생 중 품질 축소·풀 반환 시 모션 초기화.
- `ItemEffectView`: 기존 본체 motes 11/shards 18, 분신 4/6 캐시를 재사용한다.
  획득은 수렴, 보유는 본체 최대5/분신2 알갱이, 소모는 0.7초 월드 파편.
  비활성화·Reduced 전환 때 이동 파편을 정리하며 원화와 부모 배율에 무관하게 크기를 보정한다.
- `DeathInkStainPool`: 사망 먹 자국 최대 20개를 로비에서 비활성 프리웜하고 순환
  재사용한다. 세대 토큰으로 재사용 전 코루틴이 새 자국을 수정하는 경합을 막는다.
- `FallingInkRockSpawner`: 첫 플레이 전에 낙묵석 한 개를 프리웜한다.
- 사운드 피드백용 `AudioSource`는 씬 빌더가 8개를 미리 구성해 첫 재생 순간의
  컴포넌트 추가와 FMOD 출력 전환 경고 가능성을 줄인다.

## 5. 이번 이벤트 연출

| 이벤트 | 핵심 표현 | 예산 저하 시 |
|---|---|---|
| 일반 점프·착지 | 발밑 압축링·방향 붓획 + 탄도 먹 튐·갈필 가루·납작한 번짐 | 화면 밖 후보 제외·프레임 병합·추가 입자 37/62/90 상한·Reduced에서는 링만 |
| 아이템 획득 | 원화 0.18초 흡수, 자체 효과가 없는 종류만 공용 문양 | 보조 방울 축소, 효과·충돌 적용 시점 불변 |
| 먹물방울·풍맥 | 굵은 먹과 가는 분사·잔상·선두를 따르는 짧은 붓 꼬리 | 움직임 줄이기는 잔상·spray 제외, 0.65초 이내 반납 |
| 황금 붓 | 하단 게이지 금색 안료 전환, 시작 0.18초·종료 0.24초 | 원본 알파 보존, 복제 텍스처 없음 |
| 유효 획 완성 | 끝점에서 짧은 갈필 섬유와 작은 방울 정착 | 무효 획에는 방출 안 함, Reduced는 기존 고리만 |
| 먹분신 생성 | 먹 몸통→완성 캐릭터 팝, 초기 이동 속도를 반영한 응집 입자 | Reduced는 본체 즉시 표시, 도중 전환도 본체 복원 |
| 영구 성장 첫 해금 | 대각선 먹획 프레임→잠금 표식→중앙 먹물 파열·해금 아이콘·성장명·먹고리 | 먹획·아이콘·제목·중심 파열 유지, 주변 방울만 4/6/8개로 축소 |
| 영구 성장 반복 강화 | 같은 먹획 프레임을 0.86초로 압축→Lv.N 표식→중앙 먹물 파열·강화명·먹고리 | 첫 해금과 같은 핵심 레이어 유지, 주변 방울만 4/6/8개로 축소 |
| 벽 충돌 | 진행 방향이 읽히는 먹 베기 | 잉크 조각 축소 |
| 방어막 획득·파괴 | 바깥 먹 응집→보유 고리→외곽 파편, 전역은 진동만 | 고리 유지, 움직임 줄이기는 이동 파편 제외 |
| 최고 기록 | 붉은 낙관과 짧은 강조음 | 항상 유지 |
| 낙묵석 예고 | 목표 X의 붉은 낙관을 먹 게이지 위로 배치, 선 두께까지 포함해 여백 확보 | 가이드 선만 생략 |
| 낙묵석 충돌 | 납작한 붉은 고리와 먹 방울 | 중심 충격 유지 |
| 동시 분신 행동 | 45~140ms 창으로 같은 피드백 병합 | 마지막 목숨은 병합 우회 |

## 6. 개발 진단

- 제출 HUD에는 개발용 DEBUG 창을 표시하지 않는다.
- Unity Editor:
  `MukJump > Diagnostics > Audit Mobile VFX`
- 감사 메뉴 보고 항목:
  Unity/URP, Color Space, Android Graphics API 모드, 품질 예산,
  VFX 텍스처 개수·RGBA 추정 메모리·무압축·MipMap 개수,
  빌더 생성 씬의 Line/Sprite/Particle/AudioSource 수, 카메라 HDR/MSAA,
  런타임 모니터 존재 여부

## 7. 실기 QA

2026-09-05 점프·착지 1단계: Unity EditMode 신규 9/9 및 기존 피드백 7/7 통과.
증거는 `output/quality-polish/particle-stage-01/`의 `*-final.xml` 두 개다. 실제 플레이 촬영과
실기기 성능 검증의 상태는 `animation-plans/01-contact-particles.md`를 따른다.

2026-09-05 나머지 사건 VFX: 관련 12개 테스트 클래스 181/181 통과(건너뜀 0).
증거: `output/quality-polish/roadmap-validation/final-regression.xml`.
새 코드의 50m 상승·방어막·유효 획·분신은 각 High/Medium/Low/Reduced로 실제 Game View를 촬영한다.
세부 수치와 단계별 증거는 `animation-plans/02-05-event-vfx.md`, `animation-plans/README.md`를 따른다.

다음은 에디터 테스트로 대체할 수 없다.

1. GLES3와 Vulkan 각각으로 같은 Android 기기에서 15~30분 플레이한다.
2. 24분신 동시 점프·방어막·사망과 먹물방울 연속 획득을 반복한다.
3. 낙묵석 예고가 작은 화면 Safe Area 안에서 충돌 위치를 가리키는지 확인한다.
4. 앱을 일시정지·복귀하고 소리, 풀, 품질 표본이 정상 복원되는지 확인한다.
5. Android Low Memory 상황 뒤 Low 단계로 바뀌고 게임 규칙은 그대로인지 확인한다.
6. Profiler에서 GC Alloc, 활성 Renderer, Material 인스턴스, 발열 뒤 FPS를 기록한다.

현재 ProjectSettings의 URP HDR 지원, Graphics API 자동 선택, 텍스처 압축 정책과
Android API 레벨은 위 실기 결과 없이 변경하지 않는다.

## 8. 자연스러운 먹 운동 보강 (2026-09-05)

- 기존 3개 방출기 안에서 벽·위험의 방향성 먹 튐과 화면 선두의 빠른 이동 잔향을 공유한다.
  공중 잔향은 motes 슬롯 8개를 남기며 접촉이 우선이다. 순간이동·선두 교체·복귀에
  과거 경로를 따라잡아 방출하지 않는다. 콜라이더·원본 캐릭터·점프 힘은 바꾸지 않는다.
- 큰 방울은 항력 2.4로 감속하고 갈필은 뒤늦게 드러난다. 고리는 고정된 먹 결과
  가늘어지는 두께를 사용한다. 사망/피격 공용 방울·방어막 조각·상승 잔방울의
  수명 후반 투명도와 감속을 `InkVfxMotion`으로 통일한다.
- 전체 1181/1181 테스트 통과. 상세 실제 촬영 경로와 실기 미검증 범위:
  `docs/design/vfx-natural-motion-pass.md`.
