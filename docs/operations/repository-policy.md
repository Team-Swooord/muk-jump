# 먹점프 저장소 운영 정책

2026-09-23 중복된 branch-policy.md와 commit-policy.md를 통합했다.

- 기본 정책은 `main` 단일 브랜치다. 새 브랜치·clone·worktree를 만들지 않는다.
- 현재 브랜치가 다르면 원인을 확인한다. 문서 정리를 이유로 자동 전환하지 않는다. 브랜치 전환은 사용자 확인이 필요하며 미커밋 변경이 있으면 전환하지 않는다.
- 한 번에 한 명만 파일을 수정한다. 다른 작성자의 변경·스테이징을 덮어쓰거나 내 커밋에 포함하지 않는다.
- 시작과 커밋 직전에 전체 Git 상태를 확인하고 이번 파일만 명시적으로 stage한다. `git add .`, `git add -A`는 사용하지 않는다.
- 완료·검증한 변경은 기능 단위로 바로 커밋한다. Conventional Commits와 한국어 설명을 사용하며 매번 커밋 승인을 다시 묻지 않는다.
- Push·PR·merge는 사용자 요청 또는 승인 범위에서만 수행한다. 자동 push는 하지 않는다.
- reset·checkout·stash 등 워킹트리를 바꾸는 복구 작업은 먼저 사용자 확인을 받는다. force push는 금지한다.
- 씬은 MukJumpSceneBuilder로만 생성한다. 검증은 변경 영향에 맞춘 컴파일·관련 최소 회귀를 우선한다.
- TestFlight 배포는 승인된 최신 소스·브랜치를 확인하고 기존 생성 출력과 해당 DerivedData만 정확히 식별해 클린 빌드한다. 소스·에셋·Archive·서명자료·검증 로그와 출시 사용자 기록은 보존한다.

## 문서 관리

작업 규칙은 루트 AGENTS.md, 제품 설명은 docs/project-context.md, 상세 기능은 docs/README.md에서 안내하는 원본을 갱신한다.
CLAUDE.md는 진입점만 유지한다. 과거 보고서·스냅샷을 수정해 과거 검증 결과를 바꾸지 않는다.
