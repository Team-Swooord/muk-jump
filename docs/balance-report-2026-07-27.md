# 먹점프 밸런스 시뮬레이션 리포트

> 기준 커밋: `0bd6371`
> 실행일: 2026-07-27
> 범위: 0~1,000m 첫 코스와 1,000m 이후 무한 구간

## 결론

- 현재 게임에는 설계된 **절대 최대 점수는 없다.** 1,000m부터 배경 3종과 250m 구간이
  계속 순환한다. 다만 최고 점수는 가장 높은 한 마리, 맵 진행은 먹떼 하위 중앙
  `SwarmProgressHeight` 기준이므로 둘을 분리해야 한다. `최고 점수 1,000m`는 기록 목표,
  `먹떼 진행 고도 1,000m`는 첫 코스 완주·무한맵 진입 목표다. 2,000~3,000m는
  장시간 QA 범위로 사용한다.
- **실제 도달 판수는 아직 알 수 없다.** Unity 물리만으로 사람의 발판 판단을 대신할 수
  없고 플레이 로그도 없기 때문이다. 가정한 10m 통과율이 반복 시도에 따라 좋아지는
  한 가지 민감도 시나리오에서는 먹떼 진행 고도 1,000m 첫 도달 중앙값이 18판이었다.
  이는 현재 게임을 플레이해 학습한 예측값도, 선두 최고 점수의 예측값도 아니다.
- 먹분신을 놓치지 않는 편인 70% 획득 가정에서는 **24마리 상한 도달 중앙값이
  234.4m**였다. 이는 피격·사망이 한 번도 없고 획득 고도를 아이템 배치 고도로 근사한
  상한 실험이다. 500m에는 99.77%가 상한에 도달해 먹떼의 재미는 빠르게 보이지만,
  생존 보상이 초반에 포화될 가능성이 있다.
- 이번 작업에서는 값을 임의로 바꾸지 않았다. 아래 결과는 여러 테스터의 반복 플레이
  로그를 모으기 전의 밸런스 가설이며, 조정 우선순위를 정하는 기준이다.

## 실행 규모

`tools/run_balance_simulation.mjs`를 다음 기본 설정으로 실행했다.

```bash
node tools/run_balance_simulation.mjs
```

| 검사 | 반복 수 |
|---|---:|
| 콘텐츠 배치·아이템 경제 | 100,000개 세션 시드 |
| 고정 숙련도 민감도 | 숙련도별 100,000판, 총 400,000판 |
| 반복 향상 민감도 | 50,000개 시나리오 × 최대 50판, 총 2,500,000판 |

한 번의 전체 실행은 Apple Silicon 개발 환경에서 약 4초가 걸렸다.

## 방법과 한계

### 코드 상수를 직접 반영한 항목

- `GameplayRandom`과 동일한 기능별 xorshift32 난수 스트림
- 아이템 첫 12m 먹분신 보장, 10~16m 간격, 고도별 35→50% 분신 확률
- 먹분신 획득당 +3/+4/+5, 최대 24마리
- 이동 장애물 30m 해금과 8~12m 간격
- 어린 용 60m 첫 등장 보장과 이후 28% 후보
- 풍맥 발판 82~128m 간격
- 첫 상승기류 180~260m, 이후 220~340m의 고도 간격

어린 용 수는 카메라 아래에서 제거될 때까지 다른 용을 만들지 않는 런타임 규칙 때문에
카메라 가시 폭을 고도 45.2m로 환산한 근사치다. 상승기류도 고도 간격만 적용한
이론치다. 실제 `Weather` 난수는 시간 기반 풍향 전환에도 쓰이고 다음 예약은 발동 순간의
현재 고도에서 잡히므로 플레이 속도에 따라 달라진다.

### 가정이 들어간 항목

Unity 물리만 자동으로 움직이는 봇은 사람의 발판 위치·길이·각도를 대신 판단할 수 없다.
따라서 숙련도 표는 10m마다 “다음 구간까지 먹떼를 유지할 확률”을 **입력으로 둔**
목표 퍼널 민감도 모델이다. 실제 장애물 이벤트나 아이템 경제를 이 계산에 연결하지 않고,
발판 실수와 분신·방패·바람의 순효과가 조건부 확률 안에 이미 포함됐다고 가정한다.

| 가상 숙련도 | 0~30m 조건부 통과율 | 이후 조건부 통과율 |
|---|---:|---:|
| 입문 | 88.0% | 93.2% |
| 보통 | 94.0% | 96.2% |
| 숙련 | 97.5% | 97.8% |
| 전문 | 99.0% | 98.6% |

먹비·낙묵 협곡의 가정 순 페널티와 판별 편차도 적용했다. 이 수치는 실제 사용자 데이터로
학습하거나 현재 코드에서 계산한 값이 아니다. 아래 “몇 판” 결과는 출시 예측치가 아니라
어떤 통과율이어야 목표 퍼널이 나오는지 비교하는 예시 시나리오다.

## 1,000m까지의 콘텐츠 밀도

| 항목 | 판당 평균 |
|---|---:|
| 아이템 | 76.51개 |
| 이동 장애물 | 97.51개 |
| 어린 용 | 12.90마리 |
| 풍맥 발판 | 8.81개 |
| 상승기류(고도 간격만 적용한 이론치) | 3.19회 |

30m 이후 1,000m까지 이동 장애물 슬롯이 평균 약 10m마다 하나씩 있다. 낙묵석은 별도의
시간 기반 스포너이므로 이 표에 합산하지 않았다. 200m 이후 기본 간격은 3.5~5초이고,
750~1,000m 낙묵 협곡에서는 0.62배인 약 2.17~3.10초까지 짧아진다.

아이템 배치 고도로 +3/+4/+5를 판정하므로, 선두가 먼저 60m·150m를 넘는 실제 플레이보다

입력한 구간 통과율이 판마다 좋아지지 않는다고 가정한 한 판 분포다. 게임의 실제
숙련도별 점수 분포가 아니다.

## 사전 밸런스 가설

### 목표 퍼널과 비교할 기준

- 실제 첫 판 먹떼 진행 고도 중앙값이 80~120m이면 초반 진행은 의도 범위로 본다.
- 12m 먹분신 보장 덕분에 첫 장애물 전 게임 정체성인 먹떼를 경험한다.
- 1,000m 이후 2,000~3,000m는 기록 경쟁이 가능하다고 단정하지 않고 장시간 물리·성능
  QA 목표로 사용한다.

### 우선 확인할 위험

1. **30m 이중 난도 절벽**

   이동 장애물과 낙묵석이 모두 30m부터 열린다. 낙묵석은 3초 지연이 있지만, 실제
   초보 로그에서 30~60m 사망이 몰리면 둘 중 하나를 40~45m로 미루는 것이 우선이다.

2. **분신 성장의 조기 포화**

   70% 획득 기준 250m에 이미 평균 21.47마리다. 더 많은 분신을 주는 조정은 1,000m
   접근성을 해결하기보다 초반 생존 변동과 모바일 부하만 늘릴 가능성이 높다.

3. **750~1,000m 낙묵 협곡**

   낙묵석 간격 0.62배와 이동 장애물 최고 속도가 겹친다. 0.72배 발판 수명은
   500~749m 먹비에서만 적용되고 750m부터 기본 5초로 돌아온다. 가정 시나리오에서는
   750m 중앙 12판에서 1,000m 중앙 18판으로 늘었으므로 실제 사망 밀도를 확인한다.

4. **분신으로 막기 어려운 공통 실패**

   개별 장애물 피격은 많은 목숨이 흡수하지만, 발판을 놓쳐 먹떼 전체가 화면 아래로
   떨어지는 실패는 분신 수로 해결되지 않는다. 1,000m 접근성을 높일 때 분신 확률보다
   발판 판정·가독성·협곡 패턴의 일관성을 먼저 봐야 한다.

## 다음 실제 테스트 기준

현재 값은 바로 수정하지 않는다. 한 개발자의 15~30판만으로 사용자 중앙값을 검증할 수
없으므로, 가능하면 최소 3~5명이 각 15~30판을 실제 플레이해 다음 값을 기록한다.

- 판 번호, 선두 최고 점수와 먹떼 하위 중앙 진행 고도
- 한 판 플레이 시간
- 사망 고도와 원인: 발판 미생성 / 화면 아래 / 이동 가시 / 어린 용 / 낙묵석
- 세션 seed, Development Build·DEBUG 사용 여부
- 사망 직전 생존 분신 수와 판 중 최대 생존 수
- 획득·놓친 아이템 수
- 30m, 250m, 500m, 750m 첫 도달 판수
- 24마리 시점 FPS·GC Alloc·활성 오브젝트 수

제출용 목표는 다음 범위를 권장한다.

| 지표 | 권장 범위 | 현재 사전 모델 |
|---|---:|---:|
| 첫 판 먹떼 진행 고도 P50 | 80~120m | 100m |
| 진행 250m 첫 도달 P50 | 2~4판 | 3판 |
| 진행 500m 첫 도달 P50 | 5~8판 | 7판 |
| 진행 750m 첫 도달 P50 | 9~13판 | 12판 |
| 진행 1,000m 첫 도달 P50 | 15~20판 | 18판 |

18판은 위 목표 범위와 비교하기 위한 민감도 기준일 뿐 현재 게임이 범위 안이라는
증거가 아니다. 실제 다인 로그에서 먹떼 진행 고도 1,000m 중앙값이 20판을 넘고
사망이 750~1,000m에 집중될 때만 낙묵 협곡을 우선 완화한다. 10판 미만이어도 숙련
테스터 편향인지 먼저 확인하고, 분신 상한·지원 아이템 획득과 생존의 인과가 로그에서
확인될 때만 해당 밀도를 조정한다.
