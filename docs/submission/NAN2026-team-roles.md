# 최연소밴드

> 화면을 맡은 사람과 규칙을 맡은 사람이 함께 만든 2인 팀.

## 팀 정보

- 팀원: 김승연, 최성빈
- 프로젝트: 먹점프 (MukJump)
- 개발: 2026.07.20–2026.08.07
- 저장소: https://github.com/Team-Swooord/muk-jump

최연소밴드는 UI·아트를 맡은 김승연과 게임·기획을 맡은 최성빈으로 구성됐다. 한 사람은
게임이 어떻게 보이고 눌리는지를, 다른 한 사람은 한 획이 어떤 결과를 만드는지를
책임졌다. 영역을 나눴지만 결과물은 따로 완성하지 않았다. UI와 게임 규칙이 만나는
지점을 매일 함께 플레이하며 고쳤다.

## 김승연 — UI·아트

김승연은 로비, 튜토리얼, 옵션, 일시정지, 결과 두루마리, 영구 성장 먹나무를 하나의
수묵 언어로 묶었다. 한지와 먹 번짐을 장식으로만 쓰지 않고 정보의 순서가 보이도록
농도와 여백을 조절했다.

### 맡은 일

- 로비부터 게임오버까지 화면 흐름과 버튼 배치.
- iPhone Safe Area, 글자 가독성, 모바일 터치 영역 검수.
- 먹방울 캐릭터와 아이템·장애물·배경의 아트 방향.
- 이미지 생성 프롬프트 작성, 결과 비교, 채택·폐기.
- 크로마 제거, 투명화, 크기·기준점 정규화.
- 실기기 화면 캡처, 제출 문서와 시연 동선 구성.

실기기에서 튜토리얼 문장이 카드 밖으로 나오거나 게임의 붓이 작아진 장면을 직접
확인했다. 텍스트를 줄이고 Safe Area를 다시 잡았으며, 버튼은 보이는 붓획과 실제
터치 영역을 분리해 작은 화면에서도 놓치지 않게 했다.

## 최성빈 — 게임·기획

최성빈은 자동 점프, 드로잉 발판, 먹 총량과 오래된 획 소멸, 분신 생존, 체력과 카메라의
규칙을 정리했다. 기능이 늘어날수록 한 획을 긋는 재미가 흐려지는지 확인하고, 필요하면
이미 구현한 기능도 제거했다.

### 맡은 일

- 자동 점프와 발판 길이·기울기에 따른 물리 규칙.
- 먹 게이지, 분신, 체력, 추락 복귀, 카메라 설계.
- 아이템 4종, 용·해태·낙묵석, 바람과 맵 구간.
- 영구 성장 39노드와 누적 거리 보상 밸런스.
- Unity 상태 흐름, 오브젝트 풀링, 저장 복구 구조 검토.
- 회귀 테스트, 오류 경계, 실행 방법의 기술 검수.

플레이 중 증강 카드와 도감도 한때 구현했지만, 핵심 조작보다 메뉴가 앞선다고 판단해
걷어냈다. 대신 판 밖의 영구 성장 세 계보만 남기고 각 계보에서 한 줄기를 고르는
방식으로 정리했다.

## 둘이 함께 고친 한 장면

첫 실기기 테스트에서 튜토리얼은 읽기 어려웠고, 안내 뒤에서도 월드가 움직였다.
김승연은 다섯 장의 정보량과 정렬을 다시 잡았다. 최성빈은 팝업이 열려 있는 동안
물리·스폰·날씨·기록 시간과 드로잉 입력이 모두 멈추도록 상태를 고쳤다. 두 사람이
같은 iPhone 화면을 다시 보며 버튼 위치와 마지막 시작 시점을 확인했다.

이런 경계 작업은 한 사람의 영역으로 끝나지 않았다. 먹 용량이 바뀌면 게이지의 뜻과
성장 문구를 함께 고쳤고, 분신 체력이 바뀌면 캐릭터 위 체력 칸과 카메라 기준을 함께
확인했다. 화면에서 이해되지 않는 규칙은 설명을 바꾸고, 설명하기 어려운 규칙은 다시
단순하게 만들었다.

## 19일의 흐름

- **7월 20일** — 자동 점프와 그린 선이 물리 발판이 되는 첫 프로토타입.
- **7월 24일** — 아이템 4종, 먹분신, 사망 먹 자국과 소리 통합.
- **7월 30일** — 로비·튜토리얼·결과창·먹나무를 모바일 화면에 맞게 재구성.
- **8월 3일** — 여러 작업선을 `main` 하나로 정리하고 재현 가능한 씬 빌더 규칙 확정.
- **8월 7일** — iPhone 실기기 문제 수정, 결실 패시브 검수, 제출 문서와 영상 준비.

## 협업 기준

| 영역 | 주 책임 | 상호 검수 |
|---|---|---|
| UI·아트·실기기 화면 | 김승연 | 최성빈 |
| 게임·기획·밸런스 | 최성빈 | 김승연 |
| 통합·우선순위·제출 | 공동 | 공동 |

AI는 구현 후보와 검수 목록을 빠르게 만드는 도구로 썼다. 김승연은 시각 결과와 모바일
경험을, 최성빈은 규칙과 물리·저장을 먼저 검토했고, 최종 채택은 두 사람이 함께
결정했다. 저장소 커밋은 대표 계정에 집중돼 있으므로 커밋 수를 개인 기여도의 지표로
사용하지 않았다.

둘은 결과물을 나눠 만든 뒤 마지막에 합친 것이 아니다. 한 획이 보이는 방식과 한 획이
작동하는 방식을 계속 맞춰 가며 먹점프를 완성했다.
