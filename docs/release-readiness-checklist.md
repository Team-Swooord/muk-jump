# 먹점프 출시 직전 질문표

이 문서는 작업 기록이 아니라 App Store·Google Play·Apps in Toss 제출 직전에 반복해서
사용하는 현재형 체크리스트다.

- `[x]` 코드·자동 검사로 확인
- `[~]` 구현됐지만 새 빌드 또는 실기기 확인 필요
- `[ ]` 미완료 또는 외부 콘솔 작업 필요

## 먹점프 1.0 확정 답변

던던던의 실제 출시 구조와 SHIFT의 최신 출시 준비 구조를 참고하되, 두 프로젝트에서
확인된 민감 토큰 로그·불완전한 계정 캐시 초기화·클라이언트 권한 랭킹 문제는 복사하지
않는다. 번들 ID, 뒤끝 앱 ID, OAuth 클라이언트, 광고 단위, 서명 파일도 먹점프 전용으로
분리한다.

| 질문 | 먹점프 1.0 답변 |
|---|---|
| 첫 실행 | 뒤끝 토큰 자동 로그인을 먼저 시도하고, 토큰이 없거나 네트워크가 실패하면 게스트로 즉시 플레이한다. 로그인 화면 때문에 첫 플레이를 막지 않는다. |
| 로그인 종류 | iOS는 게스트·Google·Apple, Android는 게스트·Google을 지원한다. Android 1.0은 Apple 승인 철회까지 안전하게 끝내는 탈퇴 경로가 없어 Apple 계정 생성을 노출하지 않는다. 설정의 `계정`에서 현재 상태와 연동·로그아웃·탈퇴를 관리한다. |
| 게스트 승격 | 연결된 뒤끝 게스트는 `ChangeCustomToFederation`으로 기록과 성장을 그대로 유지한다. 서버 게스트 연결 전의 오프라인 로컬 기록도 먼저 복구본으로 저장하고, 처음 쓰는 소셜 계정이면 그대로 첫 서버 저장으로 올린다. |
| 기존 소셜·다른 기기 충돌 | 재화·성장을 자동 병합하지 않는다. 기존 소셜 계정은 현재 로컬 기록을 기기에 보관하고 서버 기록으로 전환한다. 같은 계정의 서버 세대가 달라졌으면 저장을 멈추고 `서버 기록` 또는 `이 기기 기록`을 사용자가 직접 선택한다. 최고 고도만 큰 값을 안전하게 유지할 수 있다. |
| 닉네임 | 1.0에서는 공개 닉네임을 수집하지 않는다. 리더보드는 순위와 최고 고도만 표시해 중복·금칙어·신고 기능을 만들지 않는다. |
| 서버 저장 | 사용자 스키마 버전, 최고 고도, 먹빛, 보유 성장, 활성 결실, BGM/SFX, 튜토리얼 완료 버전을 저장한다. 인증 토큰은 PlayerPrefs나 로그에 저장하지 않는다. |
| 오프라인 | 마지막 정상 스냅샷으로 코어 게임을 계속한다. 변경된 전체 상태는 저장 성공 전까지 보류한다. 저장 직전에 서버 행·세대를 다시 읽고 예상 세대와 다르면 덮어쓰지 않고 충돌 선택 화면을 표시한다. |
| 리더보드 | 보상이 없는 전체 최고 고도 1종만 운영한다. 완료된 정상 판만 제출하고 의심 기록은 뒤끝 콘솔에서 운영자가 제거한다. 서버 권위 검증이 필요한 대회·현금성 보상과 주간 리그·친구·채팅은 1.0에서 제외한다. |
| 계정 삭제 | 설정에서 2단계 확인 후 뒤끝 탈퇴를 실행한다. 성공 후 세션·로컬 사용자 데이터·보류 작업을 지우며 Apple 계정이면 승인 철회 처리도 함께 검증한다. |
| 광고 | 로비 상단 적응형 배너와 판당 1회 게임오버 부활 보상형만 사용한다. 앱 시작 광고·플레이 중 전면 광고·첫 판 방어막 광고는 1.0에서 사용하지 않는다. |
| 결제 | 인앱결제와 유료 재화는 1.0 범위에서 제외한다. |
| 알림 | 1.0에서는 푸시·로컬 알림을 넣지 않고 iOS Push Notifications capability도 켜지 않는다. 재방문 알림은 실제 기능과 수신 설정을 함께 만들 때 추가한다. |
| 개인정보·문의 | 공개 HTTPS 개인정보처리방침과 계정 삭제 안내 페이지를 만들고, 고객 문의는 `cysbandcs@gmail.com`으로 통일한다. |
| 플랫폼 분리 | iOS·Android 스토어 빌드는 뒤끝과 Google Mobile Ads를 사용하고, Apps in Toss WebGL은 토스 앱 세션·게임센터·광고 API를 별도 어댑터로 사용한다. 뒤끝 네이티브 DLL과 Toolkit은 WebGL에서 제외한다. |
| 연령·아동 | 전체이용가 캐주얼 게임으로 제출하고 광고 콘텐츠 등급은 G로 제한한다. 아동만을 대상으로 지정하지 않으며 스토어의 대상 연령·데이터 응답도 이 기준과 일치시킨다. |
| 접근성 | 햅틱은 끌 수 있고 `움직임 줄이기`를 켜면 강한 점프의 카메라 흔들림과 줌을 제거한다. 두 선택은 기기별로 저장한다. |
| 분석 | 1.0에는 계정 연동 자체 분석 SDK를 넣지 않는다. 광고는 AdMob 집계 보고서만, 밸런스는 버전별 익명 수동 플레이테스트만 사용한다. |

이 표의 항목은 제품 결정이다. 아래 체크박스는 실제 코드·콘솔·빌드·실기기 검증이
끝날 때만 완료로 바꾼다.

## 현재 출시 차단 요약

1. `cysbandcs@gmail.com`의 던던던과 같은 AdMob 게시자 계정을 사용하되, 먹점프 전용
   iOS·Android 앱 ID와 배너·보상형 광고 단위는 이미 분리했다. 공개 개인정보처리방침
   URL 준비 후 UMP 개인정보 메시지 게시와 출시 후 스토어 목록 연결이 남아 있다.
2. 게스트·Apple·Google 로그인, 안전한 동기화, 2단계 탈퇴, TOP 10 코드와 UI는 구현됐다.
   먹점프 전용 뒤끝 앱 ID·서명키, 비공개 플레이어 테이블, 초기화·보상 없는 최고 고도
   리더보드, Android/iOS 식별자와 Apple Team ID까지 연결했다. 같은 개발자 계정의
   던던던 설정 구조는 참고하되, 번들 ID가 다른 먹점프 전용 Google OAuth Client를
   만들어야 한다. 운영 AdMob 게시자 계정은 사용자가 확인한 `cysbandcs@gmail.com`이고,
   OAuth는 현재 다른 창에 로그인된 Google 계정에서 확인한다. 먹점프 전용 Cloud 프로젝트
   생성 또는 던던던 프로젝트가 보이는 계정 확인, Apple 토큰 철회용 Key 이름·p8, Apple
   계정 변경 웹훅, Android 서명 해시 입력과 실기기 검증이 남았다.
3. 개인정보처리방침·삭제 안내·스토어 데이터 답변 원문은 작성됐다. 고객지원 저장소는
   공개됐지만 두 법적 문서 URL은 현재 404다. 저장소 반영 또는 별도 HTTPS 배포와
   App Store Connect·Play Console 최종 입력이 남았다.
4. 2026-08-27 13:45 iOS Unity 검증본과 `Unity-iPhone.xcworkspace`의 서명 없는 Release
   컴파일은 성공했다. 생성된 앱에도 번들 ID `com.CYSB.MukJump`, 버전 `1.0.0`(1),
   `ITSAppUsesNonExemptEncryption=NO`, ATT 설명 키 부재가 유지된다.
   이 산출물은 최신 계정 안전성 변경 전 검증본이므로 제출하지 않는다. 최신 Unity 재생성,
   Xcode Archive·TestFlight·실기기 검증과 Android AAB가 남아 있다.
5. Apps in Toss는 공식 게임센터 연동, WebGL 전용 플랫폼 분리, 32.21MB 사전 용량 검증까지
   완료했다. 공개 HTTPS 아이콘 URL과 토스 배너·보상형 광고 그룹 ID를 입력한 뒤 최종 `.ait`
   생성, 콘솔 업로드, QR 실기기 검증이 남았다.
6. Android Build Support는 아직 없다. 실행 중인 `6000.5.9f1-arm64` 복사본과 Hub에 등록된
   `6000.5.9f1` 경로가 달라 자동 설치를 중단했다. 프로젝트를 저장·종료한 뒤 Hub 등록
   경로로 다시 열고 Android Build Support·SDK/NDK·OpenJDK를 함께 설치해야 한다.
   재배포 제한 폰트·MP3·버튼 파생물은 OFL 폰트·자체 WAV·자체 마스크로 교체했다.
